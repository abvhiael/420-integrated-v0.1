# GEN-11.16 — 420Status and Bundler observability

The Bundler publishes read-only operational telemetry on `GET /status` alongside the existing `GET /healthz` and `GET /readyz` endpoints. It uses the existing 420Status component contract (`status/components`) with `ClassRPC`, service ID `420/service/bundler/v1`, and `Authoritative: false`. A component is healthy only when the runtime is ready; otherwise it is degraded. Status has no authority to authorize, deny, reorder, include, settle, or finalize a UserOperation. An operator may register the Bundler URL as a monitored RPC component and probe its HTTP readiness and JSON status payload.

The `/status` response carries service and service ID, canonical/authoritative booleans (both false), observation timestamp, runtime readiness, configured chain ID and EntryPoint, current bounded mempool occupancy, and process-local aggregate counters. Counters distinguish new admission, idempotent duplicate, replacement, admission failure, submission success, revalidation rejection, and submission failure. They do not expose signatures, signed UserOperations, per-sender metrics, private keys, operator credentials, or untrusted dependency error text. Responses are GET-only, JSON, and `Cache-Control: no-store`.

Process-local counters reset on restart; persisted mempool occupancy is reconstructed by GEN-11.14 and does not imply a lifetime operation total. `/readyz` and `/status` are operational snapshots, not chain inclusion/finality evidence. A 420Status outage or failed metrics read must not be consulted by the validator, mempool, EntryPoint submitter, Paymaster, or Wallet as an authorization decision. Receipt reconciliation continues to require canonical chain evidence.

The public and peer admission paths share an observational mempool wrapper; the bundle loop records outcome counts. Metrics collection uses atomics and does not change the result of underlying admission/submission. The `status/components.Snapshot` conversion enforces the existing nonauthority contract and requires explicit network/environment labels from the 420Status operator. Operators should monitor staleness and reachability independently; GEN-11.16 does not add an unverified global health claim.

Qualification must pass the exact branch head containing the production wiring, component conversion, telemetry endpoint, and tests proving nonauthority, counter accounting, GET-only semantics, and omission of sensitive fields.
