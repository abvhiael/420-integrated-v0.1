## Explicit trust states and invariants

`DISPLAY_SNAPSHOT` (possibly fixtures) != `REVIEW_CANDIDATE_ONLY` (bounded request/response, but source unauthenticated) != future `TRUSTED_EXECUTION_QUOTE` (approved/verifiable producer and exact quote integrity) != future `REVIEWED_TRANSACTION` (same canonical/user-visible transaction, fresh wallet/session/preflight) != future `SUBMITTED_TRANSACTION` (wallet returned hash) != separately finalized, settled and reconciled chain/beneficiary state. Never derive trusted status from HTTPS, JSON schema, `verified` tokens, `sourceAuthenticated:true`, `marketSource:'api'`, a fixture, a configured URL or a passing unit test.

Pin normalized chain ID/account/provider generation, independently verified manifest/router/token identity and decimal metadata, market/route/path commitment, positive integer raw amounts, net minimum/fees, recipient/spender, calldata/value/fingerprint, quote timestamps and replay identifiers. Stale/edit/account/chain/provider/runtime/navigation changes invalidate all prior candidates. Distinguish API error, source trust, preflight, wallet rejection and chain-versus-indexer disagreement. The V14 `swap-submit`, `order-sign`, `bridge-submit` and cancellation prompts stay disabled; V15 quote fetch is read-only.

**PRE-01 DONE:** source-tree inventory, scoped API/indexer HTTP implementation inspection, real route/envelope comparison, trust model and implementation handoffs are recorded. **Still open by design:** PRE-02 browser identity; PRE-03 read-only review; PRE-04 quote producer; PRE-05 provenance; PRE-06 execution architecture; PRE-07/08 order and cancellation; PRE-09 bridge proof/beneficiary; PRE-10 Exchange read adapter and indexer operator bootstrap; PRE-11 automated schema/security/CI qualification; PRE-12 review and handoff.
