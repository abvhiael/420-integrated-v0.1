## Five distinct trust states (do not collapse)

1. `DISPLAY_SNAPSHOT`: source-labeled, possibly fixture-backed catalog and historical information; never executable authorization.
2. `REVIEW_CANDIDATE_ONLY`: bounded request/response, wallet/session, freshness and canonical-display checks from the V15 intake; **untrusted provenance** even if response claims `marketSource:'api'`, `demo:false` or `tokens.*.verified:true`.
3. `TRUSTED_EXECUTION_QUOTE` (future): authenticated, operator-approved producer identity and tamper-evident quote binding to chain, manifest, token provenance, route/market IDs, amounts, fee, spender/recipient, expiry and replay policy; requires a separately verified service implementation and trust anchors. Does **not** prove chain state by itself.
4. `REVIEWED_TRANSACTION` (future app integration): a *current*, exact canonical transaction projected into the UI and explicitly acknowledged by the same selected wallet/session. Must invalidate when user inputs, quote, runtime, account, chain, provider or route change; a caller-provided `sourceAuthenticated:true` is not evidence.
5. `SUBMITTED_TRANSACTION` (future live gate): wallet/provider accepts a transaction and returns a hash. This is neither mined/finalized success nor destination payout. Receipts, reorgs and indexer/beneficiary reconciliation have separate authoritative states.

## Cross-layer invariants to standardize before PRE-02 through PRE-05

- **Identity:** normalize EVM chain ID and account; pin router, market, route IDs, token contract, network/deployment manifest and code provenance. Never infer asset identity or decimals from a symbol or V14 visual catalog.
- **Amounts:** use positive integer raw-unit strings internally, authenticated integer-decimal metadata to project them, and separately displayed net minimum/fees; ban JS float conversion for executable amounts. Pin quote ID, exact hops, path commitment, recipient, spender, calldata/value and transaction fingerprint.
- **Time and sequencing:** quote observed/expiry time, receipt-time validation, display-time validation, per-request epoch, wallet generation, order nonce and bridge replay identifiers; late responses, duplicate events or resurrected views cannot regain authority.
- **Errors:** distinguish endpoint absent, source unauthenticated, unsupported route, stale quote, changed wallet, invalid contract/config, insufficient allowance, provider rejection, simulation revert, submission pending and chain/indexer divergence. UI must never label a server response or a wallet hash as settlement.
- **Disabled defaults:** V14 `swap-submit`, `order-sign`, `bridge-submit` and cancellation wallet prompts remain disabled; V15 read-only `v15-quote-review-fetch` is not an execution button. Do not introduce an enabled-by-runtime-JSON or enabled-by-tests trading toggle.
