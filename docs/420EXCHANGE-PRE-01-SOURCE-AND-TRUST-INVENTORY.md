## Explicit trust states and invariants

`DISPLAY_SNAPSHOT` (possibly fixtures) != `REVIEW_CANDIDATE_ONLY` (bounded request/response, unauthenticated producer) != future `TRUSTED_EXECUTION_QUOTE` (verifiable approved producer and exact quote integrity) != future `REVIEWED_TRANSACTION` (same canonical/user-visible transaction, fresh wallet/session/preflight) != future `SUBMITTED_TRANSACTION` (wallet returned hash) != separately finalized, settled and reconciled chain/beneficiary state. HTTPS, schema, token `verified` flags, caller-supplied `sourceAuthenticated:true`, `marketSource:'api'`, fixtures, configured URLs or unit tests do not prove trust or execution success.

Bind canonical chain ID/account/provider generation; verified deployment manifest/router/token identities and sourced decimals; market/route/path; positive integer raw amounts; net minimum, fees, recipient, spender, calldata/value/fingerprint, quote expiry and replay identifiers. Stale input, edit, account, chain, provider, runtime or navigation changes invalidate prior candidates. Distinguish API error, source trust, preflight, wallet rejection and chain-versus-indexer disagreement. V14 `swap-submit`, `order-sign`, `bridge-submit`, and cancellation prompts stay disabled; V15 quote fetch remains read-only.
