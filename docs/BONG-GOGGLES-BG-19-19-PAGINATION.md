# BG-19.19 — snapshot-bound scoped social pagination (implementation increment)

**Status:** repository-only signed-cursor guard and regression tests; not wired to HTTP, browser, live Wallet/Identity sessions or production canonical/moderation readers. PR #350 remains open. This does not close BG-19.19.

`services/bong-goggles-indexer-v1/src/scopedSocialPagination.js` supplies `createScopedSocialPagination` for account-scoped HOME, FRIENDS and FOLLOWING pages. The server-generated HMAC-SHA256 cursor binds the exact chain, viewer, verified session ID, feed class, indexed block/hash, previous canonical sort key and expiry. An independent, sufficiently long server-held signing key is required. A cursor cannot grant authority: on **each** page, the server must independently verify the current session, canonical indexed block/finality/freshness and **each** record's current audience, block/mute and moderation policy. It rechecks session and canonical hash after asynchronous policy evaluation. If the previously indexed snapshot is no longer finalized/current or its visibility policy is withdrawn, the entire page returns unavailable. The client must refresh from page one instead of silently continuing across snapshots.

The injected `readPage` must provide a deterministic strictly descending `sortKey` order, honor exclusive `after`, return exactly the requested canonical checkpoint for subsequent pages, and give a truthful `hasMore` determined by verified backend lookahead. No raw materialized/private record may be placed in `publicDto`; providers must independently qualify an allowlisted least-data response schema. Caller-supplied `publicDto`, `hasMore`, cursor, session attributes or authorization verdicts cannot be trusted. Keep signing keys out of browser runtime configuration and logs; rotate keys with explicit cursor invalidation.

**Remaining:** production-owned session verifier with revocation, real indexed snapshot retention or an explicit stale-snapshot failure, canonical record order/uniqueness and lookahead, actual current-state per-record policy, independently reviewed DTO allowlists, HTTP authentication and response contracts, rate limits, negative privacy/security tests and deployed real-browser evidence. Public DISCOVER remains a single bounded sample with `hasMore:false`: this module does not silently enable public pagination or authenticated endpoints. All ingress stays disabled until BG-19.16/17 operational gates pass.
