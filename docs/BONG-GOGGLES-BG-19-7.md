# BG-19.7 — Private messaging web client

**Status: messaging presentation and policy model implemented; integration/qualification pending.**

Files: `bong-goggles/web/core/messaging.js`, `messaging-ui.js`, `test/messaging.test.js` and `/messages` integration in `app-shell.js`.

The browser consumes canonical `MessengerConversationRegistry420` request/active/closed state, exact participant-bound inbox/envelope metadata and canonical delivery/read receipts. It rejects foreign participants, duplicate message identities, wrong-conversation envelopes, invalid receipt ordering and recursively forbidden private fields in public projection DTOs. The inbox uses incoming-request-first sorting with deterministic time/conversation-ID tie breaking. The thread displays only envelope metadata; message bodies, attachment bytes and decrypted material are not presented by a public metadata projection. Wallet-bound intent metadata covers accept, send, close and acknowledgement. Device, current policy and private-epoch eligibility gates fail closed.

**Not yet end-to-end complete:** there is no browser-facing qualified BG-14 inbox/thread transport contract wired to the runtime service client; `app.js` does not yet load canonical messaging projections or bind selected-conversation deep links to a dedicated data loader. The qualified device-local encryption/decryption adapter and authenticated attachment retrieval are not integrated into this browser app. For that reason the message textarea remains disabled; the app must not submit plaintext, ciphertext, decryption keys or private URLs through the public JSON service client. Action descriptors are not transaction execution, and none of the message buttons should be represented as functioning sends until their qualified Wallet/Messenger bridge is actually attached. The existing browser UI fails closed rather than claiming successful private delivery.

**Required closeout for BG-19.7:** implement a versioned, authenticated messaging service/read adapter that checks exact viewer/conversation, current block/social policy, device revision, private epoch and canonical sequence on every protected read/write. Connect a device-local encryption interface, Wallet-authorized envelope commit and receipt acknowledgement, transport retry/replay identity, current canonical unread refresh, selected-conversation deep links and metadata-only notification handoff. Add end-to-end tests for transport loss, replay, device revocation, epoch rotation, block and attachment failure before claiming private messaging usable in production.
