# BG-19 integration follow-up: 420Indexer HTTP status diagnostic

The web application now instantiates its existing typed indexer service and requests the repository-defined `GET /v1/status?chainId=<configured numeric chain ID>` HTTP contract from `420-indexer/src/http-transport.ts`. `core/indexer-status.js` validates the `apiVersion: v1` envelope, chain ID, indexed head and finality fields against `420-indexer/src/operational-api.ts`. The app surfaces the result as an explicitly **non-authoritative diagnostic** and fails closed to unavailable when the endpoint is unreachable, the HTTP response fails or the schema/chain mismatch. The reader aborts superseded requests. Tests cover happy path, invalid schemas, network failure and invalidation.

**Scope limitation:** `/v1/status` is the general-purpose indexer HTTP diagnostic. Its successful response does not prove that the indexer is caught up to the network head, that a Bong Goggles feed/profile HTTP projection is implemented, that a particular host is deployed, or that browser CORS, transaction execution, session authorization, private message access, moderation and reward flows work. It never grants write capability. In particular, the generic indexer API does not contain the required browser social projection controllers; do not derive social objects from generic protocol events in the client or mistake this HTTP probe for a BG-19.14 journey qualification.

**Next required implementation:** expose a qualified public Bong Goggles projection on the backend with documented endpoint path, response DTO, visibility filtering, chain/finality/cursor metadata and controlled CORS; test controller output against canonical materialized records; add exact contract-driven frontend normalization, stale-request invalidation and route loading/error states; verify real testnet browser transport and operator release evidence. Private/account-scoped reads require authenticated owner scope in the service, not merely an account string supplied by the browser. BG-19.14/15 closeout remains blocked, and PR #350 remains unmerged.
