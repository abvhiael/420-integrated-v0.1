# Bong Goggles BG-20.3 — rollback, backup and recovery evidence gate

**Status: preparatory code only. Not a live rollback, backup system, drill, or deployment approval.** The BG-19 session, policy, private ingress and deployed browser gates remain outstanding. BG-20.3 cannot authorize a launch. The intended web origin is `https://bonggoggles.420integrated.org` on Cloudflare after release qualification, not a verified deployment today.

`bong-goggles/web/core/operational-recovery.js` provides a non-listening, pure `evaluateRecoveryReadiness` gate. It requires an exact release, environment, commit and SHA-256 digests of the immutable artifact, runtime configuration and effective policy, plus a distinct pinned rollback target. It blocks if private ingress or unqualified feature flags are not explicitly reported disabled. Backup inputs require encrypted snapshot inventory, access review and restore evidence. It requires separately reviewed, release-bound, measured drills for policy outage, chain reorg, access revocation, database restore and media unavailability. Each drill must recheck authorization and show disabled private ingress and unqualified features after recovery. A missing/duplicate/failed drill, missing operator or independent approver, invalid evidence URL, or exceeded RTO/RPO fails closed.

Even a fully populated supplied record produces `hold_for_operator` and `ready:false`, never launch permission. The evaluator checks reported data shape and limits, **not the authenticity of URLs, signatures, actual backup bytes, Cloudflare settings, live access denial, measured recovery, or operator identity**. No credentials, private account data, message content, or backups should be written to GitHub evidence. Operational artifacts belong in access-controlled infrastructure with signed/verifiable references.

## Required live qualification and runbook

1. Pin the exact reviewed release and capture independently verified, immutable build and configuration manifests; verify content digests against actual artifact bytes. Record policy version and contract/chain checkpoints. Sign and retain reviewer and operator acknowledgments separately.
2. Configure Cloudflare custom-domain TLS, DNS, security rules and a tested previous-release deployment for `bonggoggles.420integrated.org`; ensure a rollback does not silently reactivate unqualified private routes or feature flags. Confirm cache invalidation and prohibit cached protected responses.
3. Establish actual encrypted, least-privilege backups of the relevant projections and off-chain data, inventory, restore capability and approved retention. Do not interpret projection rollback as chain rollback or overwrite canonical transactions. Rebuild chain-derived projections only from verified finalized checkpoints, handle reorgs and avoid stale authorization or moderation replay.
4. Run each of the five incident drills against staging with deliberately induced faults. Confirm that policy/session/identity outages deny access; revoked and blocked viewers remain denied across rollback and restore; stale/private media is never leaked from CDN or browser caches. Measure elapsed recovery and data-loss windows against preapproved RTO/RPO; record distinct operator and approver evidence.
5. Test restored app and service health, privacy boundaries, wallet handoffs, public and account-scoped routes, alert delivery and the operator runbook. Keep maintenance and private routes closed on uncertainty; independently review results before a human deployment decision.

`bong-goggles/web/test/operational-recovery.test.js` exercises gate failures and a supplied complete-record hold. Passing CI covers deterministic validation only. BG-20.3 remains **operationally incomplete** until real backups, infrastructure integration, verified staged drills and signed evidence exist. PR #350 must not be merged or production launched solely because this gate passes.
