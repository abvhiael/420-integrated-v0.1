## Persistence and call-path risks

- Both repositories have per-process locks and individually atomic temp-file replacement. **Those do not serialize writes from two independent `FileStore` instances targeting the same pathname**, nor commit Location and Events together. A writer and read-only service opening the files simultaneously can observe incompatible generations.
- Both `OpenFileStore` implementations create missing snapshot files containing empty repositories. The public deployment adapter currently checks file existence before opening, but it cannot by itself distinguish intentionally approved empty publication from an initialized test/blank dataset or validate publisher provenance.
- `Place.Validate` requires an `Owner` reference and a `Source`, but a syntactically valid owner/source value is **not** a verified claim or source licence. Events likewise validate organizer fields without proving that an imported event was approved for republication.
- An event visibility/status change affects discoverability through index rebuilding; a place visibility change affects the public place view. There is no existing cross-entity rule demonstrated here that an event referring to a withdrawn/private place becomes unavailable automatically. Define this in publisher validation before publishing paired snapshots.
- The generic repository APIs remain useful storage primitives, but **must not be published as unauthenticated ingestion interfaces**. Authorized operator/importer workflows should use service-level policies for event lifecycle and a new explicitly controlled Location admission/visibility path rather than writing arbitrary PUBLIC models directly.

## Implemented, tested, or still absent

**Implemented in inspected code:** per-file validated Location and Events persistence; optimistic versioning; provider alias collision protection; event organizer-authorized service create/edit/whole-event transitions; canonical recurrence exception representation and derived public index; read-only public GEN-SVC-2 HTTP API and Travel SDK integration.

**Present as injectable interfaces or tests, not proof of running deployment:** Location dependency authorizer and Registry/Verify readers; injected Events organizer authorizer; in-memory/canonical fixtures; test use of `OpenFileStore`/`Create`/`Update`. The service does not currently bind any live external Identity/Registry/Verify publisher for these snapshot files.

**Not established by inspected source:** an authenticated public place-write service; authorized external importer; source-licence verification; managed operator approval; deletion/tombstone and withdrawal propagation; dedicated occurrence-cancellation command; single writer across processes; cross-store atomic generation; publisher-provenance attestation; deployed canonical data source; actual persistent Railway publisher.
