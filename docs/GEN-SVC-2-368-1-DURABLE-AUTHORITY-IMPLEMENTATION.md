# PR #368 / 368.1 — durable private authority implementation

**Status:** private code and focused tests; NOT an operational publisher, verified live source, atomic canonical+audit transaction or qualified public feed. See [368.1 authority design](GEN-SVC-2-368-1-PUBLISHER-AUTHORITY-AND-PROVENANCE.md), [health contract](GEN-SVC-2-368-0-4-HEALTH-AND-PUBLICATION-STATES.md) and [frozen release scope](GEN-SVC-2-368-0-5-FROZEN-SCOPE-AND-RELEASE-GATES.md).

## Implemented private boundaries

- [Durable decision ledger](https://github.com/abvhiael/420-integrated-v0.1/blob/feature/gen-svc-2-public-deployment/genesis/svc2/publisher/durable.go) adds a single-process, one-writer journal. Each complete post-operation candidate state is chained by HMAC-SHA256 over deterministic Go JSON encoding and an externally supplied >=32-byte audit key; updates use private temp files, file sync, atomic rename and parent-directory sync. On startup it rejects invalid schemas, sequence, MAC, state or record data and restores withdrawn/rejected tombstones. State becomes visible through this ledger only after its local journal write. The prior `NewLedger` remains an in-memory helper for tests; authoritative staging code must use `NewTrustedDurableLedger`.
- [Deployment trust policy](https://github.com/abvhiael/420-integrated-v0.1/blob/feature/gen-svc-2-public-deployment/genesis/svc2/publisher/trust.go) requires an independent `PrincipalResolver`, an explicit allowlist of action/kind grants for operators, a qualified source manifest and terms/attribution/validity grant, and a trusted injected clock. The operator ID from a request must equal the authenticated resolver result. These are **configuration interfaces**, not evidence that credentials, licences or authenticated principals have actually been provisioned on Railway.
- [Canonical bridge](https://github.com/abvhiael/420-integrated-v0.1/blob/feature/gen-svc-2-public-deployment/genesis/svc2/publisher/canonical.go) binds an approved candidate to the exact JSON hash of an existing canonical Place or draft Event payload and checks operator authorization again at apply time. It delegates place visibility and withdrawal to the [restricted Location publication writer](https://github.com/abvhiael/420-integrated-v0.1/blob/feature/gen-svc-2-public-deployment/location/service/publication_write.go), preserving optimistic version and immutable owner/Registry fields. Event creation and whole-event cancellation delegate to `events/service.Service` and therefore require its independently configured real organizer authorization. No external importer can turn its own unverified organizer assertion into an authorization grant through this bridge.
- Focused tests cover journal restart, tombstone persistence, modification detection, untrusted/revoked policy, spoofed operator ID, denied write durability, approved canonical place mutation, ownership takeover and stale-version/withdrawal rejection. See [journal tests](https://github.com/abvhiael/420-integrated-v0.1/blob/feature/gen-svc-2-public-deployment/genesis/svc2/publisher/durable_test.go), [bridge tests](https://github.com/abvhiael/420-integrated-v0.1/blob/feature/gen-svc-2-public-deployment/genesis/svc2/publisher/canonical_test.go), and [Location tests](https://github.com/abvhiael/420-integrated-v0.1/blob/feature/gen-svc-2-public-deployment/location/service/publication_write_test.go).

## Remaining mandatory gates — do NOT connect to public HTTP

1. The journal is **single-writer local staging**; it is not a distributed transaction, external attestation or immutable storage. HMAC detects rewriting without the key, but **cannot detect a truncated valid prefix without an independently protected checkpoint of `(sequence, head_MAC)`**. Configure and test external checkpoint storage, restore and key rotation/revocation. Protect audit key in a deployment secret; never commit the key or allow the source feed to specify trust anchors. A failed directory sync after rename may leave ambiguous disk state; quarantine the instance and reopen/reconcile before any subsequent action. Add a tested exclusive-writer/lock strategy for real deployment.
2. The ledger decision and canonical repository write are separate durable operations. The bridge cannot atomically commit both. Define and test an idempotent write-ahead command/outbox with reconciliation for crash between approval, canonical mutation and publication. `Approved` is *not* synonymous with `canonical-applied` or `published`. Resolve existing Event update/occurrence cancellation and place delete/withdrawal policy gaps before importer automation.
3. Explicitly provision and verify a real operator authenticator, scoped source policy and licensing documents; restrict permission to the operator process. The allowlist matches source metadata supplied by an importer against deployment configuration but does not by itself cryptographically authenticate a remote provider, attest source truth, or validate licence terms.
4. Build versioned paired Location+Events publication, cross-store snapshot checks, signed manifest verification against deployment-controlled trust anchors, revocation floors, freshness policy and fail-closed readiness in later phases. Current public handler still reads independent files and **must not be given the ledger or its audit key**. `SVC2_PUBLICATION_SOURCE` remains a label, not a trust decision.
5. This work does not deploy Railway storage, source import, operator identity, Events publisher credentials or Travel binding. Keep PR #368 draft. Code-level CI and live release acceptance must be evidenced separately at exact commits.
