# GEN-SVC-2 368.1 — checkpoint, write recovery and deployment trust gates

Status: private code on PR #368. **Not an operating publisher; not approved to connect to public HTTP, promote a paired generation, or enable Travel.** The baseline [authority contract](GEN-SVC-2-368-1-PUBLISHER-AUTHORITY-AND-PROVENANCE.md) and [frozen scope](GEN-SVC-2-368-0-5-FROZEN-SCOPE-AND-RELEASE-GATES.md) remain controlling.

## Implemented code (private only)

- [checkpoint.go](https://github.com/abvhiael/420-integrated-v0.1/blob/feature/gen-svc-2-public-deployment/genesis/svc2/publisher/checkpoint.go) requires an independently administered `AuditCheckpoint` with linearizable `Read` and monotonic compare-and-swap. `OpenGuardedLedger` rejects a missing, deleted, truncated or divergent journal against a previously stored head. Mutations update the journal then the checkpoint; if either step fails, further use fails closed until independently reviewed reconciliation. The in-memory checkpoint in [checkpoint_test.go](https://github.com/abvhiael/420-integrated-v0.1/blob/feature/gen-svc-2-public-deployment/genesis/svc2/publisher/checkpoint_test.go) is **test-only**. No live remote checkpoint backend, protected checkpoint account or recovery procedure is provisioned; `DurableLedger` remains available for legacy isolated tests and must not be promoted as proof of audit integrity.
- [operations.go](https://github.com/abvhiael/420-integrated-v0.1/blob/feature/gen-svc-2-public-deployment/genesis/svc2/publisher/operations.go) durably records a private canonical mutation intent before a write, and requires real canonical readback at exact expected version and digest before marking it applied. Restart with pending, uncertain or conflicting outcomes never implies successful application. [canonical_recovery.go](https://github.com/abvhiael/420-integrated-v0.1/blob/feature/gen-svc-2-public-deployment/genesis/svc2/publisher/canonical_recovery.go) wires the path for **existing-place approvals only**; event creation/cancellation, place creation/withdrawal and occurrence cancellation still need analogous post-image-reconciled commands and fault-injection coverage. The operation log itself has no independent anti-truncation checkpoint and must not be used as publication evidence.
- [deployment_trust.go](https://github.com/abvhiael/420-integrated-v0.1/blob/feature/gen-svc-2-public-deployment/genesis/svc2/publisher/deployment_trust.go) loads operator/source grants and overlapping credential-key identifiers from a deployment-only, owner-readable regular file whose SHA-256 must match an independently pinned deployment value. A restricted caller must supply a real secret; operator identity is resolved against hashed provisioned credentials, then authorizations are checked against grants. Disabled/expired credentials and source grants fail closed. [deployment_trust_test.go](https://github.com/abvhiael/420-integrated-v0.1/blob/feature/gen-svc-2-public-deployment/genesis/svc2/publisher/deployment_trust_test.go) uses test credentials only.

## Remaining external provisioning and release blockers

An operator must select and provision **a real authenticated identity**, independent secret distribution/rotation, and authorized source manifests/terms/attribution with verifiable rights. No operator ID, secret, source licence or manifest in these tests is real deployment authorization. Provision an independently secured remote checkpoint with atomic monotonic CAS in a separate administrative/failure domain; configure and test power-loss recovery and a restricted manual reconciliation procedure. There is no configured checkpoint service or privileged secret store in the repository, and a checkpoint file on the same Railway volume does not qualify.

The privileged publisher must use the guarded ledger, independently protected operation state, and a single authorization-checked dispatcher for **every** canonical mutation. Add crash injection at each write boundary and use post-image reconciliation after restart; block publication until every referenced operation is applied and its withdrawal floor reflected in the active paired generation. Bind journal sequence/head, operation completion proofs, trust-policy version and credential/source revocations to the signed generation manifest in phase 368.5. The present `/readyz` remains only a snapshot-readability check and must not be presented as verified publication.

## Verification and constraints

Unit tests exercise isolated guards and failure handling, not a deployed checkpoint backend or real credentials. Require an exact qualified branch commit and separately successful deployment acceptance before marking phase 368.1's operational gates complete. PR #368 remains draft; no release or production-readiness inference is permitted from code CI alone.
