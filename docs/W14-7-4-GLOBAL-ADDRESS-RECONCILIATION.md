# W14.7.4 — global Genesis address reconciliation

**Status: global collision-free candidate drafted; active registries NOT migrated, freeze exception NOT approved, deployment NOT attested.** PR #358 stays draft. Wallet `readyForLiveTestnet` and `canonicalAddressConflictResolved` remain false. Do not enable send, sponsor, or read the candidate in production runtime.

## Decision requiring chain/consensus and cross-app review

The existing `config/system-addresses.json` and `contracts/config/system-addresses.json` describe `0x0420..0x043b` as unchanged/frozen and fix `ConsensusSystemCall420` at `0x043c`. The canonical Wallet/application registry claims incompatible identities throughout the same range. In particular, its Names420 reservation is `0x0445` but the legacy system and predeploy records put Names420 at `0x0435`. It is impossible to preserve **all** existing frozen application placements while also preserving the Names420 reservation and Wallet destinations `0x0446..0x0449`: two locations for one logical contract or two contracts at one address would result. This is an explicit governance/chain-release decision, not a wallet-only patch.

The proposed reconciliation retains every economic/consensus assignment at `0x0420..0x0433`, the native consensus gateway at `0x043c`, and the EntryPoint420 reservation at `0x041f`. It **proposes an explicit exception** to the old `0x0434..0x043b` application freeze: migrate all eight existing application/predeploy identities to unique new locations, tombstone the legacy locations, and update every reference in the same release candidate. It retains Names420 at `0x0445`, chooses SmartAccountFactory420/CapabilityRegistry420/ProtocolRegistry/Identity420 at `0x0446/0x0447/0x0448/0x0449`, and rehomes the colliding bridge candidate BridgeAssetRegistry from `0x043c` to `0x0462`. The full 28-authority map, other bridge candidates, and eight migrated app identities are machine-readable in [`contracts/config/w14-7-4-global-address-reconciliation.json`](https://github.com/abvhiael/420-integrated-v0.1/blob/wallet-w14-6-names-send-integration/contracts/config/w14-7-4-global-address-reconciliation.json).

**A free-looking address is not proof of availability on any existing live chain.** Before approval, confirm that the proposed destinations and tombstoned locations do not contradict the selected official network genesis, deployed code, storage, immutable constructor references, registry state, chain upgrades, bridge proofs or already published signed manifests. If they do, use a separately approved migration/chain-relaunch plan; never silently reassign live addresses.

**W14.7.4 exit criterion:** cross-protocol address decision approved; active and mirrored records, code references and artifacts consistently migrated; no collision or multi-address identity in the real-data audit; no unexpected existing-chain state. Until then status is `IN_PROGRESS_CANDIDATE_ONLY`.
