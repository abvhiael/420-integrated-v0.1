# User guide

Browse by category, search registered applications, inspect details, compare versions and open applications through 420 Wallet. Application detail should expose Registry-backed identity, network, publisher provenance, contract/implementation references, verification evidence, permissions, deprecation/security warnings and launch targets.

Sponsored placement must be labeled and cannot alter canonical identity or ownership fields.

## Find 420 Pay

Browse **Payments** or search for Pay, POS, checkout, or a mobile platform.
The Genesis-approved listing describes consumer payments, merchant dashboard,
physical retail POS, hosted checkout, Android, iOS, and developer integrations.
The [Pay user guide](../pay/user-guide.md) explains the application scope.

Publication states describe each expression's progress.

| State | Meaning |
|---|---|
| Planned | Approved product scope awaiting implementation |
| Locally implemented | Implemented in the repository with local evidence |
| Testnet qualified | Qualified against the public testnet |
| Production available | Released for production use |

All seven Pay expressions are currently planned. The proposed web origin is `https://pay.420integrated.org`. See [Wallet discovery](../../users/wallet/dapp-connections.md#420-pay-in-wallet) for verified navigation and connection requirements. The curated card links to
documentation and the Registry-backed detail view. Contract identity and
settlement evidence come from Registry and chain state. Wallet controls any
separately published launch and transaction authorization.
