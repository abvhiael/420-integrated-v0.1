# Getting started with 420 Registry

Use 420 Registry when you need to identify a canonical service implementation, version, activation state, runtime/code commitment, or registration profile.

Before relying on a result, confirm the network, service ID, version and active/inactive status. For security-sensitive integration, also compare the expected interface, manifest and dependency commitments required by your client.

Do not treat a cached address, search result or UI badge as stronger than current Registry state. If the current service is deprecated or inactive, fail closed or resolve a later approved version rather than silently using an arbitrary address.
