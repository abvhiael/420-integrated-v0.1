**Scope:** The five canonical Arbitration source entries: `ArbitrationIds420.sol`, `ArbitrationPolicyRegistry420.sol`, `ArbitrationCaseRegistry420.sol`, `ArbitrationRulingRegistry420.sol`, and `ArbitrationRouter420.sol`; Wallet/runtime and evidence/storage adapters; Indexer historical reads; and existing Commerce/Launchpad consumers.

## Confirmed contract defect and correction

**Deadline width / representation risk — remediated.** `ArbitrationCaseRegistry420` originally persisted `uint64` open, evidence and appeal timestamps using `uint64(block.timestamp)` and an addition of a governance-configured `uint64` window. A near-limit timestamp/window could overflow or truncate. `openCase` now explicitly rejects a timestamp over `type(uint64).max` or a window that cannot fit before deriving a case ID or consuming a nonce. `appeal` refuses an unrepresentable new evidence deadline before incrementing the round or switching state. `markRuled` refuses an unrepresentable appeal deadline before switching state; failure reverts the enclosing `RulingRegistry.submitRuling` write, leaving no phantom ruling. The externally observable state and legitimate normal-range deadline rules are unchanged.

Direct tests: `testTimestampOverflowRejectsCaseWithoutNonceConsumption`, `testRulingDeadlineOverflowAtomicallyRejectsCommitment`, `testAppealedEvidenceDeadlineOverflowRetainsOriginalRound`, and `testRulingDeadlineExactUint64Boundary`. These include exact upper-bound acceptance and finalized state only *after* the inclusive appeal boundary. Existing canonical case, ruling, appeal, Registry and deployment tests remain intact.
