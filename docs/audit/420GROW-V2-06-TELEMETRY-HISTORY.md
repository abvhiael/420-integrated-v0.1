# GROW-V2-06 — Sensor telemetry ingestion and historical charts

**Implementation scope:** new private app-domain telemetry service for validated sensor and manually entered observations; not a production actuator, device adapter, or public directory. Architecture follows qualified V2-02 tenants/security and V2-03 database; V2-05 Level 2 remains retained, next cumulative Level 2 is V2-10.

- Ingestion: `grow/telemetry/service.go` requires server-authenticated principal and ACTIVE, tenant-correct facility/zone membership with `PLANT_WRITE`; checks bounded UUID/opaque identifiers (actual SQL UUID enforcement), source, sensor, kind and canonical unit, measurement ranges, finite values, timestamp freshness, and future time rejection. PostgreSQL unique tenant+observation ID prevents replay. No device credential auth or hardware integration is claimed until V2-07.
- History: `History` gives an ordered, tenant-restricted, facility+zone+kind bounded time-series suitable for charts, using limit 1–500, start-inclusive/end-exclusive range and a maximum 366-day window. Output carries time/value/unit/sensor/source. The reusable `grow/telemetry/chart.mjs` renderer produces an accessible bounded SVG chart from previously authorized readings, with safe numeric-only coordinates, UTC marker, and empty-state labeling. V2-13 owns integration into authenticated app navigation; this step does not deploy a public chart page.
- SQL repository: application-controlled transaction-local tenant context, parametrized query, composite tenant/zone FK, indexed range scans; `0004_telemetry.up.sql` adds sensor metadata, DB-enforced kind/unit/range constraints and range index. No canonical chain data, Genesis authority or public Place information exposed.
- Sources are explicitly observational, not proof of calibration or advice. No automatic controls based on ingested readings. Device adapters, signed ingest/MQTT authorization, calibration and outage alarming require V2-07, V2-08 and V2-14 qualification.
- Threat model: cross-tenant IDs, spoofed origin, wrong facility/zone, invalid unit, NaN/Inf, extreme or future readings, duplicates/replay, unrestricted scans, stale/missing auth, role escalation. SQL restrictions are defense in depth and not a substitute for server identity validation.

**Required Level 1:** Go unit/race/vet/gofmt, Node chart renderer tests, migration checksum replay, PostgreSQL FK/constraints and cross-tenant RLS, previous V2 scopes retained under app-specific CI and the original 420Grow fast regression. Exact candidate SHA and job conclusions must be preserved. Cumulative Level 2 is intentionally deferred to V2-10; comprehensive Level 3 to V2-15; production testnet V2-16.

**Next canonical step:** GROW-V2-07 — Equipment adapters, monitoring and safe controls.
