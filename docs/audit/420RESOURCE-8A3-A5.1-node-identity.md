# A5.1 — Canonical node identity

Node IDs are registry-local Keccak-256 hashes of six static ABI words: keccak256("420/RESOURCE/NODE/IDENTITY/V1"), providerId, serviceId, node operator address (left padded), initial endpointHash and initial capacityHash. Chain and registry context remain external. The provider operator may appoint an independent node operator. Delegated registration additionally requires the exact node-scoped capability and revocable provider-operator consent; consent is provider/node namespaced and consumed on success. Existing registered IDs are never reassigned, including after retirement. Endpoint and capacity updates do not recalculate the ID; provider, service and operator remain immutable. Identical initial payloads intentionally identify the same node; distinct nodes need distinct initial commitments. Legacy arbitrary IDs are not accepted for new registration; pre-testnet fixtures and callers must derive IDs and regenerate node-scoped grants. Existing stored records are not rewritten. The ABI is additive and storage append-only; historical artifacts remain unmodified. SDK helper and migrated integration fixtures use the same derivation. Qualification pending.
