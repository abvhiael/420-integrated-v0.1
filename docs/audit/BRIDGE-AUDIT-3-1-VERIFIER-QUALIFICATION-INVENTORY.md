## Qualification meanings

- **Independent components qualified:** identified cryptographic routines/native protocol code and genuine historical evidence have retained independently checked results. This alone does not authorize a gateway deposit.
- **Local verifier qualified for its documented model:** the concrete composition and local adversarial paths qualified, including explicit issuer, bootstrap, validator snapshot or native replay authority assumptions. A trusted replay checkpoint is not described as a permissionless consensus light client.
- **Historical native issuer gateway qualified:** CCTP and CADC have genuine issuer-protocol transfer evidence. Their supported-chain history and local/fork reconstruction do not establish 420Chain issuer support.
- **Production route qualified:** requires authenticated deployed identities/configuration, approved authority/root, live source gateway/settlement evidence and governance registration. **No production verifier instance or route is approved by this audit.** All launch routes retain their inactive status.

## Identity, admission and settlement

V.19–V.21 enforce governance qualification, exact runtime and proxy implementation identity, current source/destination chain and configuration, immutable route approval binding, revocation/expiry and persistent replay. Transfers cannot adopt a replacement approval silently. Only the canonical router may assert verification or completion. Completion requires an authenticated delivery receipt matching canonical token, recipient, message and amount. Proof-only verifiers cannot manufacture settlement. Emergency suspension, both-direction disable, dispute and governed recovery remain available.

V.22 closes a composition gap in the imported native CADC adapter: it must call CADCBridgeIntegration.requireActive, which validates live qualification, rather than authorize from a stale stored active flag. The actual-guard revocation regression covers native delivery before any token or endpoint side effect. Older gateway test setups establish the same actual qualification required in production; production guards are not weakened to make old tests pass.

V.22 also reconciles the outstanding BRIDGE-AUDIT-3.2 draft: every canonical router ingress requires a versioned envelope bound to the configured route, source/destination networks, verifier configuration and executing destination router/chain. Its claims must match the authenticated adapter result and source gateway/token context. Refreshing caller transport timestamps cannot reset source replay state. The transport observation window is not proof of source-tip freshness. The 4,200,000-byte bound accommodates the existing shielded proof format; individual native verifiers retain their tighter bounds. A strict public-data Python encoder supplies the transport without handling signing or viewing credentials.
