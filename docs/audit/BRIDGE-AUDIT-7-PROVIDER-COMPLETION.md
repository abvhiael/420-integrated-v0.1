Replacing provider state requires explicit fresh existing qualification and route admission. Consumed nonce/GUID and router replay state are never reset.

Only issuer-approved native deployments qualify. Governance cannot derive external authorization from an arbitrary contract implementing the same ABI, a hash label or a JSON flag. Existing trust-root and identity records must contain independently established issuer/provider evidence. There is no new unofficial representation or local token-mint contract in this change.

## Public support observations — 16 November 2026

Circle's [official supported-chain/domain list](https://developers.circle.com/cctp/concepts/supported-chains-and-domains) includes the configured Ethereum, Arbitrum and Base source domains and does not list 420Chain. EVM chain ID 420 is not an assigned Circle domain. Permissionless application integration on a supported chain does not create native USDC issuance authority on a new chain. The [official contract list](https://developers.circle.com/cctp/references/contract-addresses) still matches the configured Ethereum/Arbitrum/Base MessageTransmitterV2 and TokenMessengerV2 addresses. The separately published TokenMessengerWithFees interface is not silently substituted for the approved V2 path.

The [CADC issuer publication](https://loon.finance/blog/access-cadc-on-layerzero/) lists upgraded CADC on Ethereum, Base, Polygon and Solana, with Arbitrum paused; these token identities match the existing configuration. It identifies CADC Reserve Trust as issuer and Loon Payments as servicer. Neither a 420 deployment nor private issuer authorization is established. [LayerZero's official OFT documentation](https://docs.layerzero.network/v2/developers/evm/oft/quickstart) describes the native debit/credit path and peer/security configuration; protocol availability alone does not authorize CADC issuance. Retrieval URLs, facts and exact local source/config hashes are retained in `provider-completion-qualification/RECONCILIATION.json`.
