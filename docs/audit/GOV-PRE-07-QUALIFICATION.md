Source implementation head: `df67a6648f5e27f0098fd25a6d3edcce2dd6b493`, retained GOV-AUDIT-6 materialization following this revision. Review in [draft PR #1334](https://github.com/abvhiael/420-integrated-v0.1/pull/1334), authoritative repository `abvhiael/420-integrated-v0.1`.

- `contracts/src/governance/FoundingRetirementVerifier420.sol` rechecks exactly 60 unique, eligible, continuously qualifying registered Validator owners with individual distinct independent Timelock-approved witness hashes and at least 15 distinct, actually nominated Committee members with separately reviewed independent attestations. It binds signed nomination at review time and rejects changed evidence; validator pool, individual validators, unchanged Committee count, both complete witness rosters and each witness clock must remain qualified for 30 days. A merely successful previous dual-house proposal never authorizes the actual retirement transaction.
- `contracts/src/governance/CivicGovernor420.sol` adds a read-only, ephemeral `activeDualHouseExecution`/proposal marker only during the authenticated, actually executing dual-house Civic Timelock batch. The marker is cleared after execution or reverted atomically on a failed batch, and is **append-only after existing Governor mappings** in storage. This marker grants no new execution privileges and cannot replace the Timelock's existing reentrancy protections.
- `contracts/src/treasury/FoundingTreasuryAuthority420.sol` allows `retire()` exclusively as a genuinely executed Timelock action inside that active dual-house batch and only if the independent 60/15/30 status is currently valid and the Civic scheduler handoff was already effective. Retirement is irreversible and disables all existing founder payment/proposal, release execution and one-shot executor-binding powers. **Unpaid scheduled founding Treasury Budget Registry reservations** block retirement; Civic-canceled disbursements correctly release the actual reservation without erasing the historical audit counters.
- `contracts/src/treasury/FoundingCommunityRetirementSweep420.sol` moves native assets only via source-Vault exact route-scoped capability into the pre-registered `VAULT_COMMUNITY` Vault; `sweepToken` additionally moves recorded ERC-20 assets through a separate exact route to a noncustodial atomic transfer/deposit forwarder. Both enforce actual source/destination custody deltas, VaultAccounting increases/decreases, unchanged reserved/claimable liabilities and no open founding Treasury commitments. Missing routes, wrong destinations, fees/shortfalls and token-callback/reentrancy attempts fail closed. **No third party can grant itself a withdrawal capability through this contract.** Both source Vaults must have zero recorded assets, zero open obligations and zero native balances before `custodyHandoffComplete` can return true. Real unenumerated ERC-20 tokens require an independently verified inventory: the EVM cannot enumerate unknown token contracts at an address.

These changes do **not** rewrite the locked 42M Genesis supply, 4.2M Operations and 840K Contingency suballocations, frozen G1–G4 voting thresholds/timelock floors, founder wallet identities, or historical Ledger/Validator/Stake decisions.
