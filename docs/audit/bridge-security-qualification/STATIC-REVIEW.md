# Static analysis and external dependencies

Slither 0.11.3 ran 99 detectors on compiler AST and SlithIR for all **101 production bridge Solidity sources**, their **149-file import closure**, and **173 contracts/interfaces/libraries**. This is source/dataflow analysis, not a new bytecode or live deployment certification. The compiler is SHA-256-verified official Solidity 0.8.24, with the repository's Cancun, optimizer 200 and via-IR settings. Crytic's AST import receives empty bytecode markers because bytecode was not requested; that is explicit in the reproducer. Retained runtime-size evidence and the new Forge build supply separate bytecode evidence.

There are 386 bridge-relevant detector records (12 High, 173 Medium, 52 Low, 147 Informational, 2 Optimization); the entire import closure produced 388. Detector severity alone is not confirmation of an exploit. `slither.json.gz` preserves every original bridge-relevant result, source location, detector ID and source fingerprint; `static-triage.json` accounts for every ID. No detector is disabled or hidden through a source suppression. The two findings outside the bridge filter are not represented as bridge findings. Shared access/dependency guards are separately assessed below.

## High findings

| Detector | Count | Assessment |
|---|---:|---|
| arbitrary-send-erc20 | 3 | CADC/USDC outbound entry points are canonical-router-only and protected against callbacks. Custody reserve is canonical-router-only, guarded by `entered`, and receives the actual router caller as sender. Allowance, exact balance changes and current qualification remain required. The sender argument is necessary for delegated execution; it is not caller-controlled spending authority. |
| arbitrary-send-eth | 1 | Ethereum payout recipient and amount are authenticated by the qualified backing verifier over the entire outbound request and its gateway/chain domain. Permanent payment/cancellation identity and `entered` are committed before the recipient call. Arbitrary caller-supplied addresses cannot release value. |
| controlled-delegatecall | 1 | BridgeVerifierProxy420 is deliberately a governance-controlled proxy. Updates require the immutable governance timelock, exact expected implementation version, nonzero deployed target and unchanged identity after initialization. Admission separately requalifies runtime, implementation/version, roots and configuration. Governance upgrade authority does not inherit an old verifier approval. |
| encode-packed-collision | 1 | Litecoin Scrypt HMAC concatenates a fixed 64-byte outer pad and a fixed 32-byte digest. The inner pad is also fixed at 64 bytes; only the salt varies. There is no ambiguous pair of attacker-chosen variable-length fields. Do not replace protocol HMAC serialization. |
| incorrect-exp | 4 | `i ^ 1` deliberately selects the sibling index in a binary Merkle tree. It is XOR, not exponentiation. Bitcoin, Tron, POT and CURE Merkle bounds use it intentionally; historical inclusion/odd-width/native-wire evidence remains at its original source SHA. |
| reentrancy-eth | 2 | Ethereum source payout/refund set the reentrancy flag and permanent outcome before the external payment. The reported later state write resets that flag. Backing verifier calls are `view`/STATICCALL; source configuration changes are timelock-only and guarded. Post-call current qualification and exact deltas remain checked. |

These are contextual detector warnings; no Solidity vulnerability was confirmed from these twelve records. The client findings described in the audit report were confirmed separately and corrected.

## Medium findings

| Detector | Count | Assessment |
|---|---:|---|
| incorrect-equality | 14 | Exact equality is the conservation and authority assertion: no transfer tax, partial mint/burn, token/code/qualification substitution or changed reservation can be silently accepted. A token that violates the exact delta can reject its own unsupported route, not obtain an unbacked credit. New hostile-token tests exercise rollback. |
| locked-ether | 16 | Thirteen concrete protocol adapters reject nonzero `msg.value`; two unwired legacy adapter placeholders always revert. BnbDepositGateway420 deliberately escrows source BNB and explicitly documents that source withdrawal custody is a separate inactive deployment dependency. This audit does not turn that deposit-only source gateway into a qualified withdrawal service. Native source custody remains a real prerequisite in the existing roadmap. |
| reentrancy-no-eth | 7 | Custody fund/reserve/outcome/refund paths share `entered`; mutation is canonical-router-only and configuration/verifier replacement checks the guard. Ethereum and BNB source deposits hold their guard across token calls. Read-only getters do not create authority. New mint/burn/refund/funding callback tests complement retained source/issuer regressions. |
| uninitialized-local | 80 | Reviewed scalars, counters, accumulators and memory arrays use Solidity's zero/default initialization or are assigned in all accepted branches. They are not uninitialized storage aliases. For example, Ethereum MPT's child is assigned for either accepted node shape, and all other shapes revert; zero receipt fields are checked before use. Crypto arrays/counters are part of the retained vector-qualified algorithms. |
| unused-return | 56 | Tuple destructuring intentionally selects only relevant fields; validators are invoked for their revert behavior. `requireCurrent`, RLP scalar canonicality and kernel/output validation cannot be bypassed by discarding their return values. The Wallet client separately had a meaningful ignored admission identity; the corrected client now binds that returned qualification ID to its review. |

The two placeholder payable functions cannot successfully retain value because they always revert. All concrete adapter nonzero-value guards and source escrow boundaries were checked directly; a forced native-token donation does not create a bridge payment right.

Low/informational/optimization records concern guarded post-call event/state writes, bounded external-probe loops, explicit timestamp/finality rules, audited assembly/crypto constants, complexity, naming, event availability, pragma and self-calls. They are retained rather than reformatted away. A style or gas preference is not treated as a confirmed protocol vulnerability. Probe manifests retain their existing 16-dependency/64-probe/512-byte bounds and fixed call-gas budget; serialized proof and native-family work bounds remain in the original qualified implementations.

## External contracts and trust boundaries

| Dependency | Required authority and reviewed control |
|---|---|
| ProtocolRegistry and resident guards | `_requireResidentActive` binds this exact address/runtime/version. `_resolveRequired` checks active state and runtime hash. The immutable timelock plus GovernanceAuthority permission and satisfied delay gate configuration. Registry governance remains an explicit trust root, not an untrusted metadata API. |
| Safety, Pause, ChainContext, assets, settlement health and risk | Dependencies are resolved through the checked Registry. Normal transfer and withdrawal-recovery classes retain their distinct safety semantics. Health/accounting does not gain mint authority. Role revocation/configuration substitution and pause/retry/source-reorg behavior retain their qualified evidence. |
| Verifier/proxy/route qualification | Direct, managed, ERC1167 and audited-public identities pin the permitted delegation model; nested delegation is rejected. Root/config probes and route hashes bind the approved instance. Rotation requires a fresh qualification and never resets source/outpoint/message/nullifier replay. A governance coalition that deliberately installs an arbitrary new trust root is not represented as cryptographically impossible. |
| ERC-20/representation custody | Tokens are canonical asset/runtime/decimal-bound; mint/burn representations have an immutable direct custody controller. Only authenticated funded settlement can mint, burn or refund. Exact actual token deltas, approved direction and original reservation/qualification are independently checked. Malicious or upgraded issuer tokens, blacklist/depeg and off-chain reserve quality remain explicit external risks, not synthetic guarantees from a balance getter. |
| Circle USDC | Native MessageTransmitter/TokenMessenger/Minter, supported domain, attesters/threshold, token mapping and issuer configuration remain required. Controlled local issuer tests do not grant 420 issuer support or permit an unofficial USDC mint. |
| CADC / LayerZero | Issuer OFT/OFTAdapter, Endpoint V2, peers and multi-DVN security configuration remain pinned and rechecked. Native token balance-change delivery is required. No generic status provider or 420 validator committee can substitute for issuer/native authorization. |
| Native verifiers / source custody | The fourteen families retain their documented local proof/trust models and original hashes in `retained-evidence.json`. BTC SPV is probabilistic best-known work plus confirmations; owned UTXOs/backing/HSM and source outcome services remain separate. SOL stake/voter authority and genuine bridge-domain execution certificates, POT native-history lineage and Pirate/KMD/notary infrastructure retain their existing unresolved production prerequisites. |
| Wallet/RPC/provider | The selected EIP-1193 provider remains a wallet and RPC trust boundary. Client code pins Registry/runtime state, exact recipient/asset/network, qualification identity, simulation and explicit confirmation; it now also rechecks the last wallet state and sends the expected EIP-155 chain ID. It cannot defend against a malicious wallet deliberately lying and signing arbitrary transactions. |

There are zero production approvals and no live route activation. Qualification of the implemented internal boundary does not erase external issuer/source-custody/finality prerequisites or certify a real third-party deployment.
