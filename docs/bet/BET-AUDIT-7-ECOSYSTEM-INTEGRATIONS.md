## Implemented in this branch

**420Indexer handoff:** Production/official-network requirements for the implemented repository reader are now tracked under `TN-BET-7-INDEXER` in the canonical testnet roadmap. This does not claim local full-suite green: BET-AUDIT-7 focused Level 1 passed 19/19 at SHA `b88eb9e61c1aadeb4b5c2fb37c01b0f8f842310f` (run `42569233149`), while 420Bet lobby broad regression run `42569233150` failed 8/443 in untouched frontend tests. Those failures remain a local acceptance concern. Full PR #1089 remains draft/unmerged.

**420Wallet/420Identity local implementation:** `server/wallet-identity-sessions.mjs` and `server/canonical-identity-eligibility.mjs` establish an explicit security boundary. The session manager requires a real signature-verification callback, distinct read-only scoped nonce challenges, replay protection, expiry, and fresh Identity policy revalidation for each authorized access. The eligibility adapter checks the frozen on-chain credential interface on the configured chain and requires a trusted address-to-subject binding plus independent eligibility verification. Neither component invents user eligibility or issues spending authority. Their local fixture tests are `tests/wallet-identity-integration.test.mjs`; real verifier, live policy/provider and HTTP wiring are not claimed.

`clients/420bet-lobby/server/ecosystem.mjs` accepts *already-verified* event records injected by a future independently qualified chain/indexer adapter; it does **not** read untrusted public web callbacks or accept a browser claim of transaction settlement. A caller must verify emitting contracts, approved ABI, receipt provenance and finality **before** using it.

- Strict chain/game/account tuple and a small event-type vocabulary; malformed, out-of-range and cross-scope events are denied.
- Unsigned decimal block/log bounds, explicit safe head, normalized hashes and addresses, bounded batch size.
- Idempotent replay and a required explicit `rewindFrom` for canonical replacement. Empty replay windows remove orphaned events. Mixed block hashes or conflicting tx/log identities fail closed.
- Count-only summary without wallet identifiers or wager amount. Counters are non-authoritative visibility aids and must never alter escrow, balance, eligibility or settlement.
- `server/indexer-event-abi.mjs` computes Keccak-256 topic0 from the **actual** Solidity event ABI signatures for shared casino router/settlement, poker ledger/canonical settlement, fantasy contests and sportsbook tickets. No browser-provided event is trusted.
- `server/indexer-event-reader.mjs` reads approved-contract logs from Indexer v1 with strict chain/receipt/block identity and finality checks, cursor-opaque pagination, atomic filesystem checkpoints, startup recovery, and full rollback/rebuild if the previously committed canonical safe tip diverges. It does not grant wagering authority.
- `server/sync-indexer-events.mjs` exposes a backend-only operational command using an explicit manifest and durable private checkpoint; see `BET-AUDIT-7-INDEXER-WORKSTREAM.md`.
- `tests/ecosystem.test.mjs`, `tests/indexer-event-reader.test.mjs` and `.github/workflows/420bet-ecosystem-7-level1.yml`.

**Important limitation:** The **original in-memory** `ecosystem.mjs` module cannot independently detect chain reorgs; the new Indexer adapter implements tip-hash detection and full deterministic rollback/rebuild for its **own** checkpoint. The adapter does not independently authenticate RPC consensus, live service deployment identity, or downstream outbox/search/analytics invalidations. Its test HTTP fixtures are not official-network proof. A future consumer of the checkpoint must invalidate all orphaned projections whenever a rebuild occurs.

## 420Notifications/420Mail repository integration

`server/notifications-mail-adapters.mjs` provides a real 420Mail `POST /v1/outbox` + `/process`, `GET /v1/outbox/{id}` and `/cancel` adapter, verifying the authenticated actor, exact idempotency key and owner-bound delivery receipt; a qualified 420Notifications delivery adapter cannot be constructed without required private send/receipt/cancel callbacks. `notifications-mail-outbox.mjs` is a private durable single-writer outbox with bounded backoff, crash recovery, dead-letter, opt-in recheck at delivery, cross-tenant idempotency, explicit revocation and persistent reorg halt. `notifications-mail-source.mjs` requires verified finalized Indexer logs, signed Registry source mapping and independent audience/ownership checks, with no unsupported conversion of a poker/fantasy/settlement event into a recipient address. `notifications-mail-runtime.mjs` composes these trusted backend components only when the real provider and consent authorities are injected. No browser, spending permission or unsafe public event feed has been enabled.

**Release boundary:** The 420Notifications Go runtime currently exposes service readiness, not a public per-user delivery/receipt/cancellation HTTP protocol. This remains an explicit service-interface integration gap, not a successful production binding. Genuine delivery transport, canonical subscription/owner evidence, 420Mail service-to-service credentials, operational multi-instance store and independent testnet acceptance must be qualified before actual notification delivery.
