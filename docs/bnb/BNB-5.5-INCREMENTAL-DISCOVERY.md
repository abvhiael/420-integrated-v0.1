Existing safe_feed filtered each property's local revision as though it were a global cursor, ordered by timestamps and kept only latest state. Changes to other properties with equal/lower revisions could disappear; equal timestamps, interleaved commits and tombstones had no complete resumable history. No bounded authorized reset protocol existed.

Append-only migration 029 introduces a commit-ordered global journal and clock/epoch, per-property revision uniqueness and expiring scoped resync sessions. The clock uses a transactional row lock, not a nontransactional sequence; a higher cursor cannot commit while an earlier position is uncommitted. Rollback advances neither committed clock nor journal. Upgrade seeds existing current revisions in deterministic property order without inventing historical transitions or downstream receipts. Projection changes and deletion tombstones append in the same transaction. Recreating a deleted projection continues from its durable history revision. Identical synchronizations and metadata-only timestamp updates create no duplicate change.

The journal/clock are SELECT-only for the production runtime role. A fixed, owner-bound SECURITY DEFINER trigger with pg_catalog/public/pg_temp search path performs only the necessary clock/journal append. It does not grant arbitrary SQL/DDL or external authority. Production verification rejects journal write privilege drift. Resync rows allow runtime SELECT/INSERT only, preventing reset/expiry/ownership edits by the ordinary service role.

discovery_feed.page returns bounded items, epoch, global next_cursor, captured high_watermark and has_more. Reusing until/epoch gives stable pagination independent of timestamps and subsequent commits. Pages emit at most 50 items; a requested catch-up range over 10,000 positions requires authorized resync. Future/malformed cursors and epoch mismatches fail closed. Empty pages do not skip an uncommitted prefix. Compatibility safe_feed still returns a list, but after is explicitly a global cursor; clients must not reinterpret old per-property revisions as global cursors.

Resync creation requires independently established consumer/actor authority. A durable scoped request key is idempotent and binds a 15-minute session to clock epoch and committed watermark. Pages return latest per-property journal state at that watermark, including UUID-zero and deletion tombstones, in bounded property order. Authorization is rechecked for every page; wrong consumer/actor, revoked callback, expired session or changed epoch is denied. Final page returns resume_after=watermark so updates committed after the snapshot continue through the ordinary feed. Snapshot pages do not acknowledge delivery or certify a consumer reset.

Feed output revalidates current property/location/compliance/jurisdiction state without taking multi-property writer locks. Historical visible payloads that no longer match current authority become minimized tombstones at the same journal identity/revision. Only allowlisted public/coarse fields are reconstructed; private/unknown journal fields are never exported. source_digest binds immutable original provenance; payload_digest binds the safe returned content. Cursor identity is stable; safety-driven redaction may change content on replay after authority changes. Consumer admission retains the current-authority check and stale-revision precedence.

Signed internal HTTP feed/resync routes require the existing BNB_DISCOVERY_CONSUMER issuer adapter, exact consumer/request scope and independently verified active grant claims. There is no public feed/reset or approval boolean. Tests use actual RS256 fixture signatures. Production discovery-issuer credential binding and actual consumer transports remain BNB-5.6 and existing external acceptance gates; absent bindings fail closed. No issuer is minted or configured for live use here.
