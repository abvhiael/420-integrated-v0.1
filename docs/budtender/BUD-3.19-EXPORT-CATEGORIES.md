# Budtender 3.19 — Functional asset export categories

Canonical export prefixes: `env_` environment, `fixture_` fixture, `prop_` prop, `plant_` plant, `sign_` signage, `light_` lighting, `decal_` decal. These seven functional classes are distinct from Phase 3.18 z-order layers and do not change presentation priority.

The deterministic export catalog `assets/budtender/phase-3.19/export_catalog.json` records one destination export filename and source identity for each of the 368 original production assets, 48 Phase 3.16 hotspot assets and 48 Phase 3.17 environment-state assets (464 total (including 48 separate Phase 3.16 hotspot cutouts)). Source files and the registered runtime URLs are **not renamed or rewritten**. Exporters must resolve the catalog's `source` to `export_name`; the catalog is a naming/packaging contract, not a claim that separate exported image copies have been generated. Basenames retain recognizable source descriptors, with phase-qualified suffixes where names would collide.

Functional categorization uses asset use (not creation phase). Fixture includes fitted counters/shelving, prop includes merchandise and loose accessories, plant includes botanical decorations, sign includes store/queue menu labels, light includes luminaires/effects, decal includes surface markers, overlays and Phase 3.16 hotspot indicator artwork, env includes architecture/scenery and Phase 3.17 full environment-state images. The source hash and byte length are immutable references; the export manifest verifier rejects omissions, duplicates, invalid prefixes, unsafe paths and changed identities. No gameplay state or original approved image bytes are modified.

**Scope:** Level 1, asset export contract and verification only. Neither this step nor the manifest makes a testnet or production-release claim.
