# BUD-CHAR-01 — Customer and staff character production and animation

**Status:** planned/in progress; 01.1 is first active substep. **Qualification:** scoped Level 1 per substep, retained character-system Level 2 at 01.14, global Level 3 only at a separately approved phase closeout. **Baseline:** qualified Budtender 3.18 scene layering, 3.19 seven-prefix export naming, and 3.20 storefront composition. Do not silently extend the Phase 3.19 export prefixes: character paths are internal until a separate explicit migration qualifies customer_/staff_.

## Canonical implementation sequence

| Step | Scope | Exit criterion |
|---|---|---|
| BUD-CHAR-01.1 | Character art direction and production standards | Approved measurable style specification, perspective, proportions, palette, expression, garments, pivots, frame timing, scaling and transparency rules |
| BUD-CHAR-01.2 | Nine-character MVP roster | Three distinct staff and six distinct adult customer base sheets with stable IDs |
| BUD-CHAR-01.3 | Facial expressions | Neutral, curious, happy, impatient and disappointed for all nine (45 variants) |
| BUD-CHAR-01.4 | Clothing variants | Two complete outfit variants per character (18 combinations) |
| BUD-CHAR-01.5 | Animation production | idle_front, idle_left, idle_right, walk_left, walk_right, approach_counter, waiting, browse, purchase_complete, exit; role-applicable staff actions with documented timing/frames |
| BUD-CHAR-01.6 | Asset registry and export compatibility | Immutable identities, registered frames, dimensions, digests, collision-free paths; no unapproved Phase 3.19 prefix changes |
| BUD-CHAR-01.7 | Customer visual runtime | Idempotent rendering of authoritative queue, approach, purchase and departure events with refresh/replay safety |
| BUD-CHAR-01.8 | Staff visual runtime | Staff sprites track only actual supported staff state, without invented assignments or financial authority |
| BUD-CHAR-01.9 | Expression and behavior mapping | Deterministic, nonflickering presentation from validated authoritative events |
| BUD-CHAR-01.10 | Clothing selection | Registered outfits, stable anchors, safe fallback and no economic effects |
| BUD-CHAR-01.11 | Scene placement and occlusion | Canonical 09_CUSTOMERS and 10_STAFF tiers, valid positions, queues, viewport and overlaps |
| BUD-CHAR-01.12 | Animation runtime and performance | Bounded frame timing, caching, pause/visibility/reduced motion, desktop/mobile rendering |
| BUD-CHAR-01.13 | Interaction and accessibility | Existing authorized interactions, touch and keyboard support, accessible status and focus |
| BUD-CHAR-01.14 | Character-system Level 2 milestone | Retained integration, lifecycle, identity, asset, accessibility, performance, browser smoke, security and regression suite passes at exact SHA |

**Invariants:** characters are presentation only; all customers depicted are adults; visual demographic traits must not change gameplay behavior. Source artwork and previous qualified asset paths remain intact. No autogenerated placeholder is production artwork. Each substep requires exact-SHA Level 1 evidence and reconciliation with current main before an authorized merge; do not run global Level 3 qualification at ordinary substeps. The milestone requires successful Level 2 evidence, not simulated acceptance.
