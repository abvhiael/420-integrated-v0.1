# C02.3 — Durable source snapshots and quarantine

**Status:** Repository-level local durable archive implementation; no running source collector or production-grade multi-instance store. The Go `services/complianceauth/snapshot.go` archive writes original snapshot bytes and a separate metadata record using exclusive-create file permissions. Records preserve SHA-256, content type, retrieval time, parser version, citation locators, a prior-snapshot digest and `PARSED_PENDING_REVIEW` or `QUARANTINED` status. Re-reading history verifies the raw content against its stored hash. Duplicate names cannot replace committed evidence.

**Quarantine:** Missing/parser errors, empty extraction, missing parser version or citation anchors, and invalid anchor fields generate durable quarantine metadata rather than legal permission. A failed parser never publishes an active policy. Paths are restricted to canonical source identifiers to prevent traversal. Unarchivable and 304/no-body responses are rejected at the archive boundary.

**Trust:** `DocumentParser` is a deliberately isolated interface; hostile HTML/PDF parsing must run with appropriate sandbox/resource limits before deployment. The tests exercise a deterministic fixture parser, not a complete production PDF extraction engine. No AI inference or source content is allowed to activate policy. Initial local-file durability is not a substitute for the C07 transactional multi-instance database/object-store design or C09 deployed acceptance. Operational archival permission and retention must be separately approved.

**Level 1 acceptance:** immutable creation, history ordering and previous digests, parser/version/citation provenance, explicit quarantine for corrupt/unparseable data, source-ID validation, and tamper detection on read. Level 2 at C02.10; Level 3 at C08.5.
