# C02.9 — Evidence export and source retention boundaries

Canonical requirement: **Evidence export and source retention controls; support permitted archival limits, publisher terms and reviewer-only access where needed.**

`services/complianceauth/evidence_export.go` provides a fail-closed boundary for exporting *previously archived* source bytes with integrity verification. A request is granted only when the source identities agree, the stored record is `PARSED_PENDING_REVIEW`, the raw bytes verify against its recorded SHA-256 digest, archival and export are both affirmatively permitted, publisher terms have a recorded reference, a positive export size limit is met, and the publisher permission has not expired. Requests require an authenticated actor; sources flagged reviewer-only additionally require explicit reviewer authorization. Exported bytes are copied to prevent mutation of the underlying evidence, and exports never authorize legal policy.

**Terms and archival scope.** The permission objects are independently supplied records, **not** official publisher grants established by the repository. Production connectors must independently verify publisher terms, retention deadlines, and document access classification before constructing them. An archived source may require later deletion or restricted use under terms; this implementation does not purport to implement legal-hold reconciliation, secure distributed deletion, licensing negotiations, access-credential issuance or deployed object-store lifecycle policies. These must be accepted alongside deployed archival infrastructure during C07/C09 and independent production approval. No public download endpoint is exposed.

**Security.** Deny unapproved archive/export; missing publisher terms; expired permission; unauthenticated or non-reviewer actors for reviewer-only content; source mismatch; tampered bytes; oversized content; quarantined records. Retained Compliance suites and dedicated Go race checks qualify this local enforcement. Reviewer identity and policy grants must originate from trusted external issuers, not arbitrary request input. Level 2 milestone: C02.10. Level 3: C08.5.
