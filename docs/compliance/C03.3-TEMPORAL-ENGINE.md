# C03.3 — Bitemporal legal applicability and local clock windows

The Go `EvaluateTemporalApplicability` engine separates **legal effective time** (`At`) from **knowledge time** (`KnowledgeAt`), retaining an ordered, immutable evidence history. It evaluates the most recent version known at the knowledge instant; later corrections must not silently revise historical determinations. Each version carries verified-format SHA-256 source evidence, its recording time, scheduled commencement, end-of-validity and repeal boundaries.

Local operating hours use an IANA timezone and actual UTC instants; DST gap/overlap transitions are resolved by conversion from the absolute event timestamp, not by guessing local clock instants. Overnight intervals span midnight. Start time is inclusive, end time exclusive; repeal and expiration are exclusive end instants. Missing evidence, malformed or repeated knowledge-time records, invalid interval, unsupported timezone or ambiguous hour windows fail closed.

All outcomes are applicability evidence only: `TEMPORALLY_APPLICABLE_REVIEW_REQUIRED`, `OUTSIDE_LOCAL_HOURS`, `NOT_OPERATIVE`, or `REVIEW_REQUIRED`. None grants policy authorization. Official legal commencement, source provenance, trusted time input and legal review remain separate externally authenticated gates. Level 1 covers DST spring/fall, overnight, repeal, future commencement, historical knowledge, boundary and adversarial tests; Level 2 deferred to the C03 integration milestone, Level 3 to C08.5.
