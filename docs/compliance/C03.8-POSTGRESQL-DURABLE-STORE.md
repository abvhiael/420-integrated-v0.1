# C03.8 — Durable PostgreSQL publication store

## Implementation

`services/complianceauth/publication_postgres.go` implements `PublicationStore` using PostgreSQL and the repository's existing `github.com/lib/pq` dependency. Its dedicated relational table stores the publication scope, strictly increasing sequence, revocation epoch, policy digest, dependency digest and expiry. `CompareAndSwap` uses a single conditional `UPDATE` against **all** predecessor fields on the shared primary; PostgreSQL row locking ensures competing writers cannot both publish from the same old state. `Bootstrap` uses `INSERT ... ON CONFLICT DO NOTHING` and never replaces existing authority state.

`PublicationCache.ReadCurrent` already checks the authoritative store on every evaluation. All instances must use the same writable primary (or an equivalently linearizable routing layer): replicas with lag are not valid authorization reads. Missing rows, invalid publication state, connection errors, stale dependencies and revocation changes fail closed.

## Setup

Apply `PublicationSchemaSQL` using the controlled migration process, or invoke `(*PostgreSQLPublicationStore).Migrate(ctx)` from a privileged deployment operator; production runtime credentials should not have DDL permissions. Configure a PostgreSQL DSN with TLS certificate verification (`sslmode=verify-full`), a narrowly scoped user and managed credentials. Call `OpenPostgreSQLPublicationStore(dsn)` and inject the resulting store into `PublicationCache.ReadCurrent` and `AdvancePublication`; do not use `MemoryPublicationStore` outside tests. Allow only approved publishers to invoke `Bootstrap` or `CompareAndSwap`; the adapter does not authenticate the publisher by itself.

## Qualification

The scoped GitHub Actions job starts PostgreSQL 16 and runs `TestC038PostgreSQLMultiInstance` with `COMPLIANCE_POSTGRES_TEST_DSN`; two independent SQL connection pools compete with 32 simultaneous CAS calls. Exactly one wins. Two caches reject old publication state after revocation/dependency change. The retained Compliance Go security, race and regressions also run. Missing `COMPLIANCE_POSTGRES_TEST_DSN` skips the dedicated database test locally; it is mandatory in CI.

## Operational acceptance still required

This supplies a **durable, multi-connection datastore implementation**, not a deployed production cluster. Verify network/TLS, secrets, least-privilege SQL grants, migration rollback, backup/restore, failover with no stale secondary reads, connection saturation, monitoring, publisher authentication and the decision-service wiring in the actual production environment. Do not claim externally trusted legal authorization merely from successful data-store tests.
