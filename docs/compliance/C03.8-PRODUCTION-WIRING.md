# Compliance C03.8 — Production publication authority deployment

Production entry point: `OpenProductionPublicationRuntime(ctx,dsn,independentAuthority)`. A non-nil `IndependentPublicationAuthority` must authenticate the *independent* legal reviewer/publisher's authorization **for each** old-to-new publication. This repository has no accepted regulator signing credentials or verified government API; deployment MUST reject publication until a separately authorized implementation is connected. The function does not fabricate approval.

DSNs require PostgreSQL URL credentials, `sslmode=verify-full`, an existing `sslrootcert` and `connect_timeout`. Pass the DSN from a mounted secret provider or environment-injected secret; never commit passwords. Initialize production with an authorized primary only; all subsequent loads/CAS/bootstraps also reject PostgreSQL hot standbys using `pg_is_in_recovery()`. Every cached read contacts the primary and fails closed during outages. The runtime has no memory fallback.

Apply `services/complianceauth/migrations/0001_publication_fences.sql` **as an operator** within a controlled transaction before starting service. Provision separate database login accounts with least-privilege inherited membership in `compliance_reader` (SELECT only) and `compliance_publisher` (SELECT, INSERT, UPDATE). Login identities, passwords, certificates and legal publishing keys must be externally provisioned. Revoke CREATE/DDL from runtime roles and do not call `Migrate` with runtime credentials. Database grants alone do not provide legal authorization; only authorized runtime publishing paths may receive publisher credentials.

CI starts PostgreSQL 16 and checks two independent pools, atomic 32-way CAS, stale-cache invalidation, TLS DSN validation, absent independent approval, connection interruption, and durable reconnect. This is a **controlled connection-outage simulation**, not infrastructure HA/failover acceptance. Real primary promotion, split-brain fencing, connection routing, backup/restore and TLS certificate rotation must be tested on deployed infrastructure. Failure of independent approval or authoritative database always blocks publication.
