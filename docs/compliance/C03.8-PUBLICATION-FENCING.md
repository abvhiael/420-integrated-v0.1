# C03.8 — Cache invalidation and monotonic publication fences

The `PublicationFence` binds legal scope, strictly increasing publication sequence, nondecreasing revocation epoch, reviewed policy digest, dependency digest and expiry. `AdvancePublication` requires a strongly consistent, linearizable shared `PublicationStore` with atomic compare-and-swap; rollbacks, repeated publications, expired entries and storage failures are denied. `PublicationCache.ReadCurrent` validates the *authoritative shared store on every use*; stale local entries never confer permission and dependency changes fail closed. Explicit invalidation clears local caches.

Tests model two serving cache instances against one concurrency-safe fixture and run competing publication CAS operations to ensure a single winning update. The fixture store is **not** a durable multi-process implementation, and this milestone must not be represented as proven production cluster safety. A real deployment requires an authenticated strongly consistent transactional datastore, external verified publication authority, failover testing, and revocation distribution acceptance. Cache results themselves do not issue policy authorization. C03.8 Level 1 is the affected Go race and app checks; C03 Level 2 at milestone and global Level 3 at C08.5.
