# C04.8 — Scheduled signing, key rotation and scoped emergency shutdown

The app implements a managed-signing boundary (`ManagedManifestSigner`) which accepts a KMS/HSM key identifier and canonical manifest bytes but never obtains a private key. Signed manifests bind policy/review digests, environment, audience, domain, jurisdiction, effective window, key ID, sequence and monotonic revocation epoch. `PublicationControl` verifies key scope/validity, rejects premature scheduling and expired approval, requires Ed25519 verification after external signing, and rechecks key compromise/halt after signing to prevent an in-flight signer race.

Newly registered scoped keys allow controlled rotation without overwriting existing key IDs. A compromise irreversibly marks the key in the in-process control and advances its incident epoch, invalidating earlier signed manifests. `EmergencyHalt` advances the epoch and stops a scoped environment/domain/jurisdiction; it cannot remove a stop or create approval. The normal signed independent legal publisher, durable publication fence and downstream policy/consumer authorization checks remain required.

**Qualification caveat:** In-process control maps are **not** durable, distributed incident state. Production use must persist/reconcile epoch and halt authority across all instances (prefer PostgreSQL monotonic CAS and authenticated operator audit), use real managed non-exportable signing keys and independently authenticated incident operators; no live KMS/HSM, testnet signer or production key ceremony is provisioned by source/test fixtures. The gate cannot be advertised as end-to-end live publication authorization until these external and durable integrations pass.

**Exact-SHA software tests:** `TestC048ScheduledSigningRotationAndEmergency` and retained Compliance Go security/race and publication-fence tests. Negative cases cover premature activation, scope/environment crossovers, signer outage, duplicate key, rotation, compromised former key, epoch invalidation, scoped halt and a halt racing with signing.

**Canonical handoff:** C09.1 provision isolated testnet key/trust; C09.4 exercise deployed signing, multi-instance monotonic epoch, managed rotation and compromised-key recovery; C09.7 incident/halt/replay adversarial acceptance; C10.3 production managed key ceremony and operator identity; C10.7 release signoff. C08.5 retains phase Level 3.
