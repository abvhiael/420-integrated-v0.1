# C05.1 — Versioned Compliance v1 HTTP interfaces and SDK

Canonical C05.1 supplies `POST /api/v1/evaluate` (authenticated), `GET /api/v1/guidance?region=...` (public) and `GET /api/v1/policies/status?scope=...` (public), plus a Go SDK with evaluation, guidance and policy status methods. Version v1 is explicit; unrecognized versions return 404 and non-supported methods return 405. JSON responses are non-cacheable, reject MIME sniffing and provide no individual/private evidence in public guidance/status.

Evaluation requires a Bearer token, a separately injected `C051Authenticator` with tenant-scoped authority, strict JSON schema (unknown fields rejected), 16KiB body bound, valid digests and bounded IDs. The evaluation implementation is *injected* via `C051Backend`; no test fixture or HTTP transport grants a legal approval. Backend outages fail closed; downstream stage-bound receipts and current legal policy remain independent authorization requirements. Public collection reads have explicit scope/region, limit 1–50, bounded offset and strict query validation. No unconstrained enumeration endpoints.

The client rejects non-HTTPS BaseURLs and validates response semantics, without storing signing keys. The SDK v1 shape is intentionally additive; incompatible request/response field changes or v2 routes require independent versioned adoption. Tests: `TestC051VersionedAPIAndSDKSecurity` under Go race and retained app tests.

**Production/testnet limitations:** Injecting a mock authenticator and read-only backend is not actual service wiring, real OAuth/service identity, durable rate limiting, regional policy source approval or deployed SDK adoption. C05.2 handles actual configured Identity/Verify/Registry adapters; C09.5 integrated authenticated discovery/issuer and C09.7 outage/revocation tests; C10.6 deployed consumer acceptance. Do not mark these as completed by an HTTP fixture. Level 2 is C05.12; Level 3 C08.5.
