# C05.2 — Identity, Verify and Registry provider boundaries

Canonical step: Identity/Verify/Registry adapters with real configured provider boundaries, revocation, private evidence references and fail-closed errors.

`CredentialProviderHTTP` requires an explicitly supplied HTTPS origin, named provider, pinned issuer and audience, bounded request timeout, caller-owned token source and TLS-configured client. No URL from a request, discovery result or credential response can redirect the provider: redirects are blocked, transport must have TLS verification enabled, and custom proxy/dial bypasses are disallowed. JSON responses must have strict schema, a 16 KiB bound, matching tenant and subject, matching issuer/audience, nonexpired active records, nonrevoked status and private evidence reference/digest. Failures return no credential.

`CredentialTriplet` requires three separately named Identity, Verify and Registry authorities. Each result must satisfy the same tenant/subject and preserve private evidence references only within the trusted adapter return value; public C05.1 guidance/status APIs do not expose them. An evidence digest binds the three provider results.

**Qualification:** `TestC052ProviderBoundariesRevocationAndPrivacy` uses a real TLS HTTP test server with a pinned private test trust root, strict transport and negative tests for issuer mismatch, revoked evidence, token outage, missing TLS transport, insecure origin, path injection and timeout. Retained Go race and Compliance security regressions run at exact SHA.

**Limitations:** A local TLS provider fixture does not establish real provider credentials, canonical issuer signing, authoritative revocation freshness, or production network identity. Production integration must use independent approved Identity/Verify/Registry issuer contracts and trusted token issuance, controlled secret management, service identity/transport mutual-auth where required, issuer key rotation, durable revocation state and outage drills. No public client should receive the private evidence references. C09.5/C09.7 and C10.3/C10.6 own deployed acceptance; C05.12 Level 2 and C08.5 Level 3 remain unchanged.
