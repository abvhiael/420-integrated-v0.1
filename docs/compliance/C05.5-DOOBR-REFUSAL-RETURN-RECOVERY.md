# C05.5 — DOOBr refusal/return and in-flight policy-change recovery

The canonical C05.5 gate is `RecoverDOOBrOrder`, a **separately reviewed safety authorization** independent of the C05.4 sales-stage authority. It supports refusal, securing goods, and return to origin. A revoked or halted sale cannot suppress legitimate recovery; recovery cannot resume acceptance, dispatch, payment or handover.

The interface requires a previously bound tenant/order, revision, actor, idempotency key, fresh facts digest, old receipt digest and current policy digest. Policy-change recovery refuses stale old/new digest pairs or orders without a halt; previously bound receipt information remains intact. Independently authenticated `DOOBrRecoveryAuthority.VerifySafetyAction` controls the safety workflow, while `DOOBrRecoveryStore.CompareAndSwapRecovery` enforces one monotonic revision and a durable record. Unsafe phase jumps, terminal returns, context cancellation, missing evidence, replays, backend failures, and concurrent conflicting updates fail closed.

The stage matrix is IN_TRANSIT or AT_DOOR → REFUSED or SECURED → RETURNED; IN_TRANSIT can be SECURED before return where safe. Terminal RETURNED cannot restart. These are *state-transition safeguards*, not legally approved instructions on what a driver should physically do.
