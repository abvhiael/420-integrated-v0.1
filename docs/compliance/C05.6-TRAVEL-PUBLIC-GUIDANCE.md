# C05.6 — Sourced public Travel policy guidance

Canonical step: **Travel sourced guidance, coverage status, last review date, policy version and deep link; no embedded DOOBr checkout or private courier data.**

The new `TravelGuidanceAdapter` reads a current public-safe policy publication through `TravelGuidanceSource`; it does not create an independent legal determination. The public projection contains only region, domain, coverage status (REVIEWED / PARTIAL / UNKNOWN), last reviewed date, policy version/digest, allowlisted public guidance text (derived from source message codes) and HTTPS deep link to a configured Travel policy host. Its explicit `LegalAuthorization` is always false. This adapter is not a shop, payment processor, checkout or courier availability API.

The publication must match the requested region and domain; include policy, source and review digests and a review date; be internally time-consistent; and use a configured fixed HTTPS host and `/travel/policy/` path. Expired or not-yet-effective publications degrade to UNKNOWN rather than showing reviewed coverage. Missing authority, invalid metadata, malformed/unsafe links or unrecognized source message codes fail closed with UNKNOWN, never legal permission. No private address, courier identity, recipient or DOOBr checkout fields exist in its JSON projection.

**Level 1 retained test**: `TestC056TravelSourcedPublicGuidance` tests reviewed and stale coverage, policy revision/review metadata, crossing jurisdiction/domain, missing approval digests, unsafe redirects/link hosts, embedded checkout references, disguised private and unapproved free-form summaries and provider outages under Go race. Retain prior C04.7 travel authority, C05.1 API and C05.3 Maps regression gates.

**Integration boundaries:** This is a service-side adapter and public data contract, not a deployed Travel UI or source-backed publication registry. C09.3 official legal-source ingestion, C09.5 trusted providers, C09.8 deployed Travel consumer/deep link and C09.9 independent current-law approval remain external; C10.6 production Travel privacy and UI acceptance remains outstanding. Do not treat a policy fixture as genuine reviewed legal coverage. C05.7 separately combines provider supply with policy visibility; it is not part of C05.6.

**Qualification:** Level 1 exact-SHA app workflow only. Next Level 2 C05.12; Level 3 C08.5.
