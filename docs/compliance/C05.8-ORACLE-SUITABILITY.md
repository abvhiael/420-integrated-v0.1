# C05.8 — 420Oracle suitability decision and reporting-only integration boundary

## Canonical disposition: REVIEW COMPLETE — NO ORACLE ADAPTER REQUIRED

Canonical roadmap: **C05.8 — Oracle integration suitability review and narrowly scoped adapter where required; preserve canonical runtime ABI and reporting-only authority. Off-chain source monitoring need not become an oracle feed.**

Reviewed repository authorities: `docs/apps/oracle/index.md`, `contracts/src/interfaces/IOracle420.sol`, `contracts/src/interfaces/IOracleSourceAdapter420.sol`, `contracts/src/interfaces/genesis/IOracle420.sol`, `docs/compliance/420COMPLIANCE-ROADMAP.md`, existing Compliance policy source/change, independent legal-review and publication boundaries, and the current C05.1–C05.7 consumers.

### API, ABI and security invariant

The canonical **runtime** interface is `contracts/src/interfaces/IOracle420.sol`, whose read methods are `readNumeric(bytes32)` and `readResult(bytes32)`. The frozen Genesis `contracts/src/interfaces/genesis/IOracle420.sol` has a different older `price/isFresh/isSafe` ABI and **must not be silently substituted**. Runtime router discovery uses Registry service `420/service/oracle/v1`; no fixed Genesis Oracle address may be invented.

No Compliance-specific source adapter, feed registry entry, Solidity contract, immutable chain publication or service call is justified by the currently implemented C05 requirements. Adding one now would create a redundant authority channel and could incorrectly elevate an unreviewed observation to a legal eligibility decision. Existing `IOracleSourceAdapter420` is read-only; Oracle operators have **reporting-only authority**—never consent, publishing, custody, payments, role grants, revocation overrides or legal approval.

If a later documented requirement proves an on-chain oracle feed necessary, independently qualify that limited adapter, its input authorization, freshness/quorum/epoch/risk policy, runtime ABI, Registry identity, outage/replay cases and reporting-only authorization without changing Compliance's legal approval model. Such work requires explicit new evidence and the live deployment/partner testnet boundary at C09.5; it is **not** implicitly approved by C05.8.

### Level 1 exit criteria and verification

1. Canonical Oracle runtime/frozen ABI and their incompatibility inventoried.
2. Each current Compliance source/consumer use case routed to the existing off-chain or independent provider authority; no unsupported Oracle addition.
3. Reviewed negative decision explicitly bars oracle observations from legal approvals and identity/credential revocations.
4. A narrowly scoped static verifier checks the canonical interface method inventory, interface separation, service ID, and this recorded determination against the exact implementation SHA; existing app-specific Compliance qualification continues to run.

No Level 2 milestone is due until C05.12. Full Solidity, Genesis/address and global qualification remain C08.5. Live optional integration and independently authenticated evidence remain C09/C10 dependencies.
