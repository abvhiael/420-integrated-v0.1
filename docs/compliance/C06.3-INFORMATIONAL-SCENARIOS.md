# C06.3 — Plain-language guidance and interactive informational scenarios; do not claim eligibility without authenticated evidence or obscure unresolved requirements

Level 1 ordinary website step. Level 2 remains C06.9; Level 3 remains C08.5. Next canonical step: **C06.4 — Private author workspace with cited text, structured rule editing and version comparisons.**

## Gap analysis and implementation

C06.2 had source discovery, publication/date/history states and jurisdiction/topic routes, but no plain-language explanation or interactive scenario. This step adds scenarios.html, a local deterministic explanation model and a DOM controller, linked from the overview and all generated browser pages.

| Canonical criterion | Implementation and exit check |
| --- | --- |
| Plain-language guidance | Definitions of source discovery, coverage, effective dates, authenticated evidence and stage-specific evaluation; topic explanations for product, delivery, business permissions and travel. No current-law rule or numeric legal threshold is invented. |
| Interactive informational scenarios | Five closed hypothetical selectors: broad region, topic, role, stage and evidence claim. Changes update guidance, unresolved requirements and existing source-discovery links. Reset restores safe defaults and keyboard focus. |
| No eligibility claim without authenticated evidence | Every model response explicitly sets eligibility_assessed and legal_authorization false. Public evidence claims are never authenticated, used as a receipt or treated as a satisfied prerequisite. No evaluation endpoint, credentials or signing authority are called. |
| Do not obscure unresolved requirements | All responses retain source freshness, unpublished policy, authority applicability, licence/site, credential and operation/stage gaps. Role/stage/region/evidence-specific questions add to these gaps. No green eligibility badge, hidden checklist or positive decision is produced. |

Carrier explanations distinguish retailer employees, common carriers and independent couriers. Pickup/dispatch, handover, refusal/return and boundary crossing have separate questions. Travel guidance separates policy coverage, permission and supply. Unsupported regions have no fabricated local source links. Source discovery links retain C06.2 status and citations; they never become legal approvals.

## Failure and privacy behaviour

No names, addresses, licence IDs, birth dates, orders, free-text facts or credentials are accepted. The model rejects extra/private fields and unknown selections. Browser controls use broad allowlisted values only; they neither send nor persist data. No fetch, storage, cookies, URL query reading, checkout or third-party scripts are introduced. Content Security Policy disallows network connections, inline code and form submission. Rendering uses textContent and allowlisted relative rule-page links.

Controls start disabled and enable only when the model successfully renders. Missing/failed/invalid model results disable controls and show a visible unavailable state with unresolved requirements. With JavaScript disabled, plain-language guidance, unresolved requirements and source-browser links remain present alongside an explicit interaction limitation.
