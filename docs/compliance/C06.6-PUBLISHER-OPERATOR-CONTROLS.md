# C06.6 — Publisher/operator controls

Canonical requirements: scheduled release, restrictive halt, key status, source health and affected-app status. This is the ordinary C06 Level 1 step, not C06.9 Level 2 or C08.5 Level 3.

## Implemented
- `C066Operations`: independently verified operator session, scoped status aggregation, restrictive halt, and an exact-sequence, independently signed scheduled-publication boundary.
- Private, no-store, TLS-only browser assets and endpoints for scoped status and production halt. Browser release is explicitly forbidden.
- Existing C04.8 signing, C03.8 durable CAS publication and independently verified publication authorization remain mandatory.
- C06.6 focused Go negative tests, race/vet and private JavaScript syntax step in Compliance Level 1 workflow.
- No private signing keys are returned to browsers. Source-collection health does not extend legal review.

## Security/production conditions **not established by current C06.6 app implementation**
- `PublicationControl` uses an in-memory halt/key map and is **not a cross-instance durable incident fence**. Production multi-instance halt propagation, signed state replay and durable operator events must be independently implemented and tested before this endpoint can be treated as a reliable production-wide halt. Do not deploy or authorize actual publication on this basis.
- Genuine operator session/CSRF authority, real source and affected-app monitoring adapters, KMS key provider, audited publication scheduler, staging and deployment are externally supplied boundaries. The existing private HTTP handler is not proof of deployment or live legal authorization.
- Scheduled publication service still needs a durable scheduler/job queue and a post-sign/pre-publication incident-fence recheck tied to the authoritative multi-instance state.
- No real browser accessibility acceptance (C06.8), website/client Level 2 (C06.9) or full phase Level 3 (C08.5) is claimed.
- C06.5 durable evidence file remains absent at this audit HEAD; the earlier successful CI run cannot substitute for that evidence record.
