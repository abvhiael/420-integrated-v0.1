# C06.8 — Mobile consumption, accessibility, responsive browser and session/device revocation

Canonical definition: **App SDK/mobile consumption tests, browser accessibility, keyboard/screen reader, responsive layouts and session/device revocation. A separate native Compliance app is not initially required.**

## Current implementation
- `C068DeviceGate` enforces independently verified, app-audience-bound and device-bound sessions with tenant/domain/jurisdiction scope. No locally cached positive authorization can substitute for revalidation immediately before sensitive use.
- `TestC068MobileDeviceSessionRevocationAndBoundary` tests role/device/audience crossover, expiry, issuer unavailability, cancellation, revocation and session rotation.
- `scripts/verify-compliance-c06-8.py` validates baseline semantic browser document structure, landmarks, viewport declarations, focus style and live feedback without treating static inspection as a substitute for real assistive-technology acceptance.
- C06.8 Level 1 CI executes the focused checks against the exact candidate SHA.
- Existing C06.4 author, C06.5 reviewer and C06.6 operator browser surfaces are retained.

## Outstanding step-specific acceptance (not deferred as automatic success)
- Browser automation across public information pages and authenticated author/reviewer/operator flows at narrow mobile and desktop widths, including overflow, focus order, keyboard-only entry and error recovery.
- Actual screen-reader output, labels, instructions, status messages and dynamic content behavior, including changed/expired/revoked private sessions.
- End-to-end SDK/mobile application consumption using the actual DOOBr/420Travel clients and current C05 policy boundary; verify DENY/UNKNOWN/REVIEW_REQUIRED remain blocking.
- Real external identity/device provider wiring and cross-instance revocation propagation; in-memory mock tests do not qualify production device revocation.
- Current C06.6 multi-instance halt durability and earlier evidence closeouts remain separately unresolved.

**Status:** IN PROGRESS; C06.8 is not complete until these acceptance conditions and exact-SHA Level 1 CI are satisfied. No separate native Compliance mobile app was introduced.

C06.9 is the canonical website/client Level 2 milestone. C08.5 is the complete phase Level 3. PR #602 stays open and unmerged.

## C06.8 additional repository implementation and testnet disposition

The C06.8 consumer gateway rejects non-ALLOW outcomes, missing evidence digests, audience mismatch and revocation during evaluation. Browser automation now runs real Chromium at 320/375/768/1280px, exercises keyboard focus and validates the exposed accessibility tree (heading/main/control semantics); this does not claim NVDA/VoiceOver manual acceptance. An independently owned remote identity introspection adapter fails closed on issuer outage or revocation. The provider must still be wired to actual deployed issuer credentials under the C09/C10 release gates. See [C06.8 external acceptance/testnet ledger](C06.8-TESTNET-ACCEPTANCE-HANDOFF.md) for exact deferrals, owners, required proof and no-ALLOW rule. These tests must PASS at one exact SHA before any C06.8 repository-level qualification record is marked passed.
