# C07.1 — Production database schema and protected storage

Canonical requirement: production database schema, migrations, encryption, tenant isolation, indexing and storage limits. This is an ordinary **Level 1** step. Step IDs, C07.10/C08.5 boundaries and PR #602's open/draft/unmerged disposition are unchanged.

## Gap analysis and individual exit criteria

Existing C03.8/C06.4/C06.5/C06.7 stores had primary-only reads, scoped queries and transactional concurrency. The gaps were checksummed migrations, database-enforced isolation, encrypted payloads and bounded/indexed storage.

## Production wiring and private data classification

Use OpenC071ProductionStores and its encrypted Drafts, Reviews and Audit stores in existing authenticated services. Independent identity/review/publication/auditor gates remain mandatory; database acceptance grants no legal or operational permission. Nil-cipher stores and OpenPostgreSQLPublicationStore remain legacy **development/test/migration primitives**, not supported private production entry points. The production factory supplies every private store with encryption and provides no plaintext fallback.

Tenant/domain/jurisdiction, actor/case/evidence identifiers, timestamps, state and integrity commitments remain private indexed metadata. Draft rules/cited text, review contents/signatures and auditor-purpose payloads are encrypted. No key material, identity documents, addresses or raw private data are added to public catalogues or chain records. Host-volume and backup encryption must be independently verified at deployment.

## Controlled migration procedure

1. Freeze private writes and verify a recoverable backup. Use a separate schema-administrator connection on the primary; never serve application traffic with migration credentials.
2. Supply active and required historical keys through approved external secret management. Never commit keys/passwords or record them in evidence.
3. Apply MigrateC071Database. The ledger and backfill are transactional. Once adopted in production, migration text is immutable: add a new version rather than editing history.
4. Backfill is bounded to 100,000 rows and 64 MiB input per private table/transaction. Larger or oversized/corrupt archives fail explicitly and require a reviewed migration plan; no records are dropped or silently left plaintext.
5. Provision restricted login credentials externally and BindC071RuntimeRole to one approved scope. The helper creates no credentials and refuses to broaden an existing binding. Require successful production opening before traffic.
6. Quota/migration failure means unavailable. Do not silently retry exports, discard evidence, inflate limits or fall back to plaintext. Runtime history cannot be deleted; capacity accounting is conservative and never silently reclaimed. Retention/deletion and recovery belong to C07.5/C07.6.
