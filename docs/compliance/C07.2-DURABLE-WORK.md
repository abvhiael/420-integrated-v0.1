# C07.2 — Durable concurrency and activation

Canonical requirement: multi-instance concurrency, durable jobs, leader/lease fencing, transactional outbox and idempotent activation. This is an ordinary Level 1 step on audit/420compliance-c01-1-inventory-20261009; PR #602 stays draft, open and unmerged. C07.10 is the operational Level 2 milestone; C08.5 is the single comprehensive closeout after main reconciliation.

## Gap analysis and exit criteria

C03.8 already supplied primary-only publication CAS. C07.1 supplied encrypted private stores, checksummed migrations, database-role isolation and quotas. C05.9 described an outbox contract but had only a memory test fixture. C06.6 operator halt was local to one process. None of those prior passes certified durable worker takeover or atomic publication plus notification fan-out.

| Canonical criterion | Implementation | Mandatory proof |
|---|---|---|
| Multi-instance concurrency | Independent primary connections; per-scope row locks; conditional lease/CAS writes; no memory authorization fallback | Competing workers, independent reader, stale canonical fence denial and concurrent activation |
| Durable jobs | Encrypted immutable COLLECTION and ACTIVATION payloads; idempotency fingerprint; schedule; finite attempts; QUEUED/LEASED/COMPLETE/DEAD states | Enqueue replay/rebinding denial, encrypted rows, collection handler, cancellation, crash recovery and quota failure |
| Leader/lease fencing | Database clock, monotonically increasing owner tokens, bounded leases, heartbeat APIs; leader and job ownership checked before mutation and activation completion | Exactly one leader/claimant in each 16-worker race; expiry, takeover and stale owner denial |
| Transactional outbox | Activation fence, immutable receipt, subscriber fan-out and job completion in one PostgreSQL transaction; standalone event publishing denied | Injected outbox failure rolls back fence/receipt/job; ordered per-subscriber delivery, retry, stale acknowledgement and dead-letter blocking |

## Production composition

Use OpenC072ProductionRuntime with externally supplied encryption keys, restricted certificate-verifying TLS credentials, one fixed tenant/domain/jurisdiction/publication binding and an independent publication authority. It composes the C07.1 stores and a C072Store. The earlier publication opener remains a read/halt-aware runtime and intentionally cannot perform standalone production Publish. Its durable store has no encryption key for queue creation; use the new composition for workers.

MigrateC071Database now appends the independently checksummed sixth migration. Previous migration constants are unchanged. A dedicated administrator applies migrations before serving traffic; runtime roles cannot migrate, edit bindings, own tables, bypass RLS or change historical activation/halt records. BindC071RuntimeRole refuses publication-scope reuse across tenants. All new durable records share C07.1 scope quotas; there is no silent quota reclamation or runtime deletion.

Control scope identifiers now use separately base64url-encoded environment/domain/jurisdiction segments. The former NUL-separated in-memory key was invalid PostgreSQL TEXT. This is an internal scope encoding change, not a policy/schema/address mutation. Provision database bindings and bootstrap fences using controlScope before traffic; never silently rename an existing deployed scope. There is no claimed existing live deployment to migrate.

An independently verified operator may QueueActivation. Queueing confers no permission. A worker acquires the ACTIVATION leader, claims the job, decodes the bound C072Activation, and calls Activate with independently controlled reviewer approval, managed manifest validation and trusted invalidation public key. Every execution/replay revalidates authority. Fence lifetime cannot exceed the signed policy/review lifetime. Successful activation is the only way an activation job completes.

A collection worker acquires COLLECTION leadership and uses RunCollection with its canonical source-ingestion adapter. The bounded handler receives encrypted job intent and persists source snapshots through that adapter; collection never grants review/publication authority. External collection side effects must remain idempotent by job/source identity. RenewLeader and RenewJob are bounded database-clock heartbeats; an expired worker must reacquire/claim, never resurrect an old token.

C072Outbox implements the existing invalidation delivery contract. It issues a 30-second lease with an ownership token, increments attempts on claim (including crashed deliveries), computes retry delays using the database clock and caps attempts at ten. Delivery remains at least once: a crash after external send can duplicate the same stable event ID. Consumers verify the signature and re-read canonical policy; events never grant ALLOW. An unacknowledged dead-letter predecessor blocks later sequences for that subscriber. Approved dead-letter recovery and retention are later operational work, never an implicit skip.

Durable halt is restrictive only; there is no unhalt API. Production runtime reads check the shared halt in the same primary statement as the policy fence. Local PublicationControl remains a managed-signature gate and a fixture primitive; it is not shared durable authority. Operator halt persists before local invalidation. A failed storage read/write is unavailable, never a memory fallback.
