## External broker protocol and production composition

Provision an independently controlled broker implementing POST /v1/secrets and POST /v1/sign. The broker must authenticate the certificate URI, authorize the exact scope/environment/audience/purpose, refuse revoked workloads, protect storage/database/token material and own non-exportable manifest signing keys. The client cannot grant itself these capabilities. Certificates, CA roots, database accounts, broker authorization and signing keys are external deployment inputs, never generated by runtime code or committed in this repository.

NewC073Client owns a private TLS transport with verified hostname/CA and exact URI SAN, bounded timeout, redirect refusal and a certificate-source callback. The callback must obtain the currently valid workload certificate/private authentication key from approved workload identity infrastructure. Each request establishes a fresh TLS connection; no client session cache or keepalive permits an old certificate to survive rotation. Requests contain a fresh nonce. Broker records must match that nonce and configured scope/identity, be current with at most five minutes remaining, and meet an externally provisioned minimum generation. The client keeps only monotonic generation floors, not secret records. Provision/update the minimum floor in reviewed deployment configuration across process restarts; local memory alone is not a distributed revocation authority.

Storage-encryption records contain an active key ID and at most eight AES-256 keys. Credential-token records contain a bounded bearer credential. Database-credential records contain a certificate-verifying DSN for the configured database hostname. Manifest-signing records contain public key status, active key, minimum epoch and a scoped signer credential; no manifest private key field is accepted. Purpose confusion and unexpected JSON fields/trailing/oversized responses fail closed. Plaintext encryption keys exist transiently in process memory to perform AES-GCM; no positive key cache is retained in the managed cipher. Go does not guarantee physical memory zeroization; approved host/process isolation and broker release policy remain deployment requirements.

OpenC073ProductionRuntime composes fresh managed database credentials, a provider-backed C071Cipher, the restricted C07.2 runtime, a live service-identity guard and a PublicationControl using current external public key metadata. Every managed encryption/decryption and durable read/write rechecks authority. Independent reviewer publication authorization remains mandatory; a broker token or manifest signature does not constitute legal approval or ALLOW. Existing direct/static constructors remain explicit fixture/migration primitives; use the managed production composition for the deployed path.

Private draft/review/audit and durable job encryption now carry caller cancellation/deadline into broker access. Managed signing rejects noncanonical, wrong-scope, early/expired or stale-epoch manifests, verifies the returned Ed25519 signature against current public metadata, and re-introspects after the signer returns. PublicationControl also rechecks current external key/epoch status, preserving its restrictive local halt gate and C07.2 durable halt.

Production PostgreSQL DSNs reject duplicate/unknown options, host/service/TLS overrides, replica selection, unbounded connect timeout, incomplete TLS client credentials and broadly readable client key files. Certificate verification and restricted role/primary/RLS/migration checks remain mandatory. Real database credential rotation and connection termination/reprovisioning must be demonstrated under C09 deployment acceptance; a fixture connection does not prove a live infrastructure rotation procedure.
