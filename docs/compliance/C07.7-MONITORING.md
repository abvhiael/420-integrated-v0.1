## Authoritative signal matrix

| Required signal | Repository producer | Unit | Security boundary |
| --- | --- | --- | --- |
| Source freshness | `C077InventoryCollector` over `SourceHealthInput`, using `AssessSourceHealth` | Worst age of last successful authoritative retrieval (seconds); failed sources retained | Missing canonical source inventory, failed collection and expired legal review must not report healthy |
| Review backlog | `C077OperationalCollector` from latest author/review heads and review revisions | Number of drafts without a current independently reviewed candidate | Scope bound through publication/author mapping; a previous revision is not current |
| Decision latency | `C077InstrumentedEvaluator` directly wraps `C051Backend.Evaluate` | Per-evaluation duration seconds (latest observation; **not** a p95 without a histogram) | No user-provided timings |
| Evaluator errors | Same instrumented evaluator | Latest evaluation failure indicator (0/1) | Errors and empty outcomes counted; telemetry outage fails closed |
| Coverage gaps | `C077InventoryCollector` using independent required-vs-current coverage inventory | Expected minus current verified scopes/cases | An unknown or zero expected inventory is invalid, not zero gaps |
| Activation lag | Primary `compliance_durable_jobs` from overdue queued, leased or dead activation jobs | Worst due-to-now lag seconds | Retains overdue/dead work; doesn't rewrite job state |
| Revocation propagation | Primary `compliance_impact_outbox` oldest outstanding delivery by due time | Worst outstanding impact lag seconds | Conservative superset of revocation events; detailed revocation-only event classification requires authenticated consumer integration |
| Consumer acknowledgments | Primary `compliance_impact_outbox` not-acknowledged records | Outstanding acknowledgments count | Counted per durable subscriber/event; no synthetic ACKs |

A single monotonic per-scope, per-signal row is kept in `compliance_monitoring`. Operational sampling reads the primary, never a potentially lagging replica; all records are scope-scoped, count-bound, type-validated, timestamp-monotonic and contain no user/document/reviewer IDs.

## Alerting and targets

`C077Monitor.EvaluateC077` requires an operator-supplied threshold policy per signal (`Warn`, `Critical`, `MaxAge`). Missing limits, absent readings or stale observations result in `UNKNOWN` and **CRITICAL overall**; unknown metrics and nonfinite values are rejected. `C077Run` sends an entire eight-signal snapshot to a trusted alert sink, including green recovery transitions, and sends a separate outage alarm on collection failure. Errors from the alert sink are never reported as successful delivery.

**Numerical limits are not implicitly approved.** They must be selected/approved against risk and actual service capacity before live release per the canonical C07 guidance; the implementation deliberately prevents a fabricated default from certifying healthy service. Current observed signal values and SLA/SLO attestations are not established by local CI.
