# C08.2 — Deployment manifest template and required release fields

Template only: no deployment has been made and `release_enabled` MUST remain false before current independent external acceptance.

```json
{
  "schema": "420compliance-deployment-manifest-template/v1",
  "environment": "testnet",
  "release_enabled": false,
  "implementation_sha": "REQUIRED_EXACT_SHA",
  "application_scope": "REQUIRED_TENANT_DOMAIN_JURISDICTION",
  "policy_digest": "REQUIRED_REVIEWED_DIGEST",
  "review_digest": "REQUIRED_INDEPENDENT_REVIEW_DIGEST",
  "publication_sequence": null,
  "revocation_epoch": null,
  "signing_key_id": "REQUIRED_MANAGED_KEY_REFERENCE_ONLY",
  "tls_workload_identity": "REQUIRED_EXTERNAL_ISSUER_ID",
  "external_recovery_authority": "NOT_CONFIGURED",
  "recovery_generation": null,
  "postgresql_migration_digest": "REQUIRED_SHA256",
  "consumer_acknowledgements": "NOT_VERIFIED",
  "current_legal_approval": "NOT_APPROVED",
  "security_review": "NOT_PERFORMED",
  "rollback_policy": "NO_EPOCH_DOWNGRADE",
  "release_owner_approval": "NOT_APPROVED"
}
```

Provision separate testnet/production workloads and immutable authority outside the recoverable failure domain. Do not place tokens, signing private keys, passwords, government identifiers or raw evidence inside deployment manifests or CI artifacts. All hashes must be checked against exact built/reviewed state and the currently trusted key registry. Publish only after current legal/security/partner/operations signoffs, actual restart/canary/revocation/PITR acceptance, and C08.5 repository phase completion. The template does not alter frozen Genesis addresses and does not create a new signer or chain.
