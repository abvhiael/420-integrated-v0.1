## Preliminary architectural findings

- `AIJobManager` and `AIProviderRegistry` already have AI-specific compatibility objects. ComputeMarket should bind via explicitly authorized adapters, not rename AI objects into general-purpose compute authority.
- `AIJobEscrow` provides an existing *AI-specific* adapter-bound pattern. Its mere existence is not evidence of a ready-to-use CMP funding adapter.
- `VaultRouter420` exposes reads and authorization checks, not the job-specific custody lifecycle needed for CMP. Design cannot assume router funding methods until underlying source and interfaces are inspected.
- The frozen V1 architecture and checked repository layout are consistent with a **specification-first CMP phase**, but a complete repository-wide statement of source absence, production status or deployability is not yet supported.

This file records only source-grounded findings from the stated commit; outstanding items are deliberate qualification blockers rather than implied completed audits.
