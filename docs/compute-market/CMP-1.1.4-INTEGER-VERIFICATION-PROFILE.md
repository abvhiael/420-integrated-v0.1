# CMP-1.1.4 — bounded integer sum-of-squares verification profile v1

**Status: proposed narrow executable profile; full CMP-1.1.4 and production qualification remain open.** Implementation: `contracts/src/compute/ComputeJobIntegerProfileVerification420.sol`; end-to-end tests: `contracts/test/ComputeJobIntegerProfileVerification420.t.sol`. This is an actual deterministic arithmetic workload, not a GPU-execution, AI-inference, hardware, or general off-chain correctness proof. The older signature-only and appointment-only adapters MUST NOT be the live endpoint for this profile. Choose the integer-profile adapter as `ComputeJobRegistry420.verificationEvidence` at registry deployment; that reference is immutable.

## Canonical workload and independent oracle

Profile: `keccak256("420/CMP/PROFILE/INTEGER_SUM_OF_SQUARES/V1")`. Workload: `keccak256("420/CMP/WORKLOAD/INTEGER_SUM_OF_SQUARES/V1")`. Four uint64 input values `x[0..3]`, each at most 1,000,000,000. Compute an exact uint256 sum `x[0]^2 + x[1]^2 + x[2]^2 + x[3]^2` without rounding, hidden inputs, nondeterministic external data or approximate tolerances; the maximum is 4,000,000,000,000,000,000, safely within uint256. The job's immutable `workloadType` must match and its `outputSchemaCommitment` must equal `keccak256("420/CMP/SCHEMA/UINT256_SUM_OF_SQUARES/V1")`. Its committed input MUST be `keccak256(abi.encode(INPUT_DOMAIN, x))`, where `INPUT_DOMAIN = keccak256("420/CMP/INPUT/INTEGER_SUM_OF_SQUARES/V1")`. The worker's output preimage is one uint256 `claimed`; its output hash is `keccak256(abi.encode(OUTPUT_DOMAIN, claimed))`, where `OUTPUT_DOMAIN = keccak256("420/CMP/OUTPUT/INTEGER_SUM_OF_SQUARES/V1")`. The independent evaluator checks each bound and recomputes the expected sum directly from the committed input. No worker-supplied expected answer is trusted.

The evaluator reconstructs the *actual assigned worker result commitment* from the canonical worker adapter's `RESULT_DOMAIN`, chain ID, worker adapter address, job/request/manifest/match/acceptance/assignment/resource/attempt/worker fields, committed worker receipt hash and committed output hash. It compares that recomputation against both the canonical job result and the assignment's immutable result. A different output preimage, input value, assignment or receipt fails *before* the verdict. Incorrect but genuinely committed output is accepted only as an **independently substantiated negative** verdict. A known-good output may receive only a positive verdict. A signed positive verdict for an incorrect committed result and a signed negative verdict for a correct result both revert.

The adapter rejects the inherited bare `submitVerdict` entrypoint, so a signature alone cannot bypass evaluation. It invokes the appointment- and capability-enforcing parent only from the profile-specific evaluation entrypoint. The independent evidence reference is `keccak256(abi.encode(EVIDENCE_DOMAIN, verdictDigest, jobId, inputCommitment, workerResultCommitment, workerOutputHash, receiptHash, claimed, expected, correct))`, with `EVIDENCE_DOMAIN = keccak256("420/CMP/EVALUATION/INTEGER_SUM_OF_SQUARES/V1")`. It is stored under the exact EIP-712 verdict digest with its result and receipt binding. The event also exposes job, verdict and evaluation reference. Any failed signature, appointment, authority, job transition or evidence check rolls back atomically; it never releases reserved payer funds. The evidence reference binds the disclosed arithmetic witnesses to the **signed digest**, but the signature schema itself has no standalone `evidenceRef` field; do not present it as a general-purpose externally signed proof of arbitrary computation.

## Reproducible examples and negative controls

Input `[3,4,5,12]` yields expected `9 + 16 + 25 + 144 = 194`. A worker commitment for 194 permits a signed positive verdict and stores the expected/claimed values and evidence reference. A worker commitment for 195 causes signed positive evaluation to revert; an independently computed signed negative verdict records the mismatch and marks the job FAILED without settlement. For a job actually committed to 194, supplying 195 as the output preimage, changing the receipt hash, or changing any input value must revert before nonce consumption or job transition. A signature-only call or a different profile must revert. The focused Foundry suite verifies these paths against a real signed request, authorized payer reservation, canonical accepted match, canonical worker commitment, shared CapabilityRegistry420, and independently appointed verifier.

## Explicit limitations and release gate

Because evaluation occurs on-chain, this profile proves the bounded arithmetic relation between the supplied and committed input/output *when all inputs are revealed*. It does not prove an off-chain worker actually executed anything or meter GPU/CPU usage. Profiles for AI, video, scientific computation and private inputs require separate methods such as reproducible trusted execution, cryptographic proofs or independently rerun workloads; this profile grants none of those permissions. Governance must explicitly approve this profile and verify selector/attestor independence, evidence availability, contract bytecode/configuration and deployment roles. Production must also qualify authorization expiry, profile and controller revocation effects on historical decisions, adversarial signature paths, complete exact-head CI, main reconciliation, escrow and refund rules. Keep PR #370 draft and payments fail-closed until the separate release gates are satisfied.
