# CMP S-04 — Participant identity and consent

**Status: REPOSITORY IMPLEMENTATION ONLY — LIVE PROVIDER IDENTITY PROOF AND TESTNET CLOSEOUT DEFERRED.**

The identity registry prototype links 420Wallet chain-bound accounts to pseudonymous external donor/project commitments using dual authorization: a wallet-verification result supplied by a separately trusted Wallet boundary and a versioned Ed25519 proof from an explicitly governed provider/project proof key. Public usernames, stats or CPIDs never establish account control. Link and disconnect are explicitly consent-gated; disconnect preserves a minimal non-identifying audit digest and prevents proof replay. Re-linking requires a new challenge. Multiple external IDs cannot claim one live Wallet/provider/project link, and an external identity cannot be assigned to a second live Wallet in the same project. All records are explicitly monetization-ineligible.

**Critical boundaries:** `verified:true` wallet authorization is a **fixture-only assertion by the caller**, not a cryptographic wallet signature check. Real deployments MUST instead verify Wallet EIP-712/1271 authorization at the trusted API/on-chain boundary. The in-memory registry is not durable across restarts, so it cannot yet provide production collision/replay or historical transfer protection. The external proof signing scheme is an integration interface, not evidence that Folding@home or any BOINC project offers it. No live project credential, passkey or donor account is accessed. Do not enable monetized identity linking with this implementation.

Outstanding S-04 exit gates: actual provider-supported ownership evidence/consent, verified Wallet signatures, persistent challenge/ownership ledger, key rotation, privacy deletion policy and historical ownership-transfer/recovery handling, real unlink/relink/outage drills. These belong on the shared testnet worklist alongside S-02/S-03 live-provider gates. Existing reward/attester authority unchanged. S-06 retains the first Level 2 milestone.
