## 420Compliance adapter contract — proposed v1
`POST /v1/compliance/delivery/evaluate` is an integration *proposal*, not an existing 420Compliance endpoint. Coordinate path/schema with its independent implementer; keep an ant-corruption adapter behind the below internal immutable shape.

Input: `request_id`, `idempotency_key`, `tenant_id`, `actor_ref`, `service=DOOBR`, `action` (`QUOTE|DISPATCH|PICKUP|HANDOFF|RETURN`), `service_category=CANNABIS_DELIVERY`, origin/destination standardized jurisdiction+coarse zone refs, `carrier_class` (`LICENSEE_EMPLOYEE|DELIVERY_PERSON|COMMON_CARRIER`), opaque retailer/courier/recipient credential refs, time in UTC with canonical IANA timezone, cannabis equivalent quantity and authoritative prepaid sale/transaction reference (opaque), expected policy version and request hash. Never send raw GPS, street address, ID image, signature or unnecessary PII to broad policy logs.

Output: `decision=ALLOW|DENY|UNKNOWN`, `decision_id`, `request_hash`, `tenant_id`, `actor_ref`, `action`, `service_category`, `origin/destination_scope`, `carrier_class`, `policy_id`, `policy_version`, `issued_at`, `expires_at`, `revocation_epoch`, `issuer_key_id`, `signature`, `reason_codes`, `legal_evidence_refs`. Validate trusted issuer, signature over canonicalized payload, request hash, intended audience, nonce/idempotency domain, exact tenant and action, epoch, time/revocation and maximum acceptable decision age. Never accept cross-order/cross-region ALLOW or downgrade UNKNOWN to ALLOW.

**Fail-closed scenarios:** missing, stale, unsigned, invalid signature, wrong audience/actor/tenant/carrier/timezone, future-issued, mismatched request hash, replayed nonce, unsupported policy, issuer offline, partial responses, ambiguous location, deny, revoked retailer or courier, policy changed mid-order. A previously approved dispatch must be revalidated at HANDOFF; on mid-route revocation suspend fulfillment and invoke regulated carrier-specific safe-return/escalation flow (not automatic unsafe abandonment). Discovery eligibility isn't authorization to dispatch or handoff.

## Travel/Maps read-only public projection contract — proposed v1
Endpoint `GET /v1/public/regions/{coarse_region_id}/presence` (DOOBR API boundary once implemented). Response must be **schema-allowlisted** with exactly: `schema_version=doobr-presence/v1`, `region_id` (public coarse ID), `status=AVAILABLE|LIMITED|UNAVAILABLE|UNKNOWN`, `observed_at`, `expires_at`, `jurisdiction_policy_ref` (opaque non-sensitive public ref), `handoff_url` (pinned allowlisted HTTPS DOOBR origin). Absolutely no `courier_id`, precise coordinates, `address`, `phone`, `order_id`, capacity below anonymity threshold, payment token, credential, customer ID, ETA falsely inferred from status or exact courier counts. Only publish aggregated status when minimum sample threshold and fresh consented location evidence are met; otherwise return UNKNOWN. If 420Compliance's *public* coverage decision is absent/unapproved/stale, status UNKNOWN; never claim a real courier exists based solely on a configured service area. Must return no-store or suitable bounded caching with strict expiry and privacy safeguards.
Travel and Maps **cannot** invoke DOOBR transaction APIs; their consumer UI may display a coarse region presence card and an ordinary external DOOBR deep link after approved advertising review. No private authorization claims or public cannabis merchandising are implied.
