## System boundary, threat actors and protected assets
Potential attackers: fraudulent consumers, dishonest/compromised couriers, retailer insider, compromised support operator, malicious third-party identity or compliance issuer, stolen device, API/webhook adversary, hostile tenant, data broker and chain/indexing observer. Trust boundaries: consumer browser/mobile -> DOOBR session API -> per-tenant DB; courier mobile/location service -> dispatch; licensed retailer -> custody/payment proofs; 420Compliance signed policy -> eligibility adapter; Identity/Verify/Registry -> subject eligibility; 420Pay/Dev Compensation Vault -> approved financial authority; DOOBR coarse public status -> 420Travel/Maps/Search; notification/analytics/logging -> external processors. No implicit delegation across these boundaries.

Classify: **RESTRICTED PII** precise GPS trails, home or private delivery addresses, ID document images, recipient name/signature, phone, protected accessibility details, device identifiers; **REGULATED CONFIDENTIAL** age-verification results, licence/credential provenance, cannabis product/order quantities, custody/return records, retailer account/payment references; **SECRET** session tokens, refresh credentials, API keys, signing keys, wallet signatures, encryption keys; **PUBLIC MINIMIZED** approved aggregate region availability, non-sensitive registry references, sanitized public links. Canadian privacy laws, BC private-sector PIPA, federal PIPEDA where applicable, regulated retention and lawful access require separate counsel policy mapping; do not assert blanket erasure where retention duties apply.

## Data lifecycle and privacy acceptance
- Consumer: private shipping address never publicly discoverable; store only needed window; separate retailer required records and recipient signatures under a retention schedule reviewed by counsel.
- Courier: position sampled only while explicitly working/authorized; users and Travel/Maps may receive coarse status only, not tracking extrapolating personal movements. Retain fine-grained route samples minimally; sanitize support exports.
- Retailer: order and cannabis product details confined to originating licensed retailer and legitimate custody handlers, not public wallet/events.
- Recipient: proof-of-age must be an independently trustworthy boolean/claim and required signature/name evidence; do not use speculative face recognition or deposit images on chain.
- Operations: audit evidence append-only with actor, tenant, policy version and exact time, but cryptographically/random scoped references must not become stable public behavioral identifiers.
- Crypto: signing material protected by OS keystore/HSM as appropriate, prohibit client-side embedded master secrets; Wallet consent revocation immediate at API boundary.
- Incident: disable affected region, role or settlement adapter separately; preserve safe-custody and return obligations without creating unlawful abandonment. Retain minimal forensic evidence and protect subject notifications.
