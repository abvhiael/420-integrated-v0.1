# DOOBR R03.4 — Courier enrollment, credential status and availability

Canonical R03.4; PR #601, branch `roadmap/doobr-bc-vancouver-infrastructure`. Last verified main `6d2932deb243328e1956619e10ef250a8bcc1d88`. This is app-scoped Level 1; Level 2 at R03.12, Level 3 at R05.10.

Implementation: `doobr/courier_view.py` verifies an independently issued, nonrevoked 420Identity session and per-courier role, checks actor ownership and delegates to R02.4 `verify_courier`, which requires verified, time-valid, unrevoked authority/training/identity and vehicle credential where policy requires. A successfully verified credential returns REQUIRES_OPERATOR_APPROVAL and OFFLINE: eligibility does not independently authorize live dispatch or availability. The R02.5 trusted presence ingestion retains exclusive independent policy, geofence and authorized session checks. Public `web/doobr/courier.mjs` rejects all client-provided forged enrollment, credential and available status, returning CLOSED/UNVERIFIED/OFFLINE. The accessible website courier section discloses these restrictions and three carrier classifications without permitting uploads, customer or courier identity collection, GPS collection or enrollment mutations. `web/doobr/scripts/test-courier.mjs` and `doobr/storage/tests/test_courier_view.py` cover negative/ownership/revocation; dedicated `.github/workflows/doobr-r03-4-level1.yml` covers exact SHA, retained courier eligibility tests, site regressions and static build.

**Limitations / pending:** Actual new courier enrollment operations, independent issuance/revocation integration, authoritative credential status and authorized live availability remain NON-OPERATIONAL, not silently simulated. The present module is a trusted status projection contract, not a deployed API. No production credential issuer, 420Compliance runtime, 420Identity session issuer, mobile permission flow or operator onboarding is accepted in this phase. Release cannot proceed until independently reviewed legal, security, partner and operational approvals. **R03.4 status PENDING exact-SHA Level 1.** A green app-scoped suite qualifies only implemented non-operational boundary, not live enrollment. Level 3 main reconciliation remains deferred. Next canonical step R03.5 Courier offers, navigation, custody and proof-of-delivery flow.
