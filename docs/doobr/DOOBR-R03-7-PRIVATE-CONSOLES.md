# DOOBR R03.7 — Private operator/safety/compliance consoles and dual control

**Canonical step:** R03.7, Level 1 ordinary client phase step. Branch `roadmap/doobr-bc-vancouver-infrastructure`, PR #601. Inspected main `fe21ef07359d6915bf5daac37c4bf24a24fcf19b`. Client Level 2 R03.12, full exact-SHA Level 3 R05.10.

Implemented `doobr/private_console.py` independent dual-review gate for bounded incident escalation, safety hold and compliance review. Both actors must pass individually signed 420Identity/role/session revocation checks with resource-scoped OPERATOR ESCALATE_INCIDENT authorization; their actor ID, principal subject and token ID must all differ. The externally controlled case/purpose/evidence verifier must return exactly true. Missing/unavailable authority rejects. The return value only attests a proposed review; it cannot mutate regulated orders, waive 420Compliance decisions, release holds or approve deliveries. Unit negatives in `doobr/storage/tests/test_private_console.py` cover identity separation, same-token, purpose injection, expired/revoked identity authorization, independent review denial and unavailable authority. Exact-SHA targeted checks in `.github/workflows/doobr-r03-7-level1.yml`.

**Unfinished original step:** actual private operator console, distinct safety and compliance consoles, persisted two-person proposal/approval ledger with transactionality and replay controls, audit trails, review queues, oversight UI, independently published safety/compliance permissions and case execution are NOT implemented by this verifier. Distinct safety/compliance roles have not been added to 420Identity; OPERATOR permission remains the only pre-existing grant and therefore this verifier does NOT establish the complete role split. Independent live evidence authority and deployed identity issuer remain absent. All corresponding production operations stay disabled. This component can pass targeted unit tests without qualifying R03.7 as COMPLETE. No invented working endpoints or approvals.

**Status:** PARTIAL implementation, targeted CI pending. Level 2 at R03.12 and comprehensive Level 3 at R05.10 remain intentionally deferred, not treated as a substitute for outstanding Level 1 step requirements.
