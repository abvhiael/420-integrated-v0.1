## Real behavior and security

- **Creation and start:** Host can start only a fully accepted `ready` room, with server-locked BC-0.5 seats, verified bidirectional block checks, an explicitly registered game rules adapter and pinned version+hash. A second start cannot create a duplicate session. A room becomes `in_game`; its player and team configuration becomes immutable for that session. **No real production rule adapter exists for any of the 25 Classics**, so the production resolver is intentionally nil and an unqualified game cannot start.
- **Persistence and recovery:** The server stores the authoritative opaque game snapshot, room ownership, per-turn deadlines, revision, lifecycle status, and ordered events. A signed-in participating human can list and recover their session after disconnect/restart; only an authorized rule adapter can project that viewer's private state, so an opponent's concealed hand is not sent to another seat.
- **Turn validity:** The handler binds actions to the verified 420ID subject; source code validates requested ID, expected next sequence, active status, designated acting seat, current rule hash, legal move via trusted engine and bounded output. Same request ID/payload is idempotent; reused IDs with changed payload, stale sequences, repeated actions, turn stealing, unsupported status or fabricated results fail closed. Game-scoring logic is exclusively delegated to a qualified rule adapter, not implemented speculatively in BC-0.6.
- **Timers and terminal results:** A 120-second deadline is set by the PostgreSQL clock and enforced in a locked transaction; 3-second sweeper plus read/action expiry prevents clients from extending turns or skipping timeouts after backend restart. A session can terminate by qualified engine output, resignation, host cancellation or timeout, with public journal event and room terminal transition committed together. For a two-player resignation the server assigns the other seat the forfeit win; no browser-defined winner is accepted.
- **Player updates:** `GET /v1/classic-sessions/{uuid}/events?after=N` gives bounded ordered public-only changes. `GET /v1/classic-sessions/{uuid}/stream` publishes reconnectable SSE with event IDs, bounded duration, and reauthentication plus fresh participant/block checks each delivery pass. A stale journal cursor requires resynchronization from authorized snapshot; private engine state never enters public events.
- **Bot/rules boundary:** Mixed human/bot BC-0.5 rooms can still be configured, but BC-0.6 deliberately rejects beginning a bot-filled match until BC-0.8 supplies a qualified bot decision engine. The `bc06TestRule` used for integration is a deterministic **test-only** two-seat adapter, not Chess or Cribbage implementation. BC-0.7 still must define versioned legal actions, hidden state, scoring, reproducible randomness and per-game rules.
