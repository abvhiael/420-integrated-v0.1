## Contract and acceptance boundaries

- **Version identity:** Ruleset hash is SHA-256 over the canonical game ID, version and immutable public specification separated by newline bytes. It is a *contract fingerprint*, not a complete hash of a Go binary. Any modified semantics must ship under a new qualified rules version/hash. Recovery requires the exact pinned adapter and fails closed otherwise.
- **Legal deterministic moves:** An action must match a bounded canonical legal-action list from the registered rules module. Both legal enumeration and transition are run twice with the same inputs and must agree. Modules implement authoritative scores, phase/round progression, terminal results, seed/data validation and per-player views. Strict codec rejects malformed/duplicate/unknown JSON, fabricated winners, invalid score/turn/seat/round values, out-of-budget actions and overlarge snapshots.
- **Replay and recovery:** For a rules-backed match, the server retains an immutable seeded initial state plus each accepted private action and before/after hash. It reconstructs from the seed on a locked mutation or repeatable-read recovery; a corrupted snapshot, omitted/reordered action, forged digest, altered game source fingerprint or mismatched terminal result blocks the operation. Public SSE/journals retain only lifecycle metadata; private actions, seeds and hidden game state are never published to other players.
- **Deterministic randomness and budgets:** The server generates the initial seed with crypto/rand. Modules may use RuleRandom with explicit persisted counter and domains, but must not read the wall clock or unseeded entropy during rules evaluation. Rules and bot decision contracts receive a bounded RuleBudget; only operator-compiled/trusted rule modules may be registered (no uploaded executable/JS module sandbox). A single replay is capped at 512 moves and legal branching at 128 actions pending title-specific qualification.
- **AI boundary:** A ChooseMove policy may see *only* the requesting seat's projected view, difficulty and legal actions, and must return an action from that set within its budget. This contracts BC-0.8's interface, but **no AI policy/runner is activated** by BC-0.7. A bot-filled lobby still cannot start a match.
- **Game release boundary:** The in-repository demonstration is an explicitly **test-only deterministic counting-round fixture** installed by tests under the test game ID and cannot be confused with real Chess, Cribbage or one of the other 25 Classics. Production's rules resolver is still nil; newly qualified generic infrastructure does not authorize a playable Classic.
