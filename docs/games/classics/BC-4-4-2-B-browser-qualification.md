# BC-4.4.2-B browser qualification

This PR adds a test-only Playwright runner, not a production feature or release authorization. The required fixture job builds and statically qualifies the actual frontend, serves it locally, and runs its real app shell, controller, renderer, and CSS against explicit synthetic API responses. Six board sizes × four viewports (1920×1080, 1366×768, 768×1024, 390×844). Checks include asset decoding, background images, square geometry, intentional board scrolling, containment, solid-panel text contrast, controls, rejected move and recall. Screenshots and JSON are retained for 90 days. Fixture results do not certify real backend gameplay or screenshot design approval; human visual review remains necessary. Image-text contrast is not measured by the solid-panel check.

Optional live job: configure repository variable BC442_LIVE_ENABLED=true only after this runner is merged into main. Configure protected environment bc442-live-acceptance with required reviewers and dedicated short-lived test account cookie (BC442_COOKIE), dedicated active session UUID (BC442_SESSION_ID), and rules hash variable BC442_RULES_HASH. Live job uses trusted main code only, never PR code; fork PRs are excluded. No credentials in fixture job, no production mutations, no traces or raw API payloads. Live checks actual 420ID, authoritative session, rendered controls, reload recovery and masked screenshots. Live job skipped when not enabled; missing all live inputs yields explicit skipped report. Partial configuration fails. Full live gameplay mutation and all six live configurations require separately authorized dedicated sessions; the read-only probe does not certify them. Existing production release restrictions remain untouched. The deployed app must already expose restricted Word Salad; do not enable it via browser interception in live mode.

No baseline images are invented. Review artifacts against approved artwork and record dispositions.
