# HC-NEXT-3.2 — Manufacturing delivery and retry contract

The canonical R04.3 ManufacturingEngine and R04.1 inventory/ledger already establish immutable versioned recipes, two distinct typed inputs and two distinct typed outputs, time-locked completion, atomic reservations and single-use settlement, explicit cancellation loss/refund, owner and issuer authorization, and bounded queues of 1–32 active jobs.

This implementation adds `startWithRequest(recipeId, requestId)` and `completeIdempotent(jobId)` without weakening the original strict `start` and `complete` interfaces. A registered client must persist its random nonzero request ID before sending the start transaction and reuse exactly that ID for retries. The on-chain owner/request pair binds to exactly one recipe and job, including after completion/cancellation. Reusing a request with a different recipe reverts. A retry does not reserve stock, increment the owner nonce, or take another queue slot.

A client submitting a completion can use `completeIdempotent` to acknowledge an already completed job without consuming another input or minting another output. Only the recorded owner can receive that acknowledgement; cancelled/unknown jobs are rejected. While ACTIVE, completed processing is the same transaction as the original completion implementation: enforce the immutable timestamp, consume reserved inputs, issue outputs, decrement the queue, mark COMPLETED and emit the event. If an issuance grant, output resource, or downstream accounting call fails, EVM rollback restores the ACTIVE job, original queue slot, input reservations and unchanged outputs. The client can retry after the missing authority/resource condition is resolved; no administrator can arbitrarily claim success.

Cancellation retains the original per-input floor-rounded loss/refund and remains available independently of manufacturing ingress pauses. Replays of cancellation and strict completion are rejected; terminal jobs cannot be restarted under the same request identity. Resource conservation is by typed SKU rather than comparing incompatible units across recipes. Actual recipe physical mass balance, inventory catalogue admission, manufacturing equipment mapping, authenticated account transport, server outbox, and production issuer grants require separate evidence; the request ID alone cannot authenticate a browser or turn a guest save into authoritative stock.

Scoped exit qualification: exact-SHA Foundry R04.3 Level 1, R04.2–R04.4 Level 2 integration, R04 Level 2 retained application, and manufacturing-to-equipment issuer integration, with no manually dispatched global requalification.
