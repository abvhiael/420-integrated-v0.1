# HC-PLACE-03-C — Production authority and canonical instance lifecycle

Operator-gated world authority provisioning and revocation are persisted under the exact same serializable economy namespace lock as placement transactions. An external independent authority must authenticate the operator and verify the signed world evidence; without both dependencies, provisioning fails closed. Revision rollback and stale concurrent provisioning are rejected. Revoked parcels prohibit placement writes, including replay. Re-provisioning requires a greater revision and independently verified evidence.

Placement records retain strict HC-PLACE-02 record shape; original canonical custody-unit identity is anchored to the immutable placement operation receipts rather than a client-supplied field. Restoring an existing stored instance requires the exact original custody unit remain available and owned by the same principal, and occurs within one atomic reservation, placement and scene update. Sold or otherwise reserved original units cannot be substituted by fungible inventory. Unsupported intentional transfers remain fail closed; no browser or production API is enabled.

Outstanding production acceptance: integration of real independent operator, world-signature and ACL/geometry services with deployment credentials and revocation event synchronization; external verification and phase-wide API/attachment controls are not represented by local fixtures. Independent live acceptance remains a release gate.


## Production runtime composition and transfer policy

`runtime-service.js` may compose a placement service only if a separately supplied independent `world` verifier, qualified geometry resolver and asset resolver exist. The resulting server-only `placement` object exposes registry, transactions and stored-instance transfer components; **no placement HTTP endpoint is enabled**. `HighCountryProductionPlacementAuthority` binds the registered principal to the issuer and durable runtime session epoch inside the same locked transaction. Operator privileges come from the trusted issuer configuration. Missing world verifier methods, stale epochs, revoked accounts, revoked parcel revisions and missing synchronous world commit authorization fail closed.

The authority registry accepts independently verified grant/revoke events in contiguous monotonically increasing parcel revisions and rejects unverified, duplicated, out-of-order or missing-parent events. Operational feeds must deliver finalized signed events and reconcile remote high-watermarks; external key provisioning, event delivery and real revocation latency remain live acceptance items tracked in `HIGHCOUNTRY-TESTNET-WORK-ROADMAP.md`.

**Intentional ownership transfer is allowed only for a STORED, unreserved canonical instance** with independently verified consent from both authenticated parties, current non-revoked runtime identities, the exact original custody unit, sufficient source-backed inventory, compatible provenance, no live children and an unused operation ID. The stored record, custody owner, source lineage, balances and operation receipt update atomically. Placed/listed/escrowed items cannot transfer via this route; canonical-chain inventory transfers require their separate finality-gated escrow architecture. Recipient acquisition does not confer parcel access; any subsequent restore must independently pass the recipient's current parcel authority. Zero fees and no new BUDS issuance are involved.

Pre-testnet tests cover operator event ordering, stale/revoked session epochs, forged consent, exact-unit inventory, replay and PostgreSQL transfer persistence. A fixture PASS does not establish live signer, parcel or chain acceptance.
