## Finalized version-one economics

- Each standard pack contains **three seeds of one cultivar**. HC-SEED-08 performs one 60% common / 30% rare / 10% Original Sixteen tier draw, then a uniform draw within that tier's exact regional or World pool. Currency cannot affect odds.
- A standard regional or World pack costs **420 integer BUDS** or **1 native $420** (`1000000000000000000` native base units, 18 decimals). This is a game price decision, not a USD quote or a currency peg. HC-SEED-09 will enforce payment and exact purchase receipt binding before paid issuance.
- Once per registered principal, choose a region and receive **two distinct common starter packs**, three seeds each, free. The exact fixed cultivar allocations are in `deployments/highcountry/seed-pack-policy.v1.json`. These are transparent onboarding allocations, not randomized standard packs. Region cannot change after grant.
- Lifetime source ceilings per provisioned game namespace: 100,000 starter accounts, 100,000 standard packs per pool (three regions plus World), 100,000 issued/reserved seed units per common/rare cultivar and 10,000 per Original Sixteen cultivar. Cultivar and source ceilings both apply; a nominal source ceiling is not a promise of availability. Starter cultivar supply reserves atomically when the grant is issued. There are no automatic resets, expiry reclaims, supply refunds, substitutions or rerolls.
- All 23 common, 26 rare and 16 Original Sixteen identities are represented exactly once in World and once in their regional tier pool. Catalogue membership is not registration proof. Seed preparation requires an independently read finalized registered genome and canonical ancestry verification.

`seed-pack-policy.v1.json` is reproducibly generated by `node scripts/highcountry/build_seed_pack_policy.mjs`; CI checks its exact content. Future changes need a new explicit policy and migration preserving lifetime starter/source/lot claims. Existing packs retain their version and committed identity. These source ceilings govern this pack issuance path, not arbitrary external mint authorities or player breeding.

## State and authorization

The existing provisioned PostgreSQL namespace, SERIALIZABLE transaction and row lock cover seven new maps plus permanent starter-wallet claims. Schema-one saves default absent maps to empty; all new maps encode on every write. Runtime roles retain SELECT/UPDATE only and namespace RLS. Currency balances, assets and reward totals are untouched by grants and preparation.

Starter IDs bind game, registered principal and ordinal. A durable principal grant allows only idempotent same-region reads. New sessions, account revocation/reinstatement, wallet unlink and process restart cannot grant again. The grant is tied to the identity provider's stable registered principal, not an unprovable human uniqueness claim. A wallet used for starter issuance is permanently recorded and cannot issue a second account's starter seeds after relinking.

`/seeds/packs/allocate` is for **explicit authorized allocations**, not purchases. It requires a current independently signed issuer session with the configured `seed-packs` source permission, rechecked in the committing transaction. Exact recipient/region/count and issuer bind each globally unique source receipt; replay with changed data rejects. A registered recipient is mandatory. It creates no payment proof and cannot open a standard pack. Operators must not use this route to bypass HC-SEED-09 paid admission. Both paths must share the same standard supply counters when HC-SEED-09 is added.

Lot IDs are deterministic nonzero uint64 values derived from game and pack; a collision fails closed. Metadata commits version, pack, owner, wallet, cultivar, genome and quantity. Common starter lots use breeding event zero, not invented breeding evidence. Preparation reserves one immutable lot and frozen recipient wallet/epoch. The canonical register calldata is generated by the server; clients supply no genome, quantity, seed-lot ID or recipient address. No local seed balance is invented: existing catalogue ownership remains a finalized SeedRegistry read.

## Issuance lifecycle and operator wiring

Enable only with `seedPacks: {"version":"HC.SEED.PACKS.V1"}` and the existing reviewed `seedCatalogue` configuration. Pin actual SeedRegistry, EmergencyState (`emergency`) and all HC-SEED-05 genetic dependencies. SeedRegistry enforces capabilities; the worker separately enforces the existing `HC.EMERGENCY.MARKET` domain before new submissions. The canonical runtime uses its reviewed operator and external signer RPC; ordinary runtime can prepare and confirm but cannot silently sign. Configure the operator's identity-provider subject with source permission `seed-packs`, and provision the **actual** HighCountry capability for module `SEED_REGISTRY`, action `SEED_REGISTER`, scope `bytes32(uint256(lotId))`, amount 3. The issuer's web identity permission is insufficient to mint without that on-chain capability. No periodic grant is assumed: current HighCountryAuthorization rejects periodic budgets; durable issuance counters enforce this service's cumulative caps.

1. Player signs in, claims starter region, then prepares each pack after linking a canonical wallet. The UI is in `/seeds`.
2. Operator reads the issuer-only, paginated `/seeds/packs/pending` queue and its immutable intents and provisions its exact scoped capability through the authorized deployment lifecycle.
3. Operator calls `/seeds/packs/dispatch` with the pack ID and its own signed bearer session. The leased worker reconciles finalized registry state first. Otherwise it rechecks recipient epoch/binding, signer chain, the code-pinned canonical MARKET emergency domain, code-pinned registry state and actual registration authorization by canonical `eth_call`, then sends the exact calldata through the external signer. It never handles player private keys.
4. A returned transaction hash is pending evidence, not seeds. Repeated dispatch waits for finality. Finalized exact record readback verifies ID, genome, breeding event, recipient, quantity, metadata, current code pins, canonical genome identity and unchanged block anchor before marking the pack opened. Player `/confirm` can perform the same finalized readback.
5. Crash after broadcast but before saving the hash: a later worker reconciles the same ID. Before finality it may resubmit that same immutable registration, but the actual registry rejects duplicates. No replacement ID, changed cultivar, automatic refund or operator-supplied entropy is accepted.

Worker attempts are bounded at 50 submissions per intent, without preventing later finalized reconciliation. A recorded transaction hash is never automatically replaced: a dropped/reverted transaction stays pending until independently reviewed. This deliberately preserves provenance and avoids unsafe cancellation/refund claims. Recipient epoch revocation or unlink before submission halts dispatch. Relinking the same wallet/profile at the original epoch can resume it; an epoch change requires independent operator review and never silently allocates a replacement lot. Revoking after an on-chain broadcast cannot undo a transaction.

The operator runner is `node scripts/highcountry/dispatch_seed_lots.mjs --plan` (read-only default) or `--dispatch`. Set `HC_SEED_RUNTIME_URL` to the reviewed HTTPS service origin and `HC_SEED_OPERATOR_TOKEN_FILE` to a short-lived signed source-issuer session. Plan output includes exact scope hashes, quantity and calldata for the existing authorized capability process; it never grants capabilities. Dispatch pages all pending intents and invokes the leased worker. Re-run it through an independently configured operator scheduler with a current token to reconcile finality. The runner neither funds transactions nor handles wallet keys; a failed item is reported and gives a nonzero exit without changing its identity.

## HTTP interface

All routes are POST, strict field sets, no-store responses, origin checked. `/seeds/packs/policy` accepts `{}` publicly. Signed player routes: `inventory {}`, `starter {region}`, `prepare {packId}`, `confirm {packId}`. Scoped issuer-only routes: `allocate {receiptId,owner,region,count}` `pending {after,limit}` (at most 100 immutable prepared intents per page), and `dispatch {packId}`. Existing catalogue, social, market and currency routes retain their authority checks. Pack inventory is account-bound; no pack resale, transfer, guest claim or cosmetic-art entitlement is implied.
