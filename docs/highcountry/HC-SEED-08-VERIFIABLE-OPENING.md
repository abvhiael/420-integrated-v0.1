# HC-SEED-08 — Verifiable random opening

## Implemented scope

Standard regional and World pack opening now commits one immutable source/owner/genome-pool intent before requesting entropy, routes through the actual canonical proof-verifying RandomnessRouter420, records a deterministic outcome once, and produces the HC-SEED-07 seed-lot intent. HC-SEED-09 payment settlement remains separate. Starter packs remain the fixed common allocations from HC-SEED-07; they never enter the standard random draw.

Implementation and scoped qualification evidence is reconciled against the exact implementation SHA in the step's PR. This is not live activation: deployment manifests remain unresolved. No production VRF provider, finalized live Genesis, live registered genome set, deployed opening contract or live operator authority is fabricated by tests.

## Exact selection and immutable pools

`seed-opening-policy.v1.json` is generated by `node scripts/highcountry/build_seed_opening_policy.mjs`. It contains the canonical policy hash, four pool commitments, sorted cultivar IDs, tier sizes and 256 explicitly test-only cross-language vectors. World contains all 23 common, 26 rare and 16 Original Sixteen identities; each regional tier contains exactly its established canonical assignments. The policy preserves three seeds of one cultivar per pack, with 60% common, 30% rare and 10% Original Sixteen pack outcomes. It does not perform three independent rarity draws.

Tier selection uses a uniform ticket in 0–9: 0–5 common, 6–8 rare, 9 exclusive. Cultivar selection uses a separate domain-separated draw with that tier's exact cardinality. Both expand the same frozen canonical root through Keccak of `(root, requestId, drawDomain, counter)` and reject words below `2^256 mod bound` before modulo reduction. This removes modulo bias. Counter expansion is fixed arithmetic inside one committed draw, not a provider request, reroll or user choice. The bounded 256-word expansion fails closed on exhaustion, retaining the same entitlement; no substitute root is accepted.

Contract and JavaScript use identical ABI words and draw domains. No timestamp, browser RNG, server RNG, caller-supplied salt, rarity override, currency multiplier or artwork controls an outcome. Chain ID, opening/router/emergency deployment addresses and code hashes, profile, timeout, wallet, source receipt, policy version, region, full tier membership and an ordered snapshot of the eligible registered genome IDs are committed before entropy. Canonical genotype verification remains HC-SEED-04/05's actual registry/breeding/proof/locus checks; no new phenotype or breeding provenance is invented.

## Entitlement and supply conservation

1. A signed registered owner opens an existing sealed, source-authorized standard pack. The request accepts only its immutable pack ID. Existing source receipts must match the original registered recipient, region and pack membership. Unknown/raw client saves cannot admit a pack.
2. Every cultivar in the complete committed pool must already resolve to its canonical finalized reference genome. A missing genotype or exhausted cultivar rejects the opening before entropy; tiers are never silently shrunk or reweighted.
3. In one SERIALIZABLE transaction, reserve three units against **every possible cultivar** in that pool, record one commitment, and move the pack to `opening-committed`. Source and lifetime cultivar caps include active holds. The starter-grant path also honors these holds. An unavailable full pool leaves the original pack sealed and owned, with no draw or lost entitlement.
4. When the canonical contract has fulfilled the draw, one transaction verifies the selection, releases all unselected holds, converts the selected hold into three reserved seed units and records `outcome-ready`. Reconciliation replay cannot increment supply again. The pack is finally `opened` only after actual finalized seed-lot issuance.
5. Preparation and dispatch re-read the canonical opening proof, require the frozen recipient wallet/profile and exact selected genome, and use the existing deterministic uint64 lot identity, actual registrar capability and finalized original SeedLotRegistered evidence. Rare lot arguments retain the actual lossless canonical breeding event ID; common and founding references use zero. No local ownership balance is invented.

Worst-case reservation intentionally prioritizes exact odds and guaranteed capacity for the committed result. Pending openings can temporarily block new openings or starter grants. Provider delay never releases holds, returns the pack to sealed, changes its region, substitutes a cultivar, refunds a known outcome or creates another draw. Claims remain owned through restart and wallet unlink; issuing seeds still requires restoring the original authorized wallet/profile. Account/issuer revocation stops unauthorized writes without manufacturing another entitlement.

## Canonical timeout recovery without a second random request

Existing router requests expire and may be voided; retrying them with another canonical request ID would create a new draw. The additive opt-in `requestPersistentRandomness(profile, domain, purpose, deadline)` closes that gap for this non-refundable seed entitlement:

- Only security tier >= 2, fallback-void profiles and native-threshold/external-VRF method families are accepted. The deployed verifier must be independently reviewed for a unique valid output for the original request. Method labels alone do not prove a verifier secure.
- The original route revision, operator, verifier, method, profile revision, context, deadline and canonical request ID remain frozen. There is no provider switching, fallback activation or replacement request.
- The deadline remains part of the immutable request/proof/root binding and acts as an operational SLA. An opted-in request cannot be voided; the original approved proof can fulfill after that time. Provider availability remains necessary, but an outage does not destroy the claim or force a reroll.
- Legacy `requestRandomness` callers retain their original deadline, fallback and void behavior. Existing breeding requests do not opt in and their eight canonical lifecycle regression tests remain unchanged.

The existing router interface stays compatible; the opt-in ABI is additive. A new reviewed router deployment/code pin is required. No currently deployed legacy router is presumed to have the new method. Test-only signature verifiers exercise cryptographic request/proof binding and are expressly **not** production unique-output VRF evidence.

## On-chain opening authority

`SeedPackOpening` is deployed with actual router, HighCountryAuthorization, matching EmergencyState, game ID, policy hash, profile ID, timeout, four pool hashes and four-by-three pool sizes. Constructor and RPC readback reject empty/mismatched bindings. The module is `keccak256("HC.MODULE.SEED_PACK_OPENING.V1")`; request action is `keccak256("HC.ACTION.SEED_PACK_OPENING.REQUEST.V1")`; capability scope is the exact opening key, amount zero. The opening key is `keccak256(abi.encode(gameId, keccak256(UTF8(packId))))`.

The operator's independently signed `seed-packs` source permission is also required at the HTTP/transaction boundary. That identity permission cannot replace the actual on-chain capability. No self-grant or provider-fulfillment command is provided. Both MARKET and RANDOMNESS_REQUEST emergency domains block new request/finalize effects while preserving committed state. Deterministic on-chain fulfillment is permissionless, produces one stored result and does not itself mint seeds. Duplicate identical requests/fulfillment are idempotent; changed owner, pool or commitment rejects.

Once entropy becomes public, anyone can calculate a **committed** opening's result. The no-preview property is no free inspection while retaining an uncommitted pack: there is no cancellation, resealing, redraw, replacement source receipt, alternate region or refund path after commitment.

## Runtime, worker and API

Enable explicitly with `seedOpenings.version = HC.SEED.OPENINGS.V1`, existing `seedPacks`/`seedCatalogue`, reviewed `profileId`, positive `timeoutSeconds`, and nonempty `approvedRoutes`. Each approved route contains route ID, revision, frozen operator, verifier, verifier runtime code hash and native/external VRF method ID. Keep prior approved frozen revisions until their pending openings finish. Canonical RPC pins include `seedOpening`, `randomRouter` and `emergency` alongside the existing genotype dependencies. The unresolved template is `deployments/highcountry/seed-opening-runtime.v1.json`.

All reads and code checks use one finalized EIP-1898 block hash and require canonicality, then recheck that anchor. The reader validates contract/game/policy/profile/pool/cardinality bindings, the original persistent request and purpose, frozen approved provider/code hash, fulfilled canonical proof/root (including the registry's valid zero-valued bytes32 boundary), and independently recomputed tier/index. A committed opening cannot be retargeted to another opening contract, router, code revision, chain, profile or timeout. Restore the original reviewed deployment for its pending claims; changing runtime configuration cannot create a fresh draw for the same entitlement. A stale, reorged, wrong-provider, wrong-context, biased/altered selection or missing proof never releases supply holds or enables seed preparation.

Player POST routes (exact field sets): `/seeds/packs/open {packId}` and `/seeds/packs/opening {packId}`. Existing authenticated inventory, seed preparation and confirmation remain authoritative. A collapsed browser verification record exposes the opening contract, canonical request, entropy root, proof commitment and finalized anchor after a verified selection. Source-issuer routes: `/seeds/packs/opening-pending {after,limit}` (max 100) and `/seeds/packs/opening-dispatch {packId}`. Foreign origins, caller entropy/tiers/owners/region overrides, unregistered players and ordinary-player dispatch attempts reject.

Operator runner: `node scripts/highcountry/dispatch_seed_openings.mjs --plan` (default) exports exact capability scope, commitment and calldata; `--dispatch` processes the queue. It uses the same reviewed HTTPS origin and short-lived issuer token-file settings as HC-SEED-07. The canonical runtime supplies the external signer; the wallet-optional ordinary runtime can commit/reconcile but cannot silently sign.

Worker leases are durable across instances. It reads canonical state first; a crash after request or fulfillment broadcast resumes the same opening. A recorded pending transaction waits for finality. A finalized reverted transaction can retry only after verifying its exact hash, canonical block, operator, target, zero value and calldata; retry uses the same key/commitment. Uncertain/dropped transactions remain pending for operator review. Fifty submissions per phase bound automated work but do not prevent later canonical reconciliation. Provider proof arrival is independently operated, not injected by this runner.
