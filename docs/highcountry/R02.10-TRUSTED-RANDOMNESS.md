# R02.10 — Trusted 420 Random integration for breeding

Status: Repository implementation and qualification in progress.

## Canonical authority

High Country consumes **420 Random**, not an ordinary 420 Oracle feed. The approved protocol's `RandomnessRouter420` binds profile, provider route, operator, verifier, domain, purpose, deadlines, fallback policy and chain-specific request identity **before** a provider can supply entropy. Proof verification, replay protection, failed provider handling, emergency fallbacks and void expiry belong to that canonical router and its profile/route authorities.

`CanonicalBreedingRandomnessAdapter` implements the existing High Country breeding-side `request/consume/cancel` interface. It freezes the router address, profile ID and deadline window at construction, and requires a one-time, capability-authorized reciprocal binding to the deployed breeding engine. Production deployment must qualify the exact canonical router bytecode/profile/route and revoke the bootstrap binding grant. Construct adapter before breeding engine, deploy breeding engine with adapter as randomness dependency, then bind the engine.

A breeding request requires the exact locally derived request ID `keccak256(abi.encode(RandomDomains.BREEDING, context))`; the adapter requests canonical randomness using the same breeding domain and full context hash as purpose. It verifies the canonical router's immutable request identity, profile, domain, purpose, requester and deadline. If the router/profile/route is inactive, stale, malformed or unqualified, request creation reverts. No local timestamp/blockhash/oracle fallback exists.

For fulfillment, the adapter requires `FULFILLED` router status, exact bound identities, a still-valid deadline, nonzero canonical randomness root and nonzero proof hash. `RandomnessRouter420` verifies provider proofs and frozen operator identity before returning `FULFILLED`; a hash alone is not a standalone proof. Replays, mismatched domains/context, missing/void/late/failed results and cancelled requests are rejected. High Country cancellation closes local consumption forever; it **does not cancel a pending request inside the immutable canonical 420 Random router**, whose timeout/void policy continues independently. Never claim remote request cancellation.

Legacy `RandomnessCoordinator.fulfill` accepts capability-authorized entropy without a canonical provider proof and remains available to already qualified test/legacy integrations. **Legacy fulfillment must never be labeled fair or 420 Random verified.** A deployment claiming verified fairness must use the canonical adapter and reviewed 420 Random configuration.

## Qualification and deferrals

Targeted Level 1 checks include adapter authorization and binding, verified router status/proof gating, domain/context/request matching, replay/cancel, build, Foundry, verifier and ABI. The existing 420 Random protocol has its own proof/route/fallback adversarial tests; the High Country adapter must not duplicate the full repository inventory.

Live route deployment, active governance-approved provider/verifier proof validation, deployment-grade address and code-hash attestation, end-to-end actual provider callbacks, freshness and fallback/void smoke qualification remain testnet-dependent. Until those pass, claim **repository adapter integration only**, never live independently verifiable fairness.
