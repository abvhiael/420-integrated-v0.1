## Accounting and admission

A plot permanently reserves its growCapacity from the parcel's private capacity. Allocation/release redistributes that reservation among growers; neither operation converts public reservation back to private capacity. Public active plants fit within individual allocations, allocatedCapacity fits within plot growCapacity, and aggregate public reservations plus active private plants fit within immutable parcel capacity. activePlantsByParcel remains the total actually active plants, not reservations. READY still occupies a slot; only the existing terminal transition releases it. No new enum/storage ordinal is substituted for HARVESTED, and no harvest is implemented here.

Private registerPlant retains effectiveOperator equality and cannot spend public reservations. Public registerPublicPlant(plantId, genomeId, grower, plotId) admits an allocated grower even if not the parcel owner/operator. The caller still requires existing scoped PLANT_REGISTER authority: allocation alone is not minting authority or permission to forge provenance. As with retained private registration, authorized issuers can register for another grower; approved issuance/consent and source consumption remain explicit later work. Wallet connection is not a simulation requirement.

PublicPlotAllocated/Released remain allocation events. PublicPlantAdmitted binds plant/plot/grower. PlantCapacityReleased binds plant/parcel/plot/grower, with plot zero for private plants. Existing PlantRegistered/Advanced remain. publicPlotOfPlant is immutable history; activePublicPlants and privatePlantsByParcel are current occupancy. Indexers must apply events using chain/contract/log identity, finality and reorg recovery under R05, rather than treating raw logs as final rights.

## Deployment, authorization and compatibility

1. Deploy auth, Genesis, regions, land and genomes as documented.
2. Deploy PublicCultivationAccess(auth, land).
3. Deploy PlantRegistry(auth, genomes, land, publicAccess). The fourth constructor argument is required; old immutable deployments need replacement, not an in-place upgrade.
4. The reviewed PublicCultivationAccess component issuer grants the deployment principal PUBLIC_PLOT_BIND_PLANTS with scope keccak256("HC.PUBLIC_CULTIVATION_ACCESS.PLANT_BINDING"), zero amount and both period fields zero.
5. Call bindPlantRegistry(plants) once, verify PlantRegistryBound and reciprocal references, then revoke the bootstrap binding grant. Register plots and issue narrow normal plot/plant grants. Unbound reservations and all plant admission fail closed.
6. Smoke-test private reservation boundary, nonowner public admission, denied occupied release, terminal decrement and reallocation; record addresses/code hashes/transactions/handoff under R07.

Binding has no replacement path. Admin-approved code is a trust assumption: reciprocal views/code length do not independently attest a canonical code hash. Deployment review must bind the canonical reviewed PlantRegistry. A compromised bootstrap issuer can deliberately bind malicious code; isolate/revoke that authority. No generic caller can alter occupancy or binding. Calls to other contracts during admission/binding/release are view/static calls; terminal capacity release is local storage only. There is no token custody, oracle, signature, fee or bridge path added. Parcel ownership/occupancy changes do not transfer or erase prior plants or public allocations; private capacity remains shared across operator changes.

Existing function selectors, plant/plot record ABI and stage values remain. Constructor ABI changes and new selectors/events/storage are additive, and the action catalogue gains one explicit deployment-only action (43 total). No shared interface, frozen address, source registry authority or shared account code changes. HC generated bindings are still missing under R05; consumers must regenerate from final artifacts before deployment. Previous deployment records are absent; no deployed compatibility is claimed.
