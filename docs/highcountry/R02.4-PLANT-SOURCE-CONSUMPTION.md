# R02.4 — eligible seed/clone consumption at plant admission

## Canonical definition and gaps

The unchanged roadmap row requires owner/operator/genome/source consistency, duplicate-use rejection and atomic rollback preserving resources. HC-SEC-08 identifies disconnected asset consumption as well as separate fabricated lineage/expression anchors. Before this step, both plant entry points minted records without a resource, SeedLot.quantity never constrained plant creation, and clones could be reused. R02.3 already qualified reservation/admission/release accounting; retain those guarantees with actual sources.

| Eligible seed source | Existing canonical lot, source genome equals plant genome, source owner equals grower, positive remainder | Production SeedRegistry/GenomeRegistry/CapabilityRegistry integration, mismatches, zero/missing source, finite exhaustion and max quantity |

## Exact admission and consent semantics

`registerPlantFromSource(plantId, genomeId, grower, parcelId, plotId, kind, sourceId)` is the only working admission API. PlantSourceKind is additive: NONE=0 (invalid), SEED=1, CLONE=2. Plot zero selects private admission; nonzero selects public admission and must belong to the supplied parcel. The old source-less methods cannot infer a resource and deliberately fail closed; update clients and deployment smoke tests. No legacy stage value, PlantRecord, SeedLot or CloneRecord ABI is renumbered/replaced. All successful plants retain the existing 1/2/7/7-day lifecycle; this step does not invent a faster clone stage or improved yield.

The source holder calls `approvePlant(sourceId, plantId, parcelId, plotId)` directly on the source registry. There is no general spending allowance. The stored commitment binds immutable consumer deployment, source/plant IDs, canonical genome, current owner, parcel, plot and ownership epoch. Holder-only `revokePlantApproval` deletes it. Every transfer increments the epoch, invalidating old approvals even if the resource later returns to the same owner. Approvals do not reserve inventory; concurrent approved admissions serialize and cannot exceed remaining quantity. They have no automatic expiry; the holder can revoke or transfer, and only the exact immutable consumer/plant/destination may consume them. No signature or service assertion substitutes for the owner transaction.

The capability-authorized issuer may submit a plant for an approved source holder; approval does not grant arbitrary PLANT_REGISTER authority. Private admission still requires effectiveOperator==grower; public admission still requires grower allocation. The bound engine needs SEED_CONSUME or CLONE_CONSUME at bytes32(sourceId), amount one and a valid nonperiodic grant. A holder/issuer with a consume capability cannot burn resources directly because caller must equal the bound PlantRegistry. Each source registry reads sourceContext from that registry and verifies kind/source/genome/grower/destination and approval before recording consumption. Admission has a reentrancy guard; downstream failure reverts the entire transaction, including emitted logs. Retrying a failed operation preserves its approval; retrying a successful plant ID is rejected.

SeedLot.quantity remains original issuance quantity. `consumedQuantity` is total historical consumption and `remainingQuantity` is quantity minus consumed. `seedLotForPlant` records each seed-backed plant. Consumers/markets must use remaining quantity, never original quantity as a spendable balance. A partial lot transfers only its remaining units; historical plant growers are unchanged. Empty lots cannot transfer/approve. Clone consumption is recorded in consumedByPlant and cloneForPlant; consumed clones cannot transfer/approve or create a second plant. Termination releases capacity only; it never restores seeds or clones. Mint/registration histories remain available.

## Events and integration

Existing SeedLotRegistered/Transferred, CloneRegistered/Transferred and plant events remain. PlantSourceApproved includes source/plant/owner/parcel/plot/epoch; PlantSourceApprovalRevoked identifies the cancelled intent. SeedConsumed identifies lot/plant/grower/remainder; CloneConsumed identifies clone/plant/grower. PlantSourceConsumed binds plant/kind/source/grower. PlantRegistryBound identifies one-time resource wiring. Use chain/contract/log identity and canonical finality/reorg recovery under R05. Typed source IDs are registry/deployment-qualified; equal numeric seed and clone IDs are distinct resources. sourceContext is a canonical read, not a transferable claim.

The new IPlantSourceConsumer interface captures reciprocal dependencies and the exact source context. PublicPlot reservations and historical publicPlotOfPlant remain as specified by R02.3. Shared Gaming/Wallet/CapabilityRegistry source, module keys and frozen-address files are unchanged. No monetary custody, token approvals, fee, bridge, signature, randomness or oracle path is introduced. Ordinary guest/service gameplay remains wallet optional in its own authority domain; canonical owner approval applies only to canonical resources.

## Deployment and compatibility

1. Deploy auth/Genesis/regions/genomes/land under existing policy; deploy SeedRegistry(auth, genomes), MotherRegistry and CloneRegistry(auth, genomes, mothers), then PublicCultivationAccess(auth, land).
2. Deploy PlantRegistry(auth, genomes, land, publicAccess, seeds, clones), now requiring six constructor arguments. It validates source registries share its auth/genome dependencies.
3. Issuers grant the bootstrap principal PUBLIC_PLOT_BIND_PLANTS, SEED_BIND_PLANTS and CLONE_BIND_PLANTS at the corresponding BIND_SCOPE. Bind public access, seed and clone registries reciprocally to this one PlantRegistry; inspect code hashes and recorded addresses; revoke bootstrap grants. No admission proceeds unless both resource registries and public access point to it. Binding is irreversible; wrong binding requires replacement.
4. Register approved canonical resources/provenance and plot/parcel records, issue source-specific consumer grants and plant-specific issuer grants. The resource holder approves each exact admission intent. Execute positive/private/public and revoked/mismatch/replay smoke journeys, record transaction/finality/handoff evidence under R07/R09.
5. Replace existing immutable PlantRegistry/source consumers under the R07 reviewed migration/drain policy; never zero consumption or recreate balances during migration. Existing historical plants from earlier deployments lack this source proof and are not silently canonicalized into the new deployment.

New action catalogue entries are SEED_BIND_PLANTS/SEED_CONSUME and CLONE_BIND_PLANTS/CLONE_CONSUME (47 total HC actions). BIND_SCOPE is keccak256("HC.SEED_REGISTRY.PLANT_BINDING") or keccak256("HC.CLONE_REGISTRY.PLANT_BINDING"); binding amount zero, consumption amount one. No broad wildcard or registry consumption authority is delegated. Resource registration/transfer capabilities retain the documented trusted-issuer model, including privileged transfer powers; actual transfers invalidate prior approvals. ABI/binding regeneration is required before clients deploy; production scripts/manifests and generated HC clients remain R05/R07.

## Qualification and remaining scope

This step requires Level 1 source/admission/security/build checks and affected Level 2 retained app integration because it adds an owner-consent/resource/capacity lifecycle boundary. Durable exact-SHA results are qualification/R02.4-level1.json once completed. A rejected Foundry test name beginning testFail was a harness compatibility defect and was renamed without weakening assertions; only subsequent successful exact-SHA results count. Global inventories and accumulated merge reconciliation remain R08 Level 3.

Trusted registrars/issuers must bind reviewed canonical code; reciprocal views and code length do not attest code hashes. Direct deployments have no proxy/storage migration path. Known HC-SEC-08 plant resource-consumption gap is resolved here, while seed breeding provenance and phenotype anchors still require R02.6. Clone issuance still must consume mother budgets under R02.5; a clone consumed here is an approved registered asset, not proof that its creation used a cutting. Emergency gates, sealed rulesets, production transports/indexers and actual testnet deployment remain their canonical later steps. No full-game/security/Genesis/production qualification is claimed.
