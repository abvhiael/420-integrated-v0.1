# R02.6 — canonical plant, breeding and expression provenance

The retained roadmap prohibits opaque, caller-supplied phenotype provenance. Phenotype registration must resolve a real plant ID, require exactly its canonical genome, verify a locked expression from the designated cultivation engine and reject fabricated trait hashes. Optional breeding-event provenance is zero for non-bred/founding genomes; a nonzero reference must be an existing **finalized** breeding event whose child genome matches the phenotype/plant genome.

## Trust and authority

A one-time PHENOTYPE_BIND_PROVENANCE capability, scoped to the registry BIND_SCOPE, establishes the reviewed PlantRegistry, BreedingEngine and CultivationEngine dependencies. Before binding, the phenotype registry checks deployed code presence, matching High Country authorization and genome registry, and the cultivation engine's exact plant-registry address. Deployers must independently attest the reviewed bytecode; address consistency alone is not identity attestation. Subsequent mutating calls require PHENOTYPE_REGISTER by the issuing principal and fail closed when provenance is unbound or nonexistent.

BreedingEngine.childGenomeOfFinalizedEvent requires a nonzero, existing, finalized child identity. CultivationEngine.expressionForPlant returns an expression only after on-contract sealing. PhenotypeRegistry reads the exact canonical plant genome, locked expression hash and (when nonzero) breeding child genome before writing immutable phenotype state. Failure leaves no phenotype.

This step does not change old PhenotypeRecord storage shape or existing phenotype event/registration signature. It does **not** claim R02.7 ruleset identity or permitted lifecycle-stage verification. R02.9 breeding child reservation and entropy timeout are likewise separate requirements.

## Qualification and operations

Relevant checks: Foundry High Country contract build, formatting, security lint, canonical-source integration negative/positive tests, retained app-specific integration/invariants and ABI/type shape verification on an exact commit SHA. The historical genetics unit/invariant fixtures use explicitly named test-only source stubs; actual cross-contract acceptance uses real PlantRegistry, BreedingEngine and CultivationEngine contracts. Accumulated Level 3 and live/testnet deployed code-hash acceptance are deferred to R08/R09; no production deployment is claimed.

Operators must bind approved canonical dependencies once and revoke the temporary binder capability. A replacement requires reviewed redeployment/migration, not mutable reattachment.
