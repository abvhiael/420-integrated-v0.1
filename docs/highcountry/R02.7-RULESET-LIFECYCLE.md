# High Country R02.7 — Ruleset identity/version and plant lifecycle boundaries

Status: implementation candidate; Level 1 evidence is separately recorded on successful exact-SHA CI.

The canonical `RulesetRegistry` derives stable IDs using `keccak256(abi.encode(RULESET_ID_DOMAIN, contentHash))`. A ruleset ID is valid only when registered, its immutable content hash derives that same ID, **and it matches the expression-domain route in the canonical RulesetRouter**. Arbitrary nonzero or differently routed registered IDs cannot seal an expression. The immutable content hash is the versioned content identity: changing rules requires registration under a **new** ID, not mutation of the old one.

The `CultivationEngine` binds the reviewed registry and its reciprocal RulesetRouter only once using `CULTIVATION_BIND_RULESETS` on `RULESET_BIND_SCOPE`; mismatched `authorization`, zero/EOA address, or later rebinds fail. Operators must check deployed code identity before granting this binding, and revoke binder capability after setup.

**Lifecycle decision:** environment telemetry may be recorded on existing living plants in GERMINATION, SEEDLING, VEGETATIVE, FLOWERING and READY. TERMINATED plants cannot be updated. Phenotype expression sealing is permitted **only in READY** and only when an environment snapshot exists; it rejects earlier and terminated stages. Ruleset identity, immutable content hash, genome, environmental dimensions, stress and quality are pinned to the one-time sealing transaction. A failed seal leaves state unsealed; a successful seal blocks update/resealing even if a caller supplies another ruleset. The legacy expression hash encoding remains `HC.PHENOTYPE.EXPRESSION.V1` and retains the registered ruleset ID.

Scope is app R02.7 Level 1 with retained High Country integration/invariant coverage. R02.8 EmergencyState and final R08 phase closeout remain separate. No deployed testnet/live assertion is implied.
