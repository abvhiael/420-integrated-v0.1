# R03.2 — deterministic harvest scoring (Level 1)

Canonical roadmap R03.2: deterministic yield/quality/grade units, integer rounding and environmental/genetic inputs; zero/min/max output. R03.1 seals the canonical genome and quality score from environmental stress. The R03.2 calculation consumes ONLY those sealed canonical inputs during harvest acceptance. Its score is stored once and immutable with the R03.1 acceptance; read via `getHarvestScore(plantId)`, and preview only READY sealed plants through `quoteHarvest(plantId)`.

## Fixed V1 simulation rules

- Quantity unit: **whole game grams** (`uint32 yieldGrams`); **not** physical crop measurement, inventory issuance or real-world botanical prediction.
- The R02 `CultivationEngine` computes `qualityBps = 10000 - stressBps` from six bounded environmental dimensions and seals that quality into phenotype expression.
- Genome ID provides a stable deterministic game modifier: `geneticBps = 9000 + (uint256(genomeId) % 2001)`. Zero genome IDs are invalid; modifier range is 9000–11000 basis points. This is a deliberate simple V1 gameplay policy, **not** independently proven genotype-based productivity, and cannot be changed after a receipt is accepted.
- Base: **500 grams** at full environment quality before genetics. First apply `floor(500 * qualityBps / 10000)`; then `floor(intermediate * geneticBps / 10000)`. Clamp to **1000 grams**. Minimum **0 grams**; very low quality may round to zero.
- Grade: NONE for zero quality or zero resulting grams; otherwise C for quality below 5000; B for 5000–7499; A for 7500–8999; PREMIUM for 9000–10000. A grade cannot be awarded for zero output. Grade depends on sealed environment quality, not mutable caller input.
- All arithmetic uses bounded `uint256` intermediates, floor integer division with no floating point, and typed bounded output. Failure for unsealed, invalid quality, missing or terminated plant is fail closed.

## Release limitations

The numeric V1 rules above are newly defined **simulation constants**, not a claim that existing canonical documentation specified these figures. Their acceptance as official gameplay policy must be reviewed against the R01 frozen parameter/trust design before production use. Do not silently treat an algorithmic genome hash as biologically validated trait data. R03.3 owns actual product provenance, inventory and resource accounting; R03.4 owns capacity release; R03.5 owns journey/adversarial closeout. Level 2 only when the R03 cross-contract milestone requires it and full Level 3 only at R03 phase closeout.
