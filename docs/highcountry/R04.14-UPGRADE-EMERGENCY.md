# High Country R04.14 — UpgradeCoordinator and SecurityCouncilController

Canonical roadmap: `R04.14 — UpgradeCoordinator, SecurityCouncilController`. This implements only the R01.5 approved **versioned direct-contract replacement/rebinding and restricted-emergency controls**. It does not add a proxy, delegatecall, dynamic arbitrary target call, ownership transfer, genesis mutation, treasury operation, or silent service rebind.

**UpgradeCoordinator:** Separate immutable deployment/release authority and independent reviewer. A proposed replacement must identify an existing code-bearing old and new instance, exact on-chain runtime code hashes, a migration plan hash and config/rebind manifest hash. A reviewer other than release authority must approve; after a two-day timelock the release authority may record the acceptance once. Either reviewer or release authority can cancel before acceptance. Old implementation can be consumed only once. Approval records *provenance only*; the coordinator does not change any module routing or other contract's immutable dependency. Actual deployment, drain, snapshot, migration, replay-key preservation, explicit service configuration, frozen addresses, user consent and recovery/rollback are separately authorized R07/testnet operational steps. No stale upgrade or backdoor is inferred from an emitted event.

**SecurityCouncilController:** Fixed different restriction and release officers, immutable validated EmergencyState target, allowlist checked via canonical EmergencyState, immediate restricted writes only by restriction officer, delayed release by separate release officer with restriction-officer veto. EmergencyState must separately authorize the **controller address** for the exact domain and action via the canonical scoped capability registry. The controller cannot grant itself capabilities. Failed authority checks/reverts preserve current restrictions. Controller has no privileged asset transfer or arbitrary target call functionality. In production, actual officer credentials, domain grants, emergency stop/recovery smoke tests, review and revocation are external acceptance items.

**Security invariant:** No arbitrary implementation swap, bypassable release, unchecked domain, unauthorized principal, silent key migration or token movement. Emergency recovery must permit approved exits and refund paths as independently enforced by existing mutating engines. No speculative assertion that R04.14 independently fixes earlier engine admission/control gaps.

**Level 1:** exact SHA, affected High Country compilation and production bytecode limits; scoped Forge formatting and lint; R04.14 authority positive, negative, cancellation, timelock, duplicate execution, invalid codehash and underlying denied scoped permission cases; canonical High Country verifier.

**Level 2:** upgrade/shared emergency authority forms a meaningful integration seam; retained app-focused R04 integration milestone must verify controller capability configuration, EmergencyState consumer effects and session/service paths when available. Do not substitute isolated mock tests for the production deployment acceptance.

**Level 3:** canonical full Solidity inventory once, separate Genesis/address-authority, 420 Integrated/global, global Docs and R04 phase merge/deployment qualification deferred to phase closeout.
