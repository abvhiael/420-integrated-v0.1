# High Country R04.2 — EquipmentRegistry

Status: implementation candidate; requires exact-SHA Level 1 PASS before completion.

Canonical assignment: defined earned equipment types, placement/ownership, catalogue-version-pinned six-control effects, bounded land capacity and immutable protective statistics. No premium or wallet-based statistic multipliers.

Authority model: trusted issuers attest earned equipment using globally unique earning references; an untrusted guest claim or wallet entitlement never authorizes issuance. Administrator approves issuers and registers distinct type IDs with immutable catalogue versions and signed changes to the six gameplay controls. Changes of catalogue require a new ID, not mutating prior effects.

Equipment ID and earning reference are single-use. The canonical LandRegistry effectiveOperator(parcelId) controls placement; equipment owner must be that operator. Equipment capacity is bounded by land growCapacityOf(parcelId), with a positive type slot cost. Placement and removal atomically conserve occupied slots and effect totals. The owner can retrieve equipment if land ownership/occupancy subsequently changes, while prior operator's effects immediately fail authority checks. The view exposes typed effect contributions only; it does not bypass CultivationEngine environment validation and does not invent integration with later client/service modules.

The six controls follow existing HC environmental order: temperature, humidity, light, water, nutrients, airflow. Signed deltas use the corresponding existing control scales; the caller applying them must preserve valid physical/control bounds. No new yield, genetic, quality, BUDS or competitive multiplier exists. No wallet argument participates in type effects or placement.

R04.3 owns manufacturing recipes and queue/cost accounting, R04.4 owns durability, breaks, repairs/recycling, R05 owns authenticated registered-state bridges. R04.1 typed inventory remains independent; issuance attestation is not fabricated by consuming inventory without a reviewed earning mechanism. Future cross-module adapters must preserve existing authority and failure behavior. Live LandRegistry deployment, operator grants, finalized state, and browser integration remain R07/R05 acceptance, not claimed by this code.

Level 1: exact SHA, affected compilation and size, forge formatting/lint, negative/authority/duplicate/land-transfer/capacity/effects regressions, retained inventory tests, ABI and HC verification. App milestone Level 2 after R04.3/R04.4, final Level 3 at R04 phase closeout.
