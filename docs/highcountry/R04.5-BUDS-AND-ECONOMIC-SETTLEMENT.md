# High Country R04.5 — BUDS and EconomicSettlement

Status: service-scoped implementation candidate; the ledger core requires a production durable serializable transaction adapter, trusted source catalogue and authenticated account boundary before launch.

The repository's normative gameplay specification defines BUDS as zero-decimal integer internal game currency, *not* an ERC-20, native $420, bridge currency, or cash redemption instrument. Guests may only maintain local preview balances. Registered economy balances must reside in an independently authenticated durable service domain, not unreviewed browser writes or a newly minted token.

The scoped `BudsLedger` enforces globally unique operation IDs, one-use approved earnings, explicit total issuance/burn sinks, owner available/reserved accounting, exact zero-fee full-fill settlement, cancellation refunds and atomic all-or-nothing failure under an externally supplied serializable transaction adapter. No arbitrary game-play values, exchange rate, premium boost or automatic harvest BUDS values were invented. The `MemoryTransactionFixture` is strictly a test fake and MUST NOT be used with production accounts. The reward catalogue must check independently authenticated proof and source limits; this library alone cannot verify claims.

A PostgreSQL serializable row-lock adapter and a least-privilege migration now exist in `services/highcountry-economy/src/postgres-store.js` and `migrations/001_buds_state.sql`; the production caller must supply an authenticated TLS database pool with scoped SELECT/UPDATE access and provision namespaces separately. Tests use a SQL transaction fixture, not a live production-equivalent database. A configured per-source cumulative issuance ceiling and globally replay-protected proof IDs mitigate reward inflation, while sinks require explicit catalogue approval. Production completion still requires live durable database integration and failover acceptance, authenticated actor-to-account ownership, vetted gameplay reward limits and evidence signatures, and market settlement integrated atomically with the asset book. These are explicit R04.5 launch blockers; the core may achieve Level 1 unit qualification but that cannot be misrepresented as production ready. R04.8 owns the ordinary full-fill asset market; R05 owns durable/authenticated transport and profiles; R07 owns deployment and end-to-end live acceptance. The app-wide Level 3 remains at R04 phase closeout.
