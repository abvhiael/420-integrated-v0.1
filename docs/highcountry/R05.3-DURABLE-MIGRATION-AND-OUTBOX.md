## Implemented authority and transaction model

`migrations/003_migration_runtime.up.sql` creates immutable application and receipt-history records plus durable outbox state. Operator-only mutation privileges, FORCE RLS for every table, and scoped read-only runtime access prevent player session actors from manufacturing an application or receipt. Migration uniqueness independently spans `chain_id, registry, game_id, claim_id`, the chain/registry/game/source commitment+revision and the local account/game/migration ID. Claim-key collision must roll back the destination save publication and profile revision alongside the outbox write.

`src/migration-runtime-migrations.js` applies this additive schema through a migrator-only advisory-locked transaction and checks a source-file digest on repeated application. No destructive down migration is provided. `src/migration-coordinator.js` requires an operator pool and two independently configured adapters: `verifyBoundClaim` and `verifyReceipt`. Neither public HTTP caller parameters nor a process-local map may assert canonical ownership, consumption, binding or finality. Application accepts only an opaque migration locator; the verifier must supply the exact source, chain/registry/claim/target, verified save reference and evidence digest. Missing or contradictory data are rejected.

On application, one SERIALIZABLE PostgreSQL transaction checks the immutable prepared migration intent, active registered account, exact SAVE_MIGRATION consent and scope, active independently linked destination wallet/chain, CLOUD_SAVE consent and scope, registered save schema and profile/ruleset. It then inserts a destination save reference, advances the registered profile revision, writes an immutable migration application and creates one outbox row. The original save reference and all prior revisions remain present. A repeated verified operation returns the original revision without advancing twice; a conflicting alternate claim or source intent is rejected atomically.

The operator outbox leases due work with PostgreSQL `FOR UPDATE SKIP LOCKED`, random lease tokens, a 60-second lease, bounded 12 attempts and durable exponential backoff. Two workers cannot hold the same unexpired lease. Lease loss or process death permits later takeover. Expired final-attempt leases are dead-lettered. Receipt verification is independently injected and bound to the immutable application record. Finalized same-operation receipts close the outbox; reorg/mismatch enters QUARANTINED without deleting a save or starting a second application. All receipt dispositions are appended to immutable history. Unexpected state requires operator review, never arbitrary rewind or duplicate mint.

## Tests and trust limitation

`test/migration-postgres.integration.mjs` runs against isolated PostgreSQL 16 with actual R05.1/2/3 schema and RLS. It tests impersonation/direct writes, concurrent app attempts across separately pooled workers, exactly-once save/claim and outbox, crash of a separate Node worker process, expired lease takeover and stale-token rejection, irrevocable receipt closure, reorganization quarantine, duplicate canonical claim rollback, revoked consent and cancelled intent. Source proof and receipt finality adapters are controlled **fixture authorities**: their behavior is tested as a fail-closed service contract, **not** as production blockchain authentication.

Production/external acceptance remains gated. R05.4 owns real GameClaims issuance/consumption and exact grower binding; R05.7 owns independent canonical RPC/finality, including reorg verification. No service private keys, raw save contents, monetary mint/spend or on-chain migration claim issuance were added. TLS, secrets, live worker credentials, backup/restore and operational incident response remain R07/R10/testnet gates. R05.5 owns save-provider integrity and backup/conflict policy. A malicious verifier cannot be made trustworthy by a `finalized:true` fixture. Do not deploy as independently chain-verified without the real canonical providers and separate acceptance.
