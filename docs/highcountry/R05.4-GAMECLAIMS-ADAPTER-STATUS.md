# High Country — R05.4 GameClaims integration status

**Canonical roadmap step:** R05.4 — real GameClaims issuance/read adapters, target-wallet consumption, grower binding and exact payload validation. Service never holds player private keys.

**Implementation candidate:** `c1f36fc9c6ffaf4357531490d2d3eb4a6535cb86`. **Base:** prior R05.3 evidence `034c6b9e9fe4a7d123e88b83a21f810fde88ed2e`. **Main at earlier reconciliation:** `959288c8bd33b6da0325b6a5d060e00e7bcf0e48`. **PR:** #638, stacked draft, unmerged.

The adapter `services/420-gaming-player-profile/src/gameclaims-adapter.js` calls the deployed ABI function names from `GameClaims420`, `HighCountryGamingBridge420` and `HighCountryMigration420` through injected read and operator transports. It generates canonical migration commitments by calling HighCountryMigration420's actual pure view methods (keccak256/ABI commitments), never substituting SHA3-256 or ad hoc JSON hashes. It reads an existing claim before retrying issuance and rejects contradictory target, game, payload or claim state. Only configured game-operator write transport submits issuance. `consume` and `bindConsumedMigrationClaim` return explicitly scoped **player-wallet** transaction intents; no server-side player keys or impersonation. Binding requires consumed, noncancelled exact target and payload. Reconciliation reads matching grower binding, bridge readiness and markApplied receipt state, rejects mismatch and preserves receipt idempotency. Reads are tagged `canonicalFinality: UNVERIFIED` until independent R05.7 verification.

**Namespace constraint:** R05.3 stores PostgreSQL claim IDs as unsigned 64-bit decimal numbers while deployed GameClaims420 keys are bytes32. This adapter only issues/reads claims in the explicitly narrow zero-left-padded uint64 bytes32 namespace. Arbitrary bytes32 claims cannot be safely represented by the previously-qualified R05.3 schema and must be rejected, not silently truncated or hashed. Expanding this namespace requires a reviewed additive migration with full R05.3 requalification.

An end-to-end target wallet broadcast, GameIdentity profile creation, grower binding and real finalized receipt were not demonstrated. R05.3 coordinator still expects the injected `verifyBoundClaim` authority and will not automatically consume this adapter; a verified finality policy (R05.7) and exact data-to-save mapping are prerequisites to production DB apply. This does not qualify a production migration, real issuer custody, or external testnet readiness. R05.7 will establish independent canonical finality; R05.5 controls save backups and provider reconciliation.
