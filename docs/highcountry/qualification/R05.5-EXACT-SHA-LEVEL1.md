## Additional source hardening at latest implementation SHA

- Restoring an independent backup rechecks the active backup ID, object locator and SHA256 under the final serializable save-revision transaction, preventing a user-deleted backup from being replayed during a concurrent restore.
- Source backup creation rejects previously redacted save revisions. Backup expiry/RLS restrict live locators immediately, independent of worker delay. Deletion jobs are readable only to the trusted migrator, with a terminal dead-letter outcome after bounded retries.
- Physical-deletion workers revalidate live save revisions and unexpired backups immediately before deletion; the encrypted local provider creates random immutable objects. Production providers must uphold immutable object-ID semantics and independent idempotent delete.
- An integrated PostgreSQL + encrypted provider journey backs up a save, redacts and physically deletes the original, and successfully restores from an independent copy into the next revision. Adversarial tests cover tampered ciphertext, cross-provider denial, revoked backup during restore and deleted source replay.
