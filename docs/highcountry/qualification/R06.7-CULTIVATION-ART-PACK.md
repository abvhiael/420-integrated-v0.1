## Integration contract
- `apps/highcountry-web/src/cultivation-art.js` defines the authoritative **UI-only** map for the five playable guest growth states from `src/guest.js` and the five supporting game assets. It uses static filenames, not save-derived URLs.
- `src/app.js` uses the map to render the right illustration for each stage, with meaningful image alt text. If a PNG is missing or fails to load, the existing locally hosted SVG placeholder appears instead; guest play never blocks on an artwork fetch.
- `scripts/build.mjs` includes the manifest module; its existing public-directory copy automatically includes these images once committed under that path.
- Supporting compositions are registered, but not presented as playable equipment/processing screens until the canonical game UI actually offers them. Do not invent gameplay to accommodate images.
- UI art never implies on-chain ownership, an escrow settlement, transferable rewards or finished deployment approval.

This caused an initial mismatch with the deliberately separate draft PR branch and the manifest. Import commit `973572bc366cc935428c638b65ddaee97c474758` reuses **the exact existing Git blob SHAs from main**, under normalized `.png` filenames on PR #654. No resampling or image regeneration was performed.

The frontend `cultivation-art.js` now resolves all five playable stages to committed PNGs. The five supporting assets are committed and registered, without inventing game equipment screens. The legacy SVG fallback remains as resilience during image loading failures.

The added `r067-cultivation-pack.test.mjs` binary checks verify existence, PNG signature and nontrivial size for all ten files. The R06.7 browser build copies `public/assets` into `dist/assets`; exact-SHA CI must pass before declaring the integration qualified.
