# L01.2 — independently authenticated sessions and bounded authorization

Canonical requirement: independently authenticated rider/driver/operator sessions, recovery/revocation, authorization tests. Scope: app-only protected service/HTTP adapters over L01.1; Level 1. Previous implementation/base head eb3f678f8d9576fbcdd6d8cf3b2014195c535110; main 959288c8bd33b6da0325b6a5d060e00e7bcf0e48. PR #633 / build/liftd-l01-1-foundation stays draft/open/unmerged. No shared contract, frozen address, Genesis or canonical issuer code changes.

## Trust model and actual implementation

420Identity remains identity/recovery authority. Use approved pinned RS256 RSA public keys (at least 2048 bits), issuer, kid and audience liftd-api. A separately approved session/grant authority uses a distinct issuer and distinct keys; shared roots fail closed. No private issuer keys or self-issued login path exist in runtime code. Tests generate synthetic keys solely for verifier qualification.

createAuthenticator verifies access signature/algorithm/purpose/issuer/audience and required subject, account, session, device, recovery epoch, JTI and integer issuance/not-before/expiry claims. Access lifetime is bounded to 3600 seconds, with no clock-skew extension. Roles supplied in access credentials or request bodies are not application authorization.

For EVERY protected operation, generate a random challenge and SHA256 digest of the exact access token. The approved session HTTPS client requests authoritative current status, bounded to 30 seconds, signed by the separate pinned session authority. Require the response to bind challenge, token digest, subject/account/session/device/recovery epoch exactly, and active token/session/device states. Do not cache positive status. A prior signed response cannot answer a new challenge. Authority failures, stale/malformed responses, expired credentials, revoked devices/sessions/tokens and old recovery epochs deny access.

Recovery does not mint credentials in LIFTd. The canonical issuer authenticates recovery and issues a new epoch credential; session authority reflects current epoch and revokes old sessions/devices as appropriate. Tests prove old-epoch denial and new-epoch acceptance. Real managed recovery/issuer/device acceptance remains LT-02, not claimed by synthetic evidence.

## Signed assertion contract

JWT header: alg RS256, typ JWT, approved kid only; reject remote key URLs and unknown header fields. Common required claims: iss, aud, sub, iat, nbf, exp, jti, purpose, sessionId, deviceId, accountId, recoveryEpoch. Opaque IDs match ASCII letters/digits/underscore/hyphen, 1–128 characters. Timestamps use integer Unix seconds.

Access purpose: liftd_access. Status purpose: liftd_session_status; additionally nonce, tokenDigest, active, deviceActive, tokenActive and grants. The status provider must derive these from its canonical session/recovery/grant store, not echo requested approval. Each grant has role, actions, exact resource, expiresAt and boolean revoked. Requests contain no requested role or granted actions.

| Role | Permitted capabilities | Additional kernel restriction |
| --- | --- | --- |
| rider | trip.create/read/cancel | Create own account resource; read/cancel actual own trip |
| driver | trip.read/arrive/start/complete/cancel | Must be the trip's assigned driver |
| operator | trip.assign | Exact trip resource and valid independent admission; no private rider/route read |

Resources are exact account:<subject> or trip:<id>; no wildcard grants. Require exactly one active matching grant. Invalid or overbroad grants deny the whole status response. Grant membership is application permission, not driver/vehicle transport eligibility or Wallet signing consent. Operator maps to internal dispatcher only after verified trip.assign authorization.

## Protected service and HTTP boundary

createTripService authenticates before create/read/transition; derives the internal actor from the verified result, never supplied principal/role headers. Check authorization expiry again after delayed reads/admission lookups and before writes. Default pause is true; admission adapter is absent by default, so no actual dispatch/start is enabled. Operator success returns only id/state/revision, not another participant's view.

createHttpHandler is a Fetch-compatible handler, with no deployed listener:
- POST /v1/rideshare/trips: id, routeRef, riderId; signed grant and identity must bind riderId to authenticated subject.
- GET /v1/rideshare/trips/:id: authenticated exact-resource read and actual participant check.
- POST /v1/rideshare/trips/:id/transitions: action, expectedRevision, optional driverId/vehicleId for assign only.

Require strict Authorization: Bearer JWT; ignore proxy user/role headers and reject body role/principal fields. Reject query parameters including URL tokens, oversized bodies (>8192 bytes), invalid JSON/UTF-8 and unsupported routes/methods. Replies use no-store and nosniff; errors expose bounded codes without token/keys/provider details. No cookie-authentication, public route discovery or credential logging is introduced.

The HTTPS session client uses administrator-configured endpoint and scoped service credential, forbids HTTP/userinfo/query/fragment, rejects redirects, validates application/jwt response type, limits payload to 32768 bytes and aborts timed-out requests (default 3 seconds; at most 10 seconds). It sends a token digest and bounded identifiers, not the user's raw access token. Transport injection is server-owned and used only for tests or explicitly trusted infrastructure.

## Persistence and release boundary

Authoritative session/grant/recovery storage belongs to the independently approved session authority. LIFTd fetches signed current projections instead of creating a second identity/session issuer or a positive in-memory authorization cache. Production endpoint/public keys/service credential are intentionally not invented. Without approved configuration, authentication fails closed.

Trip store create/get/compareAndSwap is a required server-owned adapter. Tests use an isolated in-memory store; durable PostgreSQL serialization/replay/idempotency and commit-bound concurrency are L01.4. Access tokens are reusable bearer credentials until revoked/expired; JWT JTI is not a one-use trip-command nonce. The challenge protects status replay, not duplicate trip mutations; command persistence is L01.4. Incident-support permissions and active-trip safety resolution belong to L01.9.

## Exit criteria and gap disposition

| Criterion | Implemented coverage |
| --- | --- |
| Independent signed identity, pinned separate session authority | Real RSA verification, issuer/audience/algorithm/key/purpose checks; forgery/key-confusion tests |
| Rider/driver/operator sessions | Resource grants, bounded role matrix and actual participant checks |
| Session/token/device revocation | Fresh per-request signed current status, nonce/token/session/device binding; reuse after revocation denied |
| Recovery and account binding | Exact account/current epoch binding; old epoch denied, new epoch accepted |
| Protected service integration | Authenticated create/read/cancel/assignment; no request-derived roles; default no live dispatch |
| Failure paths and privacy | Unavailable/stale providers, timeout, malformed/oversized proofs/bodies, privilege escalation, operator redaction |
| Qualification | Retained L01.1 matrix plus L01.2 crypto/service/HTTP/transport tests, all syntax checks, canonical-source verifier, exact-SHA CI and artifact retention |
