# LIFTd L02.11 — Versioned API, SDK and Travel handoff

**Canonical roadmap scope:** Publish versioned interfaces and consuming-app tests. Travel handoffs carry bounded context and require LIFTd authorization and fresh consent. Preserve disabled Genesis transaction boundaries.

## Versioned v1 interface

- `POST /v1/rideshare/trips/:tripId/travel-handoff`: authenticated rider and exact `travel.handoff` trip resource grant; body `{commandId,purpose:"travel_ground_connection",consent:true}`. Returns HTTP 201 with v1 handoff. No broad public context sharing.
- `GET /v1/rideshare/trips/:tripId/travel-handoff/:handoffId`: fresh authorization, trip/revision verification and unexpired **durable consent** required. Returns HTTP 200.
- Error contracts: fail-closed 400 invalid payload, 401 invalid proof, 403 authorization denied, 409 stale trip/consent/replay, 503 unavailable independent owner; no private locations or credentials in errors.
- Version `1.0` response: `version,handoffId,tripId,tripRevision,expiresAt,context`. `context` has **only** `service:"LIFTd",kind:"travel_ground_connection",status:"preview_only",market:"CA-BC-Vancouver"`. No routeRef, driver/rider identity, phone, coordinates, fare, GPS, driver legal status, precise pickup point or payment context.
- `rideshare/sdk/travel-handoff-v1.mjs` validates exact output fields, HTTPS same-origin configuration, signed bearer, no redirects, no credentials and no-store fetch.
- `rideshare/consumers/travel-handoff-v1.mjs` is an independently callable Travel-side consumer using only the v1 SDK. It re-verifies handoffs, bounds expiry, and outputs a **not-live preview** with `bookingEnabled:false` and `transactionEnabled:false`. It does not acquire any Genesis transaction ability, invoke Wallet, Pay, Swap, on-chain route or local signing.

## Consent, privacy and security

`travel.handoff` is added **only** to rider capabilities, and L01 independently signed session status still owns each permission. The handoff service checks actor/account/device/session/recovery binding twice, exact trip ownership, trip state REQUESTED/ASSIGNED/ARRIVED and monotonic trip revision. The user must expressly opt in to the bounded handoff *for this invocation*; remembered marketing, trip notifications, public Travel search or browser query parameters do not count as consent.

`rideshare/migrations/011_travel_handoff.sql` and `rideshare/src/postgres-travel-consent.mjs` implement a private durable receipt, binding actor/account/session, trip ID/revision, exact purpose, idempotency key and expiry. PostgreSQL transaction locks the canonical trip snapshot before issuing the receipt and refuses revision/ownership changes. Existing receipts and command history are immutable; the non-owner runtime may insert and read but not update/delete. `createInMemoryTravelConsentFixture` is test-only; never a production authority.

There is **no external production delivery or booking** in this step. The independently deployed Travel consumer must use LIFTd's live protected v1 service and accepted identity/provider credentials before it can be released. Test-only fixture and SDK wiring are not deployment acceptance.
