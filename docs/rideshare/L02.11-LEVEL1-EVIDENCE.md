Contract/integration tests verify SDK `verify` delivery, authenticated trip ID, signed-origin bearer transport, expiry, exact bounded preview and denial of forged or expanded fields. Consumer always sets `bookingEnabled:false` and `transactionEnabled:false`.
3. **Bounded context and consent:** v1 context has only `service,kind,status,market`. No coordinates, routeRef, personal identity, vehicle, fare, payments or document identifiers. Signed, rider-only `travel.handoff` permission scoped to `trip:<id>` and current account/device/session/recovery epoch is required; explicit `consent:true`, exact purpose, idempotency key, fresh authorized trip ownership, active supported trip state and matched trip revision are mandatory.
4. **Durable replay/expiry:** migration `011_travel_handoff.sql` and `postgres-travel-consent.mjs` create immutable actor/account/session/trip/revision/command/purpose/expiry receipt. Canonical trip snapshot is row-locked before write, unique command prevents conflicting replay, non-owner runtime cannot UPDATE or DELETE evidence. Verification checks receipt's original account and session to prevent same-rider session reuse. A test-only in-memory fixture is explicitly not a production store.
5. **Genesis transaction boundaries:** no Genesis contract, chain state, Wallet/Pay/Swap/signing route, transaction broadcast or automatic booking changed or enabled; consuming-app preview returns non-live status and disabled booking/transaction capabilities.
