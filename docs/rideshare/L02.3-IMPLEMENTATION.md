# LIFTd L02.3 — Pickup and destination entry

Canonical scope: address/place search; explicit location permission; manual entry; pickup clarification; route preview; recoverable provider failures.

The authenticated rider preview uses `rideshare/web/pickup-view.mjs`, controlled by `pickup-controller.mjs` and validated by `pickup-policy.mjs`. Device geolocation is **never** invoked on mount, search or preview: only a user-selected location button may call the injected `geolocate` provider; denial preserves manual entry. Search is opt-in after typing and request-specific; stale results cannot replace newer input. Returned suggestions are allowlisted, bounded and rendered through `textContent` to avoid provider HTML injection. Manual typed addresses remain usable when search or location APIs fail. Pickup and arrival clarification inputs are retained only in component memory and not automatically uploaded or logged.

Route preview requires verified coordinate resolution for both entries and delegates route computation to an independently supplied adapter; a provider outage becomes a recoverable UI state, never invented route metrics or an assertion that rides are live. `L01.5` remains the canonical off-chain Location route, private storage, signed proof, scope and retention owner. The same-origin `location-providers.mjs` adapter now calls canonical `L01.5` Location `POST /v1/rideshare/routes` using the independently provided active rider session, ephemeral bearer token and unique command ID. Explicit user-triggered browser geolocation is supported, while live place search/geocoding still requires independent approved provider injection; the UI must not independently claim authority, estimate fares, or book rides. The existing Vancouver pilot and no-live-payments notice remain in force.

Level 1: exact-head Node 22 scoped workflow, malformed-input/permission-denial/manual-fallback/stale-search/provider-error/route-preview negative tests, structural accessibility and retained L02.1/L02.2 web suites. Level 2: app integration milestone. Level 3: phase closeout once on then-current main. Independent mobile/assistive-tech tests and approved location providers remain external acceptance gates.
