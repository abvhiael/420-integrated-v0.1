# LIFTd L02.4 — quote and ride request

Canonical requirement: display the **complete authoritative fare, expiry, cancellation terms and payment state**, require explicit rider consent before submission, prevent duplicate requests.

The rider UI is built from `quote-view.mjs`, `quote-controller.mjs`, `quote-api.mjs` and `quote-policy.mjs` inside the authenticated L02 rider shell. It consumes L01.7 quote issue/consent and L01.4 trip create APIs, never computes its own payable fare, and never treats route-preview metrics as a quote. The entire authoritative CAD fare breakdown, tax/pass-through line items, quote expiry, policy version and cancellation fee/active-trip obligations must exist before the submit control is enabled. Unknown/incomplete, mismatched or expired quote payloads fail closed. Payment remains explicitly **not confirmed**; trip creation is not a payment capture.

An unticked explicit consent checkbox prevents request submission. The controller binds the exact quote hash, total CAD cents, rider/session/account/route, checks expiration before and after consent, and passes a stable unique command/trip ID to the canonical HTTP API. Double-click/in-flight duplicates are blocked; retries preserve the same identity instead of accidentally creating a second booking. L01 quote consent and durable trip command idempotency remain authoritative.

No new L01 authority or money calculation is introduced. The UI remains a non-live preview until independently approved provider/runtime wiring and passenger transport legal acceptance. Browser/device accessibility, real Wallet/Pay state projection, operational approvals, multi-instance frontend acceptance and full cross-app integration remain later L02 milestones/Level 3/testnet gates.

Level 1 runs the L02.4 exact-head Node 22 workflow and retained L02.1–L02.3 web suites. Evidence-only commits inherit the exact qualified implementation SHA.
