# LIFTd L02.6 — Driver onboarding

Canonical scope: **driver/vehicle submission, eligibility status, document lifecycle and remediation, protecting sensitive onboarding material from public discovery.**

## Delivery and ownership

- The independent L01 signed-session Identity authority grants `onboarding.manage` to the driver and `onboarding.review` to the separately authorized operator. A driver cannot call the reviewer endpoint. Session revocation/expiry and account/driver scope are checked server side.
- `rideshare/src/driver-onboarding.mjs` validates driver, vehicle and bounded document metadata; binds each opaque private-vault receipt to driver/account/vehicle/document class/expiry through an injected independent `verifyPrivateReceipt` contract, checks session authority again before write, and only transitions new/updated applications to `REVIEW_REQUIRED`. Expired or unverified receipts fail closed.
- `rideshare/src/driver-onboarding-review.mjs` accepts operator-only decisions after `verifyIndependentDecision` verifies a separately issued, revision-bound driver/vehicle/transport attestation. Only that authority can produce `REMEDIATION_REQUIRED`, `REJECTED`, `APPROVED` or `REVOKED`; the domain independently checks evidence binding and bounded remediation codes. This is a **consumer of**, not a substitute for, external Registry/transport decisions.
- `rideshare/src/postgres-driver-onboarding.mjs` and `rideshare/migrations/008_driver_onboarding.sql` persist private onboarding records and unique commands using transaction-scoped locks and revision-based CAS. Real PostgreSQL 16 tests cover stale updates, duplicate commands, concurrent writes, private internal recovery and browser projection redaction.
- `GET/POST /v1/rideshare/drivers/:driverId/onboarding` and `POST /v1/rideshare/drivers/:driverId/onboarding/review` are opt-in protected endpoints. Public trip/discovery APIs do not return onboarding content. Browser `driver-onboarding.mjs` displays status, remediation and expiry without returning private storage references, and never accepts file bytes or claims approval.

## Security and privacy invariants

No raw identity/licence/insurance/vehicle documents or bearer proofs in browser localStorage, query strings, public event streams, Indexer, discovery or the chain. Private receipts are server-owned opaque references, accepted only after independent vault verification; sensitive document bytes belong to encrypted private vault storage under operator-approved access and retention policies. Reviewer decisions require independent signed/verified legal authority, never a client-provided boolean. Review data and access must remain audit logged inside the approved server. The backend returns redacted document type, expiry and status only.

## Level 1 and remaining acceptance

Scoped Level 1 tests check malformed documents, expiry, duplicate kinds/commands, role/account denial, vault verification, reviewer-attestation mismatch, forged status, remediation, redaction, real PostgreSQL transactional concurrency/replay and retained L01 auth/L02 web regressions. CI uses exact-SHA Node 22 and isolated PostgreSQL 16. Completion evidence is recorded separately after a successful run.

**Deployment/testnet gates:** the real vault receipt issuer/verifier, secured credential storage, independent transport/Registry reviewer attestation verifier, audit access logging, operating transport authorizations, actual live driver/vehicle eligibility and independent device/accessibility evaluation require integration and external proofs. The repository step does not itself grant real-world operating permission.

**Level 2:** meaningful cross-component driver onboarding/Identity/Registry/Compliance integration milestone; not full global inventory. **Level 3:** one complete Phase L02 current-main exact-SHA reconciliation and canonical Foundry/Genesis/Integrated/Docs qualification.
