# LIFTd L02.7 — Driver availability and authoritative offer lifecycle

**Canonical scope:** Online/offline driver control; freshness and capacity; offer countdown; accepted/rejected responses; reliable fail-closed disconnect/retry behavior. This is an implementation record, **not a Level 1 PASS certificate**.

## Authoritative backend

- `rideshare/src/dispatch.mjs` retains independent driver session, eligibility, vehicle capacity, pause and transactional assignment authority. It supports acknowledging an offered lease **without changing trip state to ARRIVED**; `arrive` tolerates an already acknowledged lease. Pending or acknowledged but unarrived offers that pass the assignment deadline can be closed through canonical operator expiry; no indefinitely blocked accepted offer is treated as valid.
- `rideshare/src/driver-offers.mjs` provides driver-scoped authoritative availability and offer projections, with private `GET /v1/rideshare/drivers/:driverId/availability`, `GET /v1/rideshare/drivers/:driverId/offers`, and `POST /v1/rideshare/drivers/:driverId/offers/:offerId/response` through `rideshare/src/http.mjs`.
- The server uses independent signed-session `offer.read` and `offer.respond` grants, trip ownership, vehicle/account matching and fresh independent eligibility/transport proof before offer acknowledgment; no offer is fabricated from browser state.
- **Accept:** transactionally locks the existing trip before global dispatch selection, checks PENDING lease, availability revision/expiry, assigned driver/vehicle, pause and independently verified session/eligibility/capacity; changes lease to ACCEPTED without advancing the trip. Stable command IDs and `liftd.offer_commands` provide durable exact-payload replay and reject mismatched retries.
- **Reject:** separately authorized `offer_reject` domain action handled by the canonical L01 trip store. It atomically records an audited revision/event, closes the lease and returns a rider-visible CANCELLED trip result. Quote cancellation assessment and Pay timing use canonical `cancel` semantics. **This intentionally does not promise automatic rematching.** The current schema supports one lease per trip, so a rejection results in an explicit cancelled request; a future rematch/reoffer architecture would require separate canonical design and financial/lease evidence.
- `rideshare/migrations/009_driver_offers.sql` adds immutable offer command history and permits audited offer-reject event classifications. It does not relax transport admission or private document approval.
- Existing L01 client/server/SQL controls remain authoritative. Operator expiry, driver rejection, rider cancellation and actual accepted arrival remain distinct events.

## Driver client

`rideshare/web/driver-availability-{policy,controller,api,view}.mjs` and the protected driver workspace provide verified availability read, explicit first-time vehicle input (validated server-side for admission before match), online/offline revision-CAS commands, server-issued countdowns, pending-only responses, stale/foreign denial, single-flight and stable retry IDs, disconnect fail-closed and refresh/reconnect. Online status is **not** proof of legal driver or vehicle eligibility; independently signed transport checks are still required.
