# LIFTd PT-11 — Deployment and testnet handoff

**Repository scope:** complete offline, fail-closed preparation of an isolated nonproduction deployment, **not** a deployed, credentialed or accepted testnet. Canonical L03.9–L03.12 and TN-0–TN-6 remain unchanged and NOT ACCEPTED.

## Implementation and handoff requirements
- `rideshare/deployment/kubernetes-testnet.disabled.yaml` — hardened Kubernetes Namespace, zero-replica internal-only Deployment, dedicated ServiceAccount with automount disabled, secret-store CSI managed mount, nonroot read-only container, no privilege escalation, exec localhost readiness/liveness probes and deny-all ingress/egress NetworkPolicy. The image and CSI provider are nonfunctional examples. No production Service or Ingress is included. Actual deployment must add independently reviewed egress allowlists for the intended provider/DB/telemetry network endpoints; the default-deny template will not connect to any provider. The managed SecretProviderClass is external and must enforce file owner/permissions compatible with `0400`; it cannot be invented from repository code.
- `rideshare/scripts/start-admitted-runtime.mjs` — strict managed runtime config pathname and file permissions/size validation, then existing loopback-only admitted runtime; `probe-admitted-runtime.mjs` — local Node exec health checks, denying malformed/unready responses.
- `rideshare/deployment/testnet-manifest.template.json` — inert nonproduction template only. Operator must replace the all-zero release placeholder, example image digest, configuration and policy placeholders with approved immutable digests. This template MUST NOT be deployed as-is.
- `rideshare/src/testnet-deployment-handoff.mjs` — validates exact testnet environment, SHA-pinned image, app release, immutable config digest, isolated namespace, one replica, nonroot/read-only filesystem, no privilege escalation, no service-account token, no host networking, **no public ingress/routes**, and **all dispatch, payment and passenger flags disabled**. Requires seven distinct `/run/secrets/...` managed-mount references: runtime config, Identity, Registry, transport trust, DB CA, audit sink and telemetry sink. Requires loopback liveness/readiness on port 8080 and private strictly redacted observability with pinned policy digest.
- `rideshare/src/deployment-security.mjs` — existing runtime config validation for authenticated TLS origin, PostgreSQL verify-full, least-privileged DB role, distinct key digests, pinned release, disabled public traffic. PT-11 handoff cross-checks its redacted attestation against deployment manifest when runtime config is independently provided.
- `rideshare/src/admitted-runtime.mjs` — existing loopback-only GET `/internal/live` and `/internal/ready`, database schema/migration/role readiness, zero trip/payment endpoints and 503 fail-closed status on unavailable providers. Private health routes must never be published at ingress.
- `rideshare/scripts/testnet-handoff.mjs verify <manifest>` — produces a nonsecret config manifest digest. `capture <manifest> <redacted-health-json>` — accepts only strict redacted `readiness`, `observation`, `now` fields; returns hashed evidence with `independentAcceptance: NOT_ACCEPTED`. It does not fetch remote URLs or issue release authority.
- `rideshare/test/testnet-deployment-handoff.test.mjs` — negative tests for enabled payment/dispatch/passenger/ingress, mutable images, privilege escalation, duplicate or untrusted secret refs, unhealthy/forged readiness, telemetry leakage and audit evidence. Reuse existing deployment runtime and app tests.

## Operator wiring sequence (NOT yet deployed)
1. Independently establish the testnet provider, infrastructure owner, reviewer roles, network identities and encrypted evidence custody (TN-0). Obtain actual, distinct provider-signed credentials and managed secret refs (TN-1).
2. Build/sign immutable image and verify digest, pin exact qualified application and config digests, enforce isolated network policies and deny all ingress/public routing; only management-plane loopback probes may reach the health endpoint.
3. Mount separate managed Identity, Registry, transport, database CA and append-only audit/telemetry sink credentials. Validate independent issuer fingerprints and database role, network TLS chain, readiness and service-to-service deny/allow lists.
4. Execute provider disruption, revocation, compromised-secret rotation, health endpoint, failure-safe recovery, monitored telemetry/redaction, evidentiary chain and live integration scenarios (TN-2–TN-4); collect immutable receipts, run/job metadata, response digests and timestamps. Do not place personal, credential or location data in Git.
5. Independent security, privacy, transportation and accessibility authorities must sign TN-5 acceptance and separate TN-6 production approval before enabling anything. Mere successful local verification is NEVER a release signal.

## Known boundaries
The JSON manifest is an **abstract deployment contract**; the Kubernetes YAML is a **deliberately disabled reference workload**, not a provisioned or production-ready cluster release. No managed services, credentials, infrastructure or actual external routing are provisioned by this PR. Site-specific infrastructure templates and security policies must be authored and independently reviewed when the destination/testnet operator is selected. Instrumented runtime telemetry, signed third-party health receipts, encrypted custody and real end-to-end evidence require the actual testnet. These are existing TN-0–TN-6 obligations, not local PASS claims.
