### Source-reviewed high/medium diagnostic dispositions

| Detector, root function | Review conclusion and enforced boundary |
|---|---|
| `arbitrary-send-eth`, `SmartAccount420._call` (appears in Account and Factory import graphs) | Intended owner-controlled arbitrary payment/contract execution. `execute` and `executeBatch` enforce owner or configured EntryPoint, `executeSession` enforces EntryPoint, active session, per-call grant/scope and registry consume. Not an unprivileged arbitrary send. |
| `reentrancy-no-eth`, `EntryPoint420.handleOp` (two call-graph reports) | `nonReentrant` sets `_entered` before untrusted validation and account execution, remains locked through paymaster postOp and settlement; hostile callback and no-double-settlement regressions passed. |
| `incorrect-equality`, `CapabilityRegistry420._currentUsage` | `periodIndex == index` is the necessary equality for aligned fixed-period quota accounting. `consume` resets on period change and reverts on overflow. |
| `unused-return`, `SmartAccount420.executeSession` | `CapabilityRegistry420.consume` returns only the resulting period usage, *not* an authorization boolean; all invalid-grant/over-limit paths **revert**. Ignoring the numeric result cannot bypass grant enforcement. Appears in both Account and Factory source graphs. |
| `uninitialized-local`, `EntryPoint420.handleOp.sponsorship`, `EntryPoint420._settleSponsorship.callbackSucceeded` | Solidity zero-initializes memory structs/bools; zero sponsor indicates unsponsored path, `callbackSucceeded` becomes true only after nonreverting advisory postOp. |
| `uninitialized-local`, `WebAuthnClientData420.verify.seen`; `P256WebAuthnVerifier420._base64url32.o` | Solidity zero-initialized bitmask and allocated output buffer; WebAuthn signed JSON security fields were previously regression-tested. |
| `uninitialized-local`, `SmartAccount420._validatePasskeyUserOp.credentialIdHash` and `assertionEnvelope` | Variables set only by successful decoding external self-call; `catch` returns validation failure. Both imported into Factory analysis as well. |
| `uninitialized-local`, `SmartAccount420._authorizeCallSet.uniqueCount` | Solidity zero-initialized counter, then incremented while collecting unique capability grants; duplicate grant aggregation is covered by policy fuzz tests. Imported into Factory analysis. |

**Gate policy:** The exact observed detector + function + diagnostic fragment is reviewed with a concrete reason. The focused workflow fails on any unexpected high/medium diagnostic, missing source-security invariant, changed diagnostic count, failed compilation, or missing target. The allowlist does **not** waive high/medium detectors globally, and no Solidity authorization assertion was weakened to make it pass.
