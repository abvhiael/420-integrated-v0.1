# W15.5 — Wallet Web UX and Accessibility Qualification Matrix

## Scope and evidence
This phase qualifies the wallet web *source and automated checks*. GitHub CI validates the Node tests, static build/qualification scripts, and shared Wallet Core integration. It does **not** substitute for real-browser accessibility evaluation, full assistive-technology testing, a live network, or real Android/iOS devices.

## Completed source hardening
- Keyboard activation of navigation scrolls to and focuses the requested section, including dynamically inserted session/passkey/recovery sections. Hidden sections remain inaccessible.
- Scroll animation respects reduced-motion preference. Side navigation is keyboard focusable and horizontally scrollable at constrained viewport sizes.
- The shared status region announces copy failure/success; unavailable or denied clipboard access no longer fails silently.
- The guided transfer preview and Receive status have atomic polite live announcements; no alternate transaction authority is added.
- Contrast checks assert the principal token pairings (normal text >= 4.5:1). These tests do not cover composited gradients, browser defaults, or every dynamically injected component.
- CSS adds resilient min-width/word wrapping, narrow-screen cards and transaction review wrapping at 360px and below.

## Required manual release acceptance (NOT completed by automated tests)
| Scenario | Matrix | Required result |
| --- | --- | --- |
| Desktop | Chrome/Edge/Firefox at 1280, 1440, 1920px, 100% and 200% zoom | No lost controls, text cutoffs, horizontal page scroll or overlapping sticky status |
| Tablet | Safari/iPadOS and Chromium 768 and 1024px, portrait/landscape | Sidebar scroll, cards reflow, safe account/address display |
| Mobile | Safari iOS and Chrome Android 320, 360, 375, 390px widths | All primary controls reachable without two-dimensional page scrolling; 44px targets |
| Keyboard only | Tab/Shift+Tab, Enter, Space, Escape and dynamic feature navigation | Visible focus, logical order, focused destination, no traps |
| Screen reader | NVDA/Firefox, NVDA/Chrome, VoiceOver/Safari | Meaningful headings/labels, correct live-status announcements, disabled/unavailable controls explained |
| Color/vision | Automated contrast plus manual gradient/hover/focus/disabled-state inspection | WCAG 2.2 AA contrast and non-color cues |
| Error recovery | Unconfigured chain, wrong chain, rejected connect, unavailable clipboard, manifest failure, simulation rejection, reorg | Honest, actionable error; no false confirmation or available link |
| Wallet Core | Confirm exact-head Web + Extension + Mobile CI; live testnet after deployment | Owner authority, nonce/epoch, simulation, receipt and permission gates unchanged |

## Release boundaries
- No automatic **W15.5 finished** designation until manual/browser AT and responsive checks are recorded with evidence.
- Live network/contract/service verification remains unavailable until approved deployment manifests and testnet execution provide actual proof.
- No connected-dApp origin inventory or disconnect control is promised without an authoritative provider.
