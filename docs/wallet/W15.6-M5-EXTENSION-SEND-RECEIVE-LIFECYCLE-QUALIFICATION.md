## W15.6-M5 offline verification evidence and procedure
- **Real Chromium QR parity:** `wallet/extension/scripts/qualify-popup.mjs` renders the packaged extension's actual Receive canvas, extracts pixels via Canvas2D and decodes them with the independent `jsqr` package. The decoded payload must exactly equal the verified `#receive-address` value; visible chain-context copy is also asserted. The `wallet-extension-popup.yml` workflow installs `playwright jsqr`, runs Chromium, onboarding and packaged-extension checks, and uploads screenshots. This tests *generation and scanning parity*, **not camera-scanner functionality** (no receive camera scanner is implemented).
- **Node adversarial security regression:** `wallet/web/test/w15-6-m5-adversarial-security.test.js` exercises wrong-chain and post-preflight chain switches, simulated execution reverts, insufficient maximum-fee balance, stale pending nonces, malformed calldata, invalid fee caps, unqualified recipients and recipient-snapshot tampering. It attacks EOA retargeting, replacement nonces/fees/calldata, ERC-4337 full-nonce lanes/EntryPoint/caps, and mismatched or failed UserOperation receipts.
- **Additional suites:** `w15-6-m5-receive-qr.test.js`, `w15-6-m5-fee-names-replacement.test.js`, `w15-6-m5-eoa-signing.test.js`, `w15-6-m5-userop-gas.test.js`, `w15-6-m5-extension-transaction.test.js`, `w15-6-m5-max-amount.test.js`, `w15-6-m5-address-book.test.js`; run as part of `wallet/web` Node tests.

- Never send imported EOA keys or passkey secrets to any RPC, website, backend or analytics endpoint.
- Wrong-chain, stale epoch, missing contract and no verified execution authority fail closed.
- A pending transaction or UserOperation must never be silently rebroadcast.
- No production-ready or completed-phase signoff until independent qualified evidence exists.
