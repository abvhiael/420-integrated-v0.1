## Qualified limitations and release boundaries

- The real deployed EIP-1271 contract implementation supports owner ECDSA only; passkey EIP-1271 authorization cannot be fabricated by a client. Undeployed EIP-6492 wrappers need an independently qualified validator and must never execute an arbitrary supplied factory.
- Actual UserOperation broadcast, bundler gas validity with genuine signatures, on-chain atomic rollback/receipt/finality, EOA signing and SmartAccount passkey device ceremonies remain subject to the *already-existing* W15.9 live-testnet/W15.10 independent release gates. Offline EIP protocol tests do not convert those gates to PASS. Existing Phase 5 deferred work ledger: [W15.9-M5](W15.9-M5-TESTNET-DEFERRED-WORK-ROADMAP.md).
- The unrelated `420bet-poker-5a-4-level1.yml` failure is not Phase 6 Wallet protocol evidence; report repository-wide CI honestly.
- Do not weaken origin isolation, vault encryption, passkey device binding, WebAuthn security, supported chain manifest, explicit approval or review revalidation for dApp compatibility.
