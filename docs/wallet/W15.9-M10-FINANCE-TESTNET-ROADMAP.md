# W15.9-M10 — Swaps, bridging and staking external qualification

**Origin:** W15.6-M10 software integration. **Status:** gated by approved deployments, genuine liquidity and cross-chain settlement services; independently reviewed under W15.10.

The extension's Phase 10 interface and signing pathway are offline software work. No RPC mock, unsigned quote, stored provider record, source bridge receipt, or indexer projection constitutes live swap, destination delivery or staking revenue.

## Required live acceptance

| ID | Gate | Evidence and acceptance |
| --- | --- | --- |
| W15.9-M10-01 | Approved swap liquidity and provider identity | Deployed canonical 420Exchange/420Swap market, pool, router, route registry, capability, code hashes and executable routes resolved from independently approved runtime; separately approved third-party adapters must have matching verified deployment, spender and chain |
| W15.9-M10-02 | Swap quotation and settlement | At least two real quote routes when available; slippage, impact, exact-in/amount-out, fees and actual token balances reconciled against current on-chain state; stale, revoked or liquidity-deficient quotes fail closed; distinct network/provider costs explicitly disclosed |
| W15.9-M10-03 | Allowance and signed EOA / ERC-4337 settlement | Existing allowance, exact-amount approval receipt, explicit second review and swap authorization, qualified EOA/hardware or passkey SmartAccount execution, target simulation and canonical logs/receipt; abort when chain/account/nonce/code/fee/market changes |
| W15.9-M10-04 | Source bridge deployment and direction | Canonical source asset, route ID, approved adapter, route and risk/settlement health, source gas/fee and outbound authorization verified live; successful finalized source receipt with one matching OutboundInitiated event |
| W15.9-M10-05 | Destination proof and settlement | Approved destination EIP-155 network/fingerprint, gateway, adapter, transfer registry, canonical finalized InboundAccepted event and matching persisted source message, asset, sender, recipient, amount and transfer ID; independently establish the actual beneficiary transfer rather than inferring payout from gateway events |
| W15.9-M10-06 | Recovery and adversarial cases | Real source/destination reorg, reverted/paused routes, expired proof, replay, source-vs-destination disagreement, destination indexer outage, explicit governance-approved retry/refund/compensation and no duplicate movements; no automated retry without canonical state |
| W15.9-M10-07 | 420Stake applicability | Verify deployed 420Stake validator registry facade, bond/credit/withdrawal/reward state and policy; genesis public delegation is disabled. Enable no user-facing delegation or reward claim unless a separately qualified on-chain operation actually exists |
| W15.9-M10-08 | Security and release | Independently audit finance execution identities, adapter and signer boundary, quote replay/TOCTOU, allowances, slippage, gas and third-party provenance under W15.10; retain exact main SHA, testnet network/contract fingerprints and redacted receipts |

The browser UI must remain fail-closed when the configured provider deployment or required 420Integrated service is unavailable. Complete source/destination state cannot be manufactured by setting a local transaction status.

**Prior-phase dependency:** W15.9-M9 records genuine Ledger/Trezor device and live-signing acceptance; hardware-account finance execution requires those gates before production deployment.
