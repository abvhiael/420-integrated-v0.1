## Consensus findings

CURE uses **1,000,000 base units per CURE**, not the eight decimals used by POT/BTC. The existing unspecified base-unit configuration is now explicit. Block/transaction hashes are SHA256d; native transaction serialization includes nTime after nVersion and a CompactSize-prefixed `strTxComment` after locktime. That comment is part of the txid. Genesis includes `text:curecoin genesis block`.

PoW is allowed through height 257322, and forbidden above it. PoS existed during the hybrid era; the adapter's existing PoS-only credit policy is preserved. Effective target spacing changes from 600 to 240 seconds when the parent height exceeds 257322 (first candidate 257324). The native 4-hour retarget uses the previous two blocks of the same type, with the work-spacing gap rule and 7200-second work cap. Unlike POT, negative actual spacing is not replaced by a positive fallback. Nonpositive targets cannot establish a valid stake.

PoS target limits are the work limit through 14060, the harder `2^226-1` limit through 15000, then `2^232-1`; version >=3 is required above 14060, maximum supported native block version is 4. The entropy source changes at 9689 from the high bit of Hash160(block signature) to the low bit of the block hash. Modifier interval is six hours, with the native 64-round selection algorithm and hardened checksum checkpoints.

The kernel preimage is little-endian uint64 modifier plus uint32 origin-block time, transaction offset relative to block start, origin transaction time, output index and stake time. Eligibility applies source block age and input provenance, with ten-block coinbase/coinstake maturity. Weight is `amount * (min(elapsed,90 days)-minimumAge) / 1e6 / 86400`. The comparison accepts **equality**. The weighted target is unbounded in native CBigNum arithmetic; the EVM implementation handles products beyond uint256 without wrapping. Kernel weight is not the separate wallet GetWeight helper's different cap/subtraction order.

Minimum age changes from 30 to 4 days through mutable native globals. In a fresh sequential replay the kernel at 257324 still observes the old age before GetCoinAge mutates the global; a restarted client can observe the new value earlier. The state leaf therefore authenticates the **actual minimum-age replay context**. It is not guessed solely from height. Genuine fixtures preserve that distinction. Clock drift is two hours; MTP uses eleven parent blocks. Block signatures use coinstake output **1**, not POT's first P2PK output anywhere after index 0. Compressed, uncompressed and valid hybrid SEC1 encodings are checked; native high-s signatures are supported.

PoW contributes **one** chain-trust unit, while PoS contributes `floor(2^256/(target+1))`. Selection is strictly greater accumulated trust, with ties retaining the existing chain. The native blacklist, hardened checkpoints, synchronized-checkpoint policy, scripts, rewards and all-input spent-state checks remain enabled in native replay. Research/folding reward distribution outside consensus remains outside this bridge boundary, as required by the existing interface.

## Authenticated replay integration

`CurecoinFinalityVerifier420` reuses existing `AuthenticatedCheckpoint420`. Governance configures the native replay authority and its checkpoint root; checkpoint advance signatures bind the destination chain, registry, network, authority epoch, height/hash/root and predecessor. Authority rotation invalidates the current usable checkpoint until a fresh advance. The EVM verifies authenticated state membership, native header hash, target/trust arithmetic, stake origin serialization/amount/script/age/maturity, kernel, coinstake inclusion and block signer, then deposit inclusion, output, destination and replay identity.

**UTXO unspent state, modifier ancestry, complete script/reward validity and canonical greatest-trust history depend on the configured native replay authority. A compromised authority can falsify replay-only facts.** This is an explicit trust dependency, not an RPC-finalized boolean and not a native validator/quorum certificate. The native source has its own hardened and synchronized checkpoint mechanisms; the bridge authority is not represented as that native checkpoint master key.

`scripts/curecoin/native_replay.py` starts a fresh offline native mainnet node from raw bootstrap bytes, with `-assumevalid=0`, staking/generation/listening/DNS discovery disabled and zero peers. It never loads archive indexes or wallets. Resume requires the hash-pinned lineage of its own previously validated data and retains preceding native trace hashes. The full raw bootstrap is reoffered on resume, including when the native client renamed a partial import to `.old`. Native checked prefixes are preserved, not silently discarded or relabeled as a single binary run.

The audited local build retains native consensus decisions and uses two memoizations: immutable checkpoint ancestry (cleared when the anchor changes), and modifier selection hashes within one computation. Profiling identified verification cost; the optional pinned libsecp256k1 v0.7.1 fast path normalizes high-s and retains the original OpenSSL fallback for every unaccepted parse/verification result. A 10,000-case differential comparison covers compressed/uncompressed keys, low/high-s signatures, malformed/trailing DER and signature mutations. Source/build/dependency pins, the exact patch and native lineage are retained. Ordinary script verification is not skipped.

`scripts/curecoin/qualify_history.py` independently derives canonical ancestry, target rules, stake modifiers/checksums, every kernel/signature and UTXO projection. Native replay supplies full ordinary-script/reward validation. The index/replayer accepts explicit tips, heights and requested transaction/output samples for later evidence; the historical qualification default is hardened checkpoint 500000. `bundle.py` requires pinned native/history report hashes, checks their agreement and the entire sealed proof-state leaf, and emits only an **unsigned** checkpoint candidate plus verification calldata. It never signs, activates a route or accepts a remote RPC label as authority. Transfer export additionally validates the actual signed comment, configured gateway script and destination domain.

Confirmations are a settlement-risk policy, not irreversible PoS finality. Deep reorgs invalidating settlement evidence require existing route isolation/reconciliation. An incompatible shorter-but-higher-trust recovery cannot be published as a normal monotonic-height advance; a qualified checkpoint/verifier recovery must preserve the adapter's replay maps. Deployment addresses, authority, gateway script and production depth are operational configuration inputs and remain inactive; no deployment or custody-key installation is implied by this audit.

## Native transfer profile

Curecoin's legacy standard-script policy does not provide the assumed OP_RETURN carrier. The native signed comment supports the 61-byte format:

`420CUREV1 || sha256(abi.encode("420/CURE/DESTINATION/V1", destinationChainId, destinationRouter, routeId)) || recipient20`.

Gateway value/script and destination are therefore covered by transaction inclusion and its native signatures. State block hashes/API identifiers use display order; transaction IDs and Merkle branches use raw digest order. Source replay identity is domain-separated native genesis + txid + output index and remains stable across verifier rotation. Proof/transaction/script/count bounds define the supported bridge packet profile and reject malformed/noncanonical encodings. A valid historical ordinary payment without the new signed comment cannot be credited as a bridge transfer.
