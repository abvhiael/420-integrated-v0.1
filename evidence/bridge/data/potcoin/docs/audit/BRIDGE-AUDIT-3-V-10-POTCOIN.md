## Consensus details and trust model

The effective native target spacing is **258 seconds** (`unsigned int nTargetSpacing = 4.3 * 60`), despite advertised 260. Modifier interval is 60 seconds, minimum stake age 900 seconds, maximum weighted age 25 days. Kernel serialization is uint64 modifier followed by uint32 origin-block-time, tx offset relative to block start, origin-tx-time, output index and stake time, all little endian. Coin-day weight is amount × capped age / 1e8 / 86400; the kernel comparison is strictly `<` against the unbounded weighted target. Zero weight fails. Source block age is checked separately. Native future kernel-modifier selection depends on canonical blocks after the origin, not a claimant-selected integer.

Both work and stake blocks add floor(2^256/(target+1)) trust. Native selection uses greater cumulative trust, not length; equal trust does not displace the current chain. Work is allowed through 500, stake from 20, leaving a mixed era. Target adjustment uses the previous two blocks of the same type, interval 3600/258 = 13, negative spacing fallback 258, and bounded unbounded-integer arithmetic. The native block signature is ECDSA over the raw X13 hash using the first P2PK output from coinstake output 1 onward (charity outputs may precede it); low-s is not imposed by the source. On-chain public-key decoding validates compressed/uncompressed curve points and canonical DER signatures.

`PotcoinFinalityVerifier420` consumes existing `AuthenticatedCheckpoint420` authority epochs. A signed, destination-domain-bound advance authenticates full native replay state leaves. It independently checks kernel arithmetic, stake origin serialization/amount/script/age/maturity, type-specific target, timestamps/trust, coinstake inclusion and signer, deposit inclusion/output and destination. **This is an explicitly trusted replay-checkpoint consumer, not a permissionless X13/UTXO light client.** A compromised configured checkpoint authority can falsify replay-only fields. The source has no configured synchronized-checkpoint master public key: do not present this bridge authority as a native consensus signature.

`scripts/potcoin/replay.py` requires a complete raw bootstrap corpus, pinned native source and daemon checksum, starts a fresh offline mainnet node, waits for the expected canonical tip and independently cross-checks X13, ancestry, transaction roots, trust and canonical UTXO projection. It derives the selected stake origin and future modifier, then exports an **unsigned** state-root/proof plus replay report. It does not accept public RPC status as authority, import remote node databases, sign checkpoints, enable routes, or spend assets. The genesis execution is verified; post-bootstrap export/fork execution cannot be qualified without the missing corpus. Native `-loadblock` exits after importing; the tool uses the native startup `bootstrap.dat` path instead.

Confirmations are an explicit settlement-risk policy, not irreversible PoS finality. Authority rotation invalidates current proofs until a fresh signed checkpoint. Adapter replay identities persist outside the verifier. If a deep reorganization invalidates settled evidence or requires publication incompatible with monotonic checkpoint heights, governance must isolate the route and reconcile; this API cannot silently claim irreversible finality or publish a shorter chain as an ordinary monotonic advance. No production root, authority, gateway or deployment is approved here.

Gateway memo is a standard 62-byte script: `6a3c` plus `420POTV1` (8 bytes), SHA256 of ABI destination-domain tuple (32 bytes), recipient (20 bytes). This stays inside native data-carrier policy. Output amounts are integer pot-satoshis; source identity is native genesis + txid + output index. An allowed gateway cannot substitute the destination chain/router/route. Duplicate odd-tree count ambiguity is rejected by excluding equal siblings at positions requiring distinct nodes.
