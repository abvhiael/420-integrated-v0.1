# GEN-SVC-3.8 — Business/place claim workflow boundary

`claims.go` implements a **development-only, private, application-level** request store. The only accepted identifiers are a trusted caller's authenticated claimant ID, an existing public place ID, an existing Registry record ID and an opaque evidence reference. Before a request is accepted, `ClaimProvenance.VerifyPlaceClaim` must independently verify current 420 Identity authority, public Location binding, matching Registry provenance, and 420 Verify evidence. Neither a submitted evidence reference nor a Registry record identifier is proof on its own. Missing, stale, revoked, unavailable or mismatched upstream evidence fails closed.

Submitting a claim creates only `PENDING` workflow metadata. An independently authorized reviewer must make a separate decision, and approval rechecks upstream provenance. Even `APPROVED` does **not** change the authoritative Location owner, Registry or Verify record, reputation, reviews, page editing privileges, payouts or protocol permissions. Those changes require separately designed permissions and authorized upstream transactions. No browser-supplied identity/reviewer header, query parameter, or self-attested verification result is acceptable. Claims are not returned by public discovery or enumerated anonymously. The in-process map is not durable, audited or suitable for production.

`/travel/business/claim` remains an explicit 503 navigation shell. It must stay disabled until a real authenticated Identity session, independent reviewer authorization, a concrete fail-closed provenance adapter backed by canonical Location/Registry/Verify, durable owner-scoped storage, CSRF/rate-limit/audit protections and recovery/revocation workflows are available and tested. Do not put evidence material or claimant IDs in public pages or indexes. Reviewer authorization is the responsibility of the trusted adapter at the eventual HTTP boundary; the in-process `Decide` caller argument alone is not a reviewer credential.

Run `go test ./genesis/svc3/... ./cmd/420travel/...`, `go vet ./genesis/svc3/... ./cmd/420travel/...` and the Travel and repository-wide CI. Passing these tests qualifies the domain boundary only, not a working public claim UI, deployed Identity or Registry/Verify integration, or business control transfer.
