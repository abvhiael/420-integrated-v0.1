# GEN-SVC-3.9 — Reserved 420BnB / DOOBR compatibility contracts

`compatibility.go` defines `travel-compat/v1` planning-only, versioned Go/JSON records for 420BnB (`Property`, `Host`, `Guest`, `Availability`, `NightlyPrice`, `Reservation`) and DOOBR (`ServiceProvider`, `ServiceArea`, `DeliveryWindow`, `ServiceRequest`). These are future **schema/interface hooks**, not an installed provider, verified identity, real property listing, guarantee of availability, payment request, binding nightly-price quote, transaction ledger or permission to deliver cannabis.

`Validate` checks schema version, bounded identifiers and references, date-window order and bounds, currency shape, and consistency of delivery provider references. It is **structural validation only**. Host/guest/provider identity, place-publication permission, business license, age, jurisdictional legality, occupancy/inventory, privacy, availability and authoritative prices must be verified by the relevant external services before transaction features can ever be enabled. An amount in `NightlyPrice` is a reserved non-binding integer minor-unit representation, not an exchange-rate or price oracle. `ServiceArea` contains coarse text only; do not insert private address or exact coordinates. `Reservation` and `ServiceRequest` may be decoded as compatibility objects but are not persisted or executed by Travel.

`GenesisTravelTransactions` is a deliberately non-configurable, fail-closed gateway: reservation, quote, payment, escrow, cancellation settlement, delivery request, and dynamic pricing always return `ErrTravelTransactionDisabled`, even for syntactically valid requests. There is no external provider client or transaction store in this implementation. The development HTTP server does not register a booking, payment or DOOBR transaction route: unsupported endpoints return 404 and the rendered Travel shell identifies those flows as unavailable. Any future runtime enablement requires a separately designed, authorized and reviewed adapter, not a feature flag on this Genesis gateway.

Qualification: `go test ./genesis/svc3/... ./cmd/420travel/...`; `go vet ./genesis/svc3/... ./cmd/420travel/...`; build `./cmd/420travel`; run the dedicated GEN-SVC-3 and repository-wide qualification workflows. The new compatibility regression tests check each schema, malformed dates/IDs/versions, mismatched delivery providers and disabled operation paths. Passing these checks does not establish production readiness, regulatory compliance, deployed routing or integration with actual 420BnB/DOOBR services.
