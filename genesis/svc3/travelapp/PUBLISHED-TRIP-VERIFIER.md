# GEN-SVC-3.11.10.2 — current-public trip verification (partial)

`CurrentPublicTripVerifier{Reader: trustedPublicReader}` is a concrete `PublishedTripVerifier` for an explicitly qualified `TripSharing` composition. It must receive the deployment's trusted read-only GEN-SVC-2 public Location/Events reader; it must never be constructed from an HTTP request's URL or user-supplied authority. The default `cmd/420travel` public-only server does not enable authenticated sharing.

On each call, the verifier fetches a fresh bounded public Location/Events feed and requires every saved place and event ID to be present in that feed. If a reference is withdrawn, outside the bounded feed, invalid, or the upstream feed fails, the entire shared read is denied without identifying which reference failed. Even an empty trip requires a successful upstream fetch. This is conservative: events outside the current next-30-days/100-item public feed cannot be shared by this implementation. Saved IDs are planning references, not publication authority.

This is **not** an atomic publication snapshot, proof of timely revocation, a live endpoint qualification, or a public-trip listing. Do not enable sharing in production until the upstream public projection provides an authoritative, complete, suitably versioned/current lookup for *all* saved references and withdrawal races have been exercised. A bounded discovery feed cannot prove absence of a published event beyond the feed bounds; it can only fail closed. Verify request-time review of publication after issuance and after subsequent withdrawal, including multi-instance tests with real PostgreSQL share grants.

The remaining 3.11.10.2 gates are: production 420Identity session-introspection client and readiness, shared PostgreSQL migrations/checksums and two-process evidence, Registry/Verify/Identity claim provenance and independently authorized reviewer, live Reputation/moderation/interaction evidence, trusted public API version/withdrawal guarantees, and an explicit enabled/disabled feature matrix based on real staging service checks. No mock-only test closes those gates. 420BnB/DOOBR transactions stay disabled.
