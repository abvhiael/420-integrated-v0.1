## Composition and security gates

`HandlerWithReader` is the default public development handler. `HandlerWithReviewReader` and `HandlerWithUserDependencies` are **explicit injection seams for verified integration testing**, not production configuration switches: deployment must supply real, independently authenticated adapters and persist private records durably. Never derive an authenticated subject or review-verification status from untrusted query parameters, cookies without server-side verification, request headers or form input. The session adapter is responsible for secure, HttpOnly, SameSite, appropriately scoped session cookies, expiry and revocation; private mutation forms require an unguessable session-CSRF token and same-origin browser request. Apply production ingress, TLS, audit, rate limits, safe error handling, deletion/retention and backup controls before exposing private routes.

420Location remains authoritative for public place/event visibility. Travel must never fetch canonical private place/event records or expose exact coordinates for approximate areas; publication/revocation timing must be qualified against the deployed upstream. 420Reputation remains authoritative for review status and evidence. Place claims never create new Registry records or confer protocol authority. Booking/payment/delivery are unavailable.

## Release disposition

The newly implemented public journeys are code-complete at the bounded coarse-search level, with dedicated HTTP regression tests. Identity-gated Trips, claim submission and verified-review read journeys have injectable HTTP E2E tests but **cannot be called deployed/production-complete until their real services are connected and requalified**. The original Genesis requirement for genuine distance-aware map/list, review content/replies, durable authenticated saved trips, independently verified claims and operational acceptance testing remains open. Do not merge PR #356 as a fully qualified Genesis 420Travel release solely because GitHub Actions are green.
