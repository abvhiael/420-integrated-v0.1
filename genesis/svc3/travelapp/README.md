# 420Travel — GEN-SVC-3.1–3.2 development service

Run locally with `go run ./cmd/420travel`, then open `http://127.0.0.1:8088/travel`. `TRAVEL_LISTEN_ADDR` defaults to `127.0.0.1:8088`.

Set `TRAVEL_PUBLIC_SERVICE_URL` to the trusted base URL of the deployed GEN-SVC-2 read-only *public* Location/Events HTTP service, e.g. `http://127.0.0.1:8090` for a locally controlled service. With this variable absent, Travel displays the disconnected state; no demonstration or cached data is substituted. With the variable present, each GET `/travel` requests public `/v1/places` and `/v1/events` via `genesis/svc2/sdk`, then joins public venues and events using `genesis/svc2/consumers.Load`. It renders only this projection, returning a generic 502 page on service failures and a clear empty state when no public places are returned. The event query is bounded to the next 30 days and 100 results; the HTTP client has a four-second timeout and the handler has a five-second request timeout.

This is a **development entry point**, not a production ingress implementation. A trusted deployment must validate and control the upstream endpoint, require TLS outside a local trusted network, implement ingress policy/rate limits and audit controls, and qualify upstream event publication/recurrence and privacy gates before exposing it publicly. The public service is the data authority; Travel never reads private canonical repositories or elevates approximate locations to exact coordinates. Upcoming destination search, map/list, places, reputation, and trips are subsequent GEN-SVC-3 milestones, and the other routes currently return 404. 420BnB booking and DOOBR transaction workflows remain disabled.

Qualification: `python3 scripts/validate-gen-svc-3.py`, `go test ./genesis/svc3/... ./cmd/420travel/...`, `go vet ./genesis/svc3/... ./cmd/420travel/...`, and `go build ./cmd/420travel`. The GEN-SVC-3 workflow runs these on each relevant PR update; repository-wide checks remain separate.
