# 420Travel — GEN-SVC-3.1–3.5 development service

Run locally with `go run ./cmd/420travel`, then open `http://127.0.0.1:8088/travel`. `TRAVEL_LISTEN_ADDR` defaults to `127.0.0.1:8088`.

Set `TRAVEL_PUBLIC_SERVICE_URL` to a trusted deployed GEN-SVC-2 read-only **public** Location/Events HTTP service, e.g. `http://127.0.0.1:8090` for a locally controlled service. With this variable absent, Travel displays a disconnected state; no demonstration or cached data is substituted. With it present, GET `/travel` and GET `/travel/events` use the versioned `/v1/places` and `/v1/events` SDK and the public `consumers.Load` adapter. The request context is limited to five seconds; the upstream HTTP client is limited to four seconds; event requests are limited to 100 results over no more than the next 30 days. The public endpoint controls what is authoritative; Travel never reads private canonical repositories.

GEN-SVC-3.3 privacy: after reading events, Travel requests the public place projection again. If that projection changes or fails, Travel returns a generic 502 instead of rendering potentially stale venue/event cards. This is not an atomic snapshot or an assurance of revocation after the final read; upstream GEN-SVC-2 must qualify authoritative event visibility, atomic publication, recurrence updates and timely revocation. The public consumer adapter rejects exact coordinates on approximate-area locations, excludes events whose venue is absent from public places and never attempts a private lookup. Travel never renders coordinates.

GEN-SVC-3.4 navigation: `/travel/map`, `/travel/trips`, `/travel/business/claim`, and valid `/travel/place/{place_id}` return explicit 503 development shells, not invented or unauthorized results. Unsupported routes, booking and DOOBR endpoints return 404. GEN-SVC-3.5 Events: GET `/travel/events` renders upcoming public events, a UTC date picker (`date=YYYY-MM-DD` for the next 30 days), and a destination text filter (`destination=` matching published city, region or country). Only events attached to currently published public venues receive venue links; standalone public events appear only when no destination is specified. Filtering, ordering and public-event recurrence authority belong to GEN-SVC-2; this development view renders only the first bounded 100 event records and is not exhaustive search or pagination. Saved events, trip linking, ticketing and organizer provenance are not connected and are labelled unavailable.

This is a **development entry point**, not production ingress. Deployers must restrict the upstream to a trusted endpoint, require TLS outside a controlled local network, enforce ingress policy/rate limits, and qualify upstream event publication, stale-index handling, visibility/privacy, monitoring and deployment security independently. Map/list, place detail, Reputation and trips remain future milestones. 420BnB booking and DOOBR transaction workflows remain disabled.

Qualification: `python3 scripts/validate-gen-svc-3.py`, `go test ./genesis/svc3/... ./cmd/420travel/...`, `go vet ./genesis/svc3/... ./cmd/420travel/...`, and `go build ./cmd/420travel`. The dedicated GEN-SVC-3 workflow runs these on relevant PR updates; repository-wide CI is separate.
