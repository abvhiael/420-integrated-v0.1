# GEN-SVC-3.11.5 — saved references and owner-scoped editing

Status: **editing handler and deterministic tests implemented; complete user-facing planning journey and deployed reference verification not yet qualified.**

`trip_editing.go` introduces `HandlerWithTripEditing(reader,deps)` as an explicit opt-in composition around the existing private/public Travel handler. When trusted Identity and an `EditableTripRepository` are supplied, an owner may GET `/travel/trips/{trip_id}` to inspect a collection and POST to that same path to save its title, visibility, and newline-separated canonical place/event IDs or delete the collection. The handler re-verifies Identity, scopes reads and mutations by the session subject, requires session-bound CSRF, compares a timestamp from the edit form with the current repository snapshot, and bounds request and reference list sizes. Foreign trip IDs return 404. A missing Identity or editable store fails closed. Normal `Handler()` and `cmd/420travel` do not install this route.

The existing repositories accept validated planning reference IDs. These IDs do **not** prove that the place/event is currently published or authorized for the user; the saved-reference fields do not book, pay, grant claim authority, or disclose private canonical records. Before linking this route to production discovery or public sharing, re-resolve places and events using actual 420Location/420Events permission-aware public projections. Do not invent an event lookup or treat a saved ID as provenance.

Remaining work for milestone completion: link each owned trip from the `/travel/trips` list and add save actions on published place/event pages; independently validate current place/event visibility at add and display time; add revision-based optimistic locking at every store (the SQL store has timestamp compare-and-swap; file/in-process development stores currently do not); distinguish stale edit from missing/cross-owner IDs at the HTTP boundary without leaking ownership; test real PostgreSQL concurrency, deployment, accessibility, and actual 420Identity ingress. Only the injected-development editing contract is qualified by this change.
