# GEN-SVC-3.11.6 — trip visibility and unlisted sharing

Status: **opt-in share-grant implementation and deterministic tests added; public trip discovery and production deployment NOT qualified.**

`HandlerWithTripSharing` wraps the existing opt-in trip-editing handler. It supports an authenticated, CSRF-protected `POST /travel/trips/{id}/share`, `POST /travel/trips/{id}/revoke-shares`, and anonymous `GET /travel/shared/{opaque_token}`. Sharing applies only to `UNLISTED` trips. The issue endpoint returns a one-time seven-day bearer link in a no-store/no-referrer response. A deleted trip, a changed-to-private/public trip, a revoked grant, an expired grant, an inaccessible owner record, or a publication-verifier failure returns 404 to anonymous callers. Owner ID and place/event references are not included in the anonymous response. No route is enabled by the default public `Handler()` or `cmd/420travel`.

Apply `migrations/002_travel_trip_shares.sql` after migration 001 with a migration role; supply `SQLTripShareGrants{DB: db}` using the same transactionally consistent primary PostgreSQL as Trips. The share store persists only SHA-256 hashes of cryptographically random 256-bit tokens; runtime should have only SELECT/INSERT/DELETE privilege on the share table. Do not log token-bearing URLs, send them to third-party analytics, include them in referrers, or cache share responses. Rotating or revoking all links uses owner-scoped delete. The live Trips lookup and current visibility are checked on every share read. A deployment must inject a `PublishedTripVerifier` that confirms every referenced place/event is **currently authorized for public disclosure**. A nil or failing verifier denies sharing; a permissive verifier used by deterministic tests is NOT a production adapter.

**Outstanding release gates:** authenticate actual deployed 420Identity sessions; apply and exercise migrations against real PostgreSQL from multiple instances; implement a vetted live 420Location/420Events publication adapter and rerun it at the presentation boundary; expose accessible owner-only share/revoke controls in the Trips UI; implement separately authorized public-trip publication, retrieval and index exclusion of private/unlisted trips; ensure atomic visibility changes and grants under concurrent issue/revoke/read, including revocation races; enforce CSRF and cross-owner protection against the deployed service; audit URLs, logs, CDN, browser caching, accessibility, rate limits, token expiry and backup/restore. A shared trip's references are never evidence of booking, payment, ticketing or business ownership. Retain PR #356 open until these gates pass.
