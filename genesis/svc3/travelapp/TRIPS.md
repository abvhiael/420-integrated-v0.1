# GEN-SVC-3.7 — Trip collections (implementation boundary)

`trips.go` supplies the trip-planning domain/service layer. A `Trip` holds a title, its owner, a visibility setting (`PRIVATE` by default, `UNLISTED`, or `PUBLIC`), and bounded lists of place/event **IDs only**. It does not copy source place/event records or authorize a reservation, event ticket, escrow, payment or DOOBR delivery.

`TripStore` is an in-process development store, not durable user storage. All owner-scoped operations require the **trusted caller** to supply an authenticated owner ID. A trip-provided `OwnerID` is ignored on create and replace; another owner's trip returns the same not-found result as a missing trip. The public listing includes only explicitly `PUBLIC` trips. `UNLISTED` is excluded from public listings; it is *not* automatically accessible by knowing a trip ID. Sharing requires a separate unguessable, revocable, expiring capability and an authorization-aware retrieval endpoint, not implemented here. Reads/writes defensively copy reference slices to avoid cross-request mutation.

**Not yet exposed as a user-facing feature:** the normal `/travel/trips` route remains an unavailable shell. It must not accept owner IDs or session identity from a query string or unchecked header. Before connecting it, integrate 420 Identity/session verification, CSRF protection for mutations, a durable tenant-scoped repository, a properly scoped private/unlisted/public retrieval API, a share-capability authority, migration/backup/retention and audit controls. When displaying saved place/event references, resolve them against *current* appropriately authorized Location/Events projections; a public trip cannot make a private or withdrawn location/event public. Avoid public-index caching of private or unlisted trip metadata, and test private trip indexing, access revocation, stale references and concurrent changes in an integrated environment.

Qualification: `go test ./genesis/svc3/... ./cmd/420travel/...` and the dedicated GEN-SVC-3 and repository-wide CI. Passing repository tests qualifies this **service layer**, not a deployed or production-ready trip feature.
