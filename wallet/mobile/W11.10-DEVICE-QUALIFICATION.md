# 420 Wallet — W11.10 Release + Physical Device Qualification

W11.10 qualifies the native Android and iOS clients for internal distribution and real-device testing without moving canonical authority out of `SmartAccount420`, `CapabilityRegistry420`, or qualified Wallet Core policy.

## Release engineering policy

- CI release artifacts are unsigned unless an authorized signing environment is explicitly supplied outside the repository.
- No keystore, private signing key, certificate, provisioning profile, API token, password, or signing secret may be committed.
- Android CI must produce a release APK and Android App Bundle from the same qualified source head.
- iOS CI must produce a generic-device `.xcarchive` with code signing disabled.
- Store/TestFlight/Play internal-distribution signing is a separate authorized deployment operation and does not alter wallet account authority.

## Android release/store review

- [ ] Release APK installs on supported physical device (API 28+).
- [ ] Release AAB is accepted by Play Console internal testing when authorized signing is configured.
- [ ] Application ID is `io.fourtwenty.wallet`.
- [ ] Production App Link host is configuration-driven and verified with Digital Asset Links.
- [ ] FCM configuration is supplied through deployment environment; no server credential is embedded.
- [ ] `POST_NOTIFICATIONS` behavior is verified on supported Android versions.
- [ ] Privacy/Data Safety declarations reflect wallet account identifiers, push token handling, diagnostics, and any analytics actually enabled.
- [ ] No private key, recovery secret, passkey secret, or signing service endpoint is present in packaged resources.

## iOS release/store review

- [ ] Unsigned CI archive is structurally valid before signing/export.
- [ ] Authorized signing archive/export succeeds with the deployment team's certificate/profile outside source control.
- [ ] Bundle ID is `io.fourtwenty.wallet`.
- [ ] Associated Domains contains only authorized production wallet-link domains.
- [ ] APNs entitlement/environment matches the authorized distribution profile.
- [ ] `remote-notification` background mode is present if background remote notification delivery remains implemented.
- [ ] Face ID usage description is present if Face ID may be invoked.
- [ ] App Privacy answers reflect push token handling, wallet account identifiers, diagnostics, and any analytics actually enabled.
- [ ] No private key, recovery secret, passkey secret, provisioning profile, certificate, or APNs signing credential is embedded in the archive.

## W11.10 closeout gate

W11.10 may close only when:

1. Android release APK/AAB CI succeeds from the W11 head.
2. iOS unsigned generic-device archive CI succeeds from the same head.
3. Existing Android emulator and iOS simulator qualification remains green.
4. Physical-device passkey, biometric, secure-storage, lifecycle, deep-link and push matrix is completed or explicitly documented as an external-device release blocker.
5. Store metadata/privacy/entitlement review has no unresolved security-authority issue.
6. Integrated qualification passes on the final W11 head before PR #112 is made ready for merge.
