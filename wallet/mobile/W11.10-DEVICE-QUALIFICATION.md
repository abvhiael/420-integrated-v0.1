# 420 Wallet — W11.10 Release + Physical Device Qualification

W11.10 qualifies the native Android and iOS clients for internal distribution and real-device testing without moving canonical authority out of `SmartAccount420`, `CapabilityRegistry420`, or qualified Wallet Core policy.

## Release engineering policy

- CI release artifacts are unsigned unless an authorized signing environment is explicitly supplied outside the repository.
- No keystore, private signing key, certificate, provisioning profile, API token, password, or signing secret may be committed.
- Android CI must produce a release APK and Android App Bundle from the same qualified source head.
- iOS CI must produce a generic-device `.xcarchive` with code signing disabled.
- Store/TestFlight/Play internal-distribution signing is a separate authorized deployment operation and does not alter wallet account authority.

## Canonical physical-device record

The machine-readable qualification record is `device-qualification-results.json`.

Allowed result values are:

- `PASS` — verified on the recorded physical device and build SHA.
- `FAIL` — verified failure; CI rejects the record until remediated.
- `BLOCKED_EXTERNAL_DEVICE` — no honest physical-device result exists yet.

`npm run device:check` validates the record schema and rejects any `FAIL` result. `npm run device:closeout` is the W11.10 closeout gate and fails until both platforms have real device/OS metadata, a real build SHA, and every required result is `PASS`. Simulator/emulator evidence must never be substituted for physical-device evidence.

## W11.10 closeout gate

W11.10 may close only when:

1. Android release APK/AAB CI succeeds from the W11 head.
2. iOS unsigned generic-device archive CI succeeds from the same head.
3. Existing Android emulator and iOS simulator qualification remains green.
4. `npm run device:check` passes with no recorded `FAIL`.
5. `npm run device:closeout` passes with every Android/iOS physical-device result recorded as `PASS` against the same qualified build SHA.
6. Store metadata/privacy/entitlement review has no unresolved security-authority issue.
7. Authorized Play/TestFlight signing/export validation is completed outside source control.
8. Integrated qualification passes on the final W11 head before PR #112 is made ready for merge.
