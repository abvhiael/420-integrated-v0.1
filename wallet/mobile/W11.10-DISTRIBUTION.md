# 420 Wallet — W11.10 Authorized Internal Distribution

This path prepares signed Android and iOS builds for physical-device qualification. Signing identities and store credentials remain external to source control.

## Android

Unsigned CI remains the default. To produce an authorized signed release, provide all four environment variables in the trusted signing environment:

- `WALLET420_ANDROID_KEYSTORE_PATH`
- `WALLET420_ANDROID_KEYSTORE_PASSWORD`
- `WALLET420_ANDROID_KEY_ALIAS`
- `WALLET420_ANDROID_KEY_PASSWORD`

The Gradle build fails closed when only a partial signing environment is present. When all values are present, the `release` build binds to `authorizedRelease`. No credential value is committed or printed by repository configuration.

Qualification commands:

```sh
cd wallet/mobile
npm run distribution:check
cd android
gradle :app:assembleRelease :app:bundleRelease --no-daemon --stacktrace
```

The resulting signed APK/AAB must be tested on physical hardware and, where authorized, uploaded to Play Console internal testing. Record the tested build SHA and device evidence in `device-qualification-results.json`.

## iOS

CI continues to produce an unsigned `.xcarchive`. Authorized signing/export occurs only in a trusted Apple signing environment with the appropriate team certificate/profile or managed signing identity.

`ios/ExportOptions-AppStore.template.plist` is the repository-owned App Store Connect export policy template. The authorized environment supplies the team/account credentials externally.

Typical authorized export flow after producing a signed archive:

```sh
xcodebuild -exportArchive \
  -archivePath Wallet420.xcarchive \
  -exportPath Wallet420-export \
  -exportOptionsPlist ExportOptions-AppStore.template.plist
```

The exported build must be installed through an authorized device/TestFlight path before any physical-device result is recorded as PASS.

## Closeout rule

A green repository build proves distribution configuration integrity, not physical-device behavior. `npm run device:closeout` remains the final W11 hardware gate and must not pass until every required Android and iOS physical-device check is recorded as `PASS` with device model, OS version and build SHA.
