# W12.2 — Android Play Packaging

This step prepares 420 Wallet for Google Play internal testing without committing upload keys, Play credentials, or signing material.

## Repository-qualified release inputs

- Application ID: `io.fourtwenty.wallet`
- Release version: `0.1.0-w11`
- Version code: `1`
- Minimum SDK: `28`
- Target SDK: `35`
- Play artifact: `app-release.aab`
- Verified HTTPS App Link path: `/connect`
- App Link host: build-configured through `walletLinkHost`
- Android backup: disabled
- Notification permission: declared

`android/play-internal-testing.json` is the canonical Play packaging metadata record. `npm run android:play:check` validates it against Gradle, the Android manifest, and the canonical mobile release manifest.

## CI artifacts

The Wallet Mobile workflow builds unsigned release APK/AAB artifacts for qualification and emits `SHA256SUMS.txt` tied to `GITHUB_SHA`. These artifacts prove reproducible source provenance but are not authorized for Play upload until externally signed.

## Authorized Play upload

A Play upload requires an authorized release signing configuration supplied outside source control through the existing `WALLET420_ANDROID_*` environment variables. Partial signing configuration fails closed. No keystore, password, private key, Play service-account credential, or upload key is committed.

The first distribution target is Google Play **Internal testing**. Production promotion remains blocked until the physical-device qualification policy is satisfied.

## External requirements before Play production

- Google Play Console application exists for `io.fourtwenty.wallet`.
- Play App Signing / upload-key configuration is authorized and retained outside the repository.
- Production Digital Asset Links are deployed for the configured wallet link host.
- Google Play Data Safety declarations are reviewed against the implemented application behavior.
- Android physical-device qualification evidence is complete for the signed candidate.
- Full cross-platform `npm run device:closeout` remains blocked until real iOS hardware evidence also exists.

No simulator/emulator result may be recorded as physical-device evidence.
