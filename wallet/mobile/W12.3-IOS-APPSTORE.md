# 420 Wallet — W12.3 iOS TestFlight / App Store Packaging

W12.3 defines the repository-side package contract for TestFlight and App Store Connect without committing Apple signing material or weakening W11 physical-device qualification.

## Repository-complete requirements

- Bundle identifier: `io.fourtwenty.wallet`.
- Minimum iOS target: 16.0.
- Product name: `420 Wallet`.
- Archive source: deterministic generic-device `.xcarchive` from the qualified Git SHA.
- Export method: App Store Connect via `ios/ExportOptions-AppStore.template.plist`.
- Associated Domains remain configuration-driven through `WALLET_LINK_HOST`.
- APNs environment remains configuration-driven through `APS_ENVIRONMENT`.
- `remote-notification` background mode remains enabled.
- Privacy manifest remains present and validated.
- Certificates, provisioning profiles, App Store Connect API keys, signing passwords, and private signing material remain external to source control.

## Authorized external distribution procedure

1. Start from the exact qualified W12 Git SHA.
2. Generate `Wallet420.xcodeproj` from `project.yml` with XcodeGen.
3. Configure the production `WALLET_LINK_HOST` and APNs environment through authorized build settings.
4. Archive with an authorized Apple Developer signing identity and matching provisioning profile.
5. Export/upload using the App Store Connect export options template or Xcode/App Store Connect tooling.
6. Record the source Git SHA, build number, archive checksum, signing/distribution operator, and App Store Connect/TestFlight build identifier in external release evidence.
7. Perform TestFlight qualification on real iPhone hardware.
8. Populate the iOS rows in `device-qualification-results.json` with genuine device model, OS version, build SHA, PASS/FAIL status, and notes.
9. Do not consider production App Store readiness satisfied until all required iOS physical-device rows pass and `npm run device:closeout` succeeds.

## Current external blocker

The repository intentionally records iOS physical-device status as `BLOCKED_EXTERNAL_DEVICE`. Simulator qualification, unsigned generic-device archives, and CI success are not substitutes for real iPhone evidence.

## Security invariants

- TestFlight/App Store packaging never becomes wallet account, recovery, capability, or signing authority.
- No Apple signing credential is committed to the repository.
- App Store upload does not bypass Wallet Core, SmartAccount420, CapabilityRegistry420, passkey/session policy, or device qualification.
