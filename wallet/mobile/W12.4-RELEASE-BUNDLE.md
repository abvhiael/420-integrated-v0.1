# W12.4 — Cross-platform release bundle

This phase binds Android and iOS distribution metadata to one release identity without introducing a second wallet authority or committing signing credentials.

## Bundle contents
- `release-bundle.json` — canonical cross-platform release identity, notes, BOM contract, and security gates.
- `release-manifest.json` — qualified source version/platform metadata.
- `android/play-internal-testing.json` — Android Play packaging contract.
- `ios-appstore-package.json` — iOS TestFlight/App Store packaging contract.
- `artifact-checksums.sha256` — generated by CI for release artifacts and tied to the exact workflow SHA.

## Qualification rules
- Android and iOS must share the same `authorityPolicy`.
- Release version and qualified source commit must match the canonical release manifest.
- APK/AAB and packaged iOS archive use SHA-256 provenance.
- Release notes must continue to state that production distribution is blocked until `npm run device:closeout` passes with genuine hardware evidence.
- No signing credentials, certificates, provisioning profiles, keystores, API keys, remote-signer fallbacks, or plaintext private-key fallbacks may be introduced by packaging.

## Release bill of materials
The W12 release BOM is intentionally metadata-oriented rather than a software dependency SBOM. It records the required release-control documents and provenance artifacts needed to independently verify a release candidate. Dependency-level SBOM generation can be added later if required by distribution or compliance policy.

## External blockers
W12.4 does not satisfy physical-device qualification. Android/iOS production distribution remains blocked until W11 device closeout is complete; iOS remains specifically blocked until genuine iPhone evidence is available.
