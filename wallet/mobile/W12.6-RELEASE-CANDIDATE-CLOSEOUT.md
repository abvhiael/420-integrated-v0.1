# 420 Wallet — W12.6 Release Candidate Closeout

W12.6 closes the repository-side release packaging phase by qualifying the W12 candidate against the current pull-request merge head and preserving the W11 physical-device release gate.

## Closeout rules

1. PR #113 must remain mergeable into current `main`.
2. Final qualification is performed on the pull-request merge head so current `main` changes are included in the tested candidate.
3. `420 Wallet Mobile Verification` and `420 Integrated Qualification` must both pass on the release-candidate head.
4. Release/version, platform identity, authority policy, bundle provenance, distribution metadata, and secret-exclusion checks must remain green.
5. Packaging and distribution remain non-authoritative. Wallet Core / SmartAccount420 / CapabilityRegistry420 remain canonical authority.
6. No signing certificate, provisioning profile, keystore, App Store Connect key, Play upload key, wallet key, remote signer fallback, or plaintext private-key fallback may be committed.
7. Repository closeout does **not** mean production distribution is authorized.

## Physical-device blocker

Production release, TestFlight readiness, and Play readiness remain `BLOCKED_EXTERNAL_DEVICE` until genuine physical Android and iPhone evidence is recorded in `device-qualification-results.json` and:

```sh
npm run device:closeout
```

passes. Emulator/simulator evidence cannot satisfy this gate.

## Release-candidate state

- W12.1 through W12.5 are repository-qualified.
- W12.6 adds the final release-candidate closeout contract and qualification gate.
- The baseline W12.5 qualified head is recorded for provenance.
- The `main` SHA observed when W12.6 started is recorded for audit context only; the authoritative integration qualification is the current PR merge head produced by GitHub Actions.

Once both final workflows are green, W12 is repository-side complete and PR #113 can be prepared for merge. Production store distribution remains separately blocked on genuine device closeout.
