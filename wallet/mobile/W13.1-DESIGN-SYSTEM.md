# 420 Wallet — W13.1 Design System and Branded Components

W13.1 establishes the shared visual vocabulary for the native 420 Wallet without changing wallet authority, signing, recovery, capability, RPC, or transport behavior.

## Shared token contract

`design/design-tokens.json` is the semantic source of truth for:

- light and dark color roles;
- typography scale and weight roles;
- spacing and corner-radius scales;
- elevation and icon sizing;
- minimum 44dp/pt touch targets;
- dynamic-type and reduced-motion requirements;
- an explicit presentation-only authority boundary.

The palette uses a restrained cannabis-green identity rather than neon decoration: deep neutral greens for backgrounds, accessible green primary actions, a pale botanical accent, and distinct semantic success/warning/danger roles.

## Native adapters

Android remains a platform-native Views application. `Wallet420DesignSystem.kt` maps shared semantic roles into the existing programmatic UI without introducing a second state or authority layer.

iOS remains SwiftUI. `Wallet420DesignSystem.swift` provides semantic colors, dimensions, a surface modifier, and a primary button style while retaining Dynamic Type and native accessibility behavior.

Both adapters are presentation-only. They cannot sign, recover accounts, grant capabilities, store wallet secrets, submit UserOperations, or bypass Wallet Core.

## Qualification

`design-system-check.js` verifies token integrity, cross-platform parity markers, minimum accessibility dimensions, and the presentation-only authority contract. `npm run design:check` is part of the ordinary mobile `npm run check` gate.

## W13.1 completion criteria

- Shared semantic design tokens are repository-qualified.
- Android and iOS consume the design system in their root wallet surfaces.
- Light/dark roles are defined without changing security semantics.
- Base title/body/action/navigation treatments use shared spacing and touch-target rules.
- Wallet Mobile and Integrated qualification are green.

W13.2 will use these primitives for the detailed visual redesign of Wallet, Apps, Activity, Security, Send, Receive, Connect, approvals, recovery, permissions, sessions, and device-state screens.
