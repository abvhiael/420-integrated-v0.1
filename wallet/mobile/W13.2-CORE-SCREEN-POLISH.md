# W13.2 — Core Screen Visual Polish

W13.2 applies the W13.1 semantic design system to the native Wallet, Apps, Activity, and Security surfaces without changing wallet authority or transaction policy.

## Android

- Replaces the placeholder single-text surface with structured branded cards.
- Adds persistent bottom navigation with selected-state treatment and 44dp minimum targets.
- Adds Wallet portfolio, quick actions, recent activity, Apps discovery/finance grouping, Activity authority/status cards, and Security authentication/permissions/recovery cards.
- Keeps deep-link/push approvals and local-lock behavior intact.
- Quick-action buttons only prepare UI intent; they do not sign or submit transactions.

## iOS

- Replaces the placeholder centered text surface with scrollable SwiftUI cards.
- Adds structured Wallet, Apps, Activity, and Security content using the shared W13 semantic design language.
- Adds branded primary/secondary actions and selected navigation treatment.
- Preserves existing UI-test accessibility identifiers and lifecycle/privacy-shield behavior.
- Keeps push/deep-link approval presentation separate from canonical Wallet Core authorization.

## Security and authority invariants

- No design component becomes account, capability, recovery, signing, RPC, or UserOperation authority.
- Local biometric unlock restores presentation access only.
- Push/deep-link surfaces remain reference/presentation paths and require canonical rehydration/revalidation.
- No private keys, wallet secrets, signing material, or real user data are embedded in visual fixtures.

- Qualify iOS simulator unit/UI tests and generic-device archive.
- Run Wallet Mobile and Integrated qualification on the W13.2 head.
