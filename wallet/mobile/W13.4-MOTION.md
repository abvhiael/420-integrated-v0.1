# 420 Wallet — W13.4 Motion and Micro-interactions

W13.4 adds restrained native motion and feedback to the Android and iOS presentation layers without changing wallet authority, signing, recovery, capability, RPC, or UserOperation semantics.

## Android
- Bounded 140 ms status pulses and 220 ms content-entry transitions.
- Motion is skipped when the system animator duration scale is disabled.
- Navigation, onboarding step changes, action feedback, approval presentation, and lock-state feedback use the shared presentation helpers.

## iOS
- Shared 140 ms status and 220 ms content animations.
- `accessibilityReduceMotion` disables movement/scale transitions and falls back to identity/no animation.
- Onboarding, wallet-surface transitions, status cards, and button press feedback use native SwiftUI animation primitives.

## Authority boundary
- Motion never initiates or authorizes signing, recovery, account creation, capability grants, RPC submission, or UserOperation execution.
- Quick-action/status animation reflects presentation state only.
- Canonical Wallet Core and SmartAccount policy remain authoritative.

## W13 invariants
- WALLET-W13-001 preserved: visual changes never become account, capability, signing, or recovery authority.
- WALLET-W13-002 preserved: security-critical states remain explicit and understandable.
- WALLET-W13-003 strengthened: reduced-motion behavior is a first-class release requirement.
- WALLET-W13-004 preserved: no visual feedback implies behavior that is not implemented and qualified.
- WALLET-W13-005 preserved: motion and visual feedback expose no private data or secrets.
