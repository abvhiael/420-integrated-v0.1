## Actual routes and representations

The public-only `cmd/420travel/main.go` uses `NewPublicDeploymentHandler`, whose `HandlerWithNearbyMap(reader)` composition and `WithPublicReadiness` wrapper implement server-rendered HTML pages and a plain-text health probe. The audited `handler.go` registers `GET /travel` (optional `destination`, max 80 chars), `GET /travel/events` (optional single `date` in UTC, optional `destination`), `GET /travel/map` (nearby HTML; inspect the actual nearby handler and publication policy when implementing its JSON twin), and `GET /travel/place/{place_id}`. The `/travel/trips` and `/travel/business/claim` public shells return unavailable; they are not anonymous data feeds. `GET /readyz` returns plain text on success and 503 on missing/unavailable public feed: it is **not** a listings endpoint. See `genesis/svc3/travelapp/handler.go`, `events.go`, `deployment_readiness.go` and `cmd/420travel/main.go`.

`/travel` and `/travel/events` return **text/html** generated by `html/template` via `renderPage`. `renderPage` sets `Cache-Control: no-store` and `X-Content-Type-Options: nosniff`; invalid filter inputs return 400 and upstream failures return 502, while disconnected/empty results may be HTML with HTTP 200. The HTML page model is an internal Go `pageData` structure, not a published JSON response schema. It includes public venue rows (`consumers.Venue`) and a view-specific `travelEvent` structure; these Go types are **not** an authorized browser JSON contract. The events route uses one date filter, NOT the existing static mockup's from/to date range. Events referring to unpublished venues are suppressed, and standalone events cannot be matched to a requested destination.

No compatible, versioned, anonymous JSON listing endpoint has been established in this audit. In particular, do not guess that `/travel/api/*`, `/api/places`, `/api/events` or `/readyz` returns JSON. The browser should not scrape server-rendered HTML into records, treat HTTP 200 as a nonempty feed, or load an unaudited cross-origin service. The Cloudflare Pages deployment currently publishes static `web/travel` and cannot run the Go binary; there is no verified same-origin public-data route or deployed HTTPS Go origin on record.

## Required next implementation before browser wiring

1. Add narrowly scoped **public-only GET JSON endpoints in the Go public handler**, reusing the same `PublicReader`, `loadPublicDiscovery`, destination/date validation, publication and withdrawal filtering as the existing HTML handlers. Explicitly document the endpoint paths and versioned JSON schema from the actual new code, including public place IDs/names/category/city/region/country; event title/start time/verified published venue association; coordinate precision and the currently published exact-coordinate opt-in; and `ready`, `empty`, `disconnected`, `invalid`, `unavailable` outcomes. Exclude owner IDs, private/unlisted Trips, claims and raw upstream private fields. Do not infer coordinates from approximate areas.
2. Add Go HTTP tests for no-feed, valid empty, invalid filters, upstream failure, withdrawal, standalone events, private/approximate geography, method restrictions, response MIME and `Cache-Control: no-store`. A JSON schema should come from these tested handlers, not from the static preview's visual card fields.
3. Introduce a **same-origin, allowlisted, read-only** HTTPS proxy for those exact endpoints only. Reject arbitrary URLs, cross-origin redirects, credentials, private paths and mutation methods. No user-controlled origin or permissive wildcard CORS. Verify the deployed Go SHA, feed version, upstream outage behavior, Cloudflare deployment ID and actual response headers.
4. Only then implement the browser adapter against the validated JSON schema and wire Discover, Events and Nearby list progressively. Use `textContent` for all untrusted strings, distinguish disconnected from genuine empty and upstream error, and avoid caching withdrawn records. Map markers require explicitly published exact coordinates; no geolocation or third-party tiles at this stage.
